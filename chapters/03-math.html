1. Vectors and the dot product

Explain it like I'm 9

A vector is just a list of numbers that belong together, like a scorecard: (3 goals, 1 assist, 2 fouls). You can also draw it as an arrow: start at zero, go 3 steps right and 1 step up. Both pictures are the same thing. In Chapter 2 every row of the customer table was a vector: one customer, described by a handful of numbers.

Precisely: a vector x ∈ ℝd is an ordered list of d real numbers, written x = (x1, x2, …, xd). Geometrically it is a point (or an arrow from the origin to that point) in d-dimensional space. In ML, d is the number of features, and you cannot draw d = 50, but every operation behaves exactly as it does in 2-D, which is why the pictures below are worth learning.

The single most important operation in this book is the dot product. It takes two vectors of the same length and returns one number:

w · x = w1x1 + w2x2 + … + wdxd = ∑i wixi
The math (optional)

Two readings of the same formula. As a weighted sum: if x is a customer's features and w is a set of weights (how much each feature matters, with sign), then w·x is the customer's score. Linear regression (Chapter 5) and logistic regression (Chapter 6) are this formula plus a constant. As similarity: geometrically, w·x = ‖w‖ ‖x‖ cos θ, where ‖·‖ is the length of a vector and θ is the angle between them. So the dot product is large and positive when the arrows point the same way, zero when they are perpendicular, and negative when they point against each other. Every "how similar are these two embeddings?" question in Chapter 19 is a dot product.

# Vectors and the dot product in numpy
import numpy as np
x = np.array([3.0, 1.0, 2.0])          # one customer: tenure_years, support_calls, plan_tier
w = np.array([0.5, -1.0, 0.8])         # weights the model learned
print("length (norm) of x:", np.linalg.norm(x).round(3))
print("dot product w·x    :", np.dot(w, x))               # weighted sum = the model's score
print("same thing, spelled out:", (w * x).sum())

a = np.array([1.0, 2.0]); b = np.array([2.0, 4.0]); c = np.array([-2.0, 1.0])
cos = lambda u, v: np.dot(u, v) / (np.linalg.norm(u) * np.linalg.norm(v))
print("cos(a,b) =", cos(a, b).round(3), "  cos(a,c) =", cos(a, c).round(3))
# length (norm) of x: 3.742
# dot product w·x    : 2.1
# same thing, spelled out: 2.1
# cos(a,b) = 1.0   cos(a,c) = 0.0
Key idea

Almost every model computes dot products. A linear model is one dot product. A neural network layer is many dot products in parallel (a matrix multiply), then a squashing function. Attention in a transformer (Chapter 18) is dot products between queries and keys. If you understand "weighted sum" and "similarity", you already understand the arithmetic of deep learning.

2. Matrices, shapes, and why shape errors happen

Explain it like I'm 9

A matrix is a table of numbers with rows and columns, like the customer spreadsheet. Multiplying the table by a list of weights means: for every row, do the "weighted sum" trick and write down one number. So instead of scoring customers one at a time, you score all 2,000 in one move. That is the whole reason computers love matrices: one instruction, thousands of dot products.

Precisely: a matrix X ∈ ℝn×d has n rows and d columns. In ML the rows are examples and the columns are features, so X is literally the feature table from Chapter 2, and the label column is a vector y ∈ ℝn. There are two ways to think about multiplying by a matrix:

  1. Matrix × vector = apply the model to every row. Xw takes the (n×d) table and the (d) weight vector and returns (n) scores: row i of the result is the dot product of row i of X with w. This is how sklearn's predict works for linear models: one matrix multiply.
  2. Matrix × matrix = apply many models at once, or transform the space. XW with W of shape (d×k) gives (n×k): each of the k columns of W is a separate weight vector, so you get k scores per row. A neural network layer is exactly this: it turns d input features into k new features (Chapter 15). Geometrically, a matrix transforms space: it can rotate, stretch, squash or project the cloud of points. PCA (Chapter 12) is a matrix that rotates the data so the interesting directions line up with the axes.
# Shapes: the rule, and the error you will see a hundred times
import numpy as np
rng = np.random.default_rng(0)
X = rng.normal(size=(5, 3))            # 5 customers × 3 features  (n×d)
w = np.array([0.5, -1.0, 0.8])         # d weights                  (d,)
print("X.shape:", X.shape, " w.shape:", w.shape)
print("X @ w  -> one score per row:", (X @ w).round(2), " shape", (X @ w).shape)

W = rng.normal(size=(3, 4))            # a layer that maps 3 features -> 4 new ones  (d×k)
H = X @ W                              # (n×d)(d×k) = (n×k): all rows at once
print("(5×3)(3×4) ->", H.shape)
try:
    W @ X                              # (3×4)(5×3): inner dims 4 and 5 do not match
except ValueError as e:
    print("shape error:", str(e)[:60])
print("fix with a transpose: (X @ W).T has shape", (X @ W).T.shape)
# X.shape: (5, 3)  w.shape: (3,)
# X @ w  -> one score per row: [ 0.71  0.88 -0.86  0.02 -1.94]  shape (5,)
# (5×3)(3×4) -> (5, 4)
# shape error: matmul: Input operand 1 has a mismatch in its core dimension
# fix with a transpose: (X @ W).T has shape (4, 5)
Common mistake

Fixing a shape error by transposing until it stops complaining. Transposing (.T) swaps rows and columns. If X.T @ w "works" when X @ w did not, you have probably computed something meaningless (a weighted sum across customers instead of across features). Instead, write the shapes down: X is (n×d), w is (d,), so the result must be (n,). If the shapes on paper do not chain, the code is wrong regardless of whether it runs. The same discipline saves hours in PyTorch (Chapter 16), where a silent broadcast can turn a (32,) vector into a (32×32) matrix without an error.

At work

Comment every tensor with its shape: scores = X @ w # (n,). It costs seconds and turns the next debugging session from an hour into a minute. In code review, a matrix expression without a shape comment is a question waiting to be asked.

3. Norms, distances and cosine similarity

Explain it like I'm 9

How far apart are two houses? As the crow flies (a straight line): that is Euclidean distance. By walking along the streets of a grid city: that is Manhattan distance, and it is always at least as long. And sometimes you do not care how far, only whether they are in the same direction from where you stand: that is cosine similarity, which ignores distance entirely and only looks at the angle.

Precisely. A norm is a length. The Euclidean (L2) norm is ‖x‖2 = √(∑ xi²); the Manhattan (L1) norm is ‖x‖1 = ∑ |xi|. A distance between two points is the norm of their difference. And cosine similarity is the dot product after dividing out both lengths:

d2(a,b) = √∑(ai−bi)² d1(a,b) = ∑|ai−bi| cos(a,b) = a·b / (‖a‖ ‖b‖)
The math (optional)

ai and bi are the i-th coordinates of the two points; the sums run over all d features. d2 is the straight-line distance (Pythagoras in d dimensions). d1 adds up the per-feature gaps, which makes it less sensitive to one wildly different feature. cos ranges from −1 to 1 and equals 1 whenever b is a positive multiple of a, no matter how long either is. Note that L1 and L2 norms also appear as the penalties in Lasso and Ridge regression (Chapter 7): "keep the weight vector short."

# The three measures, using sklearn's pairwise helpers (they take 2-D arrays: rows are points)
import numpy as np
from sklearn.metrics.pairwise import euclidean_distances, manhattan_distances, cosine_similarity
A = np.array([[1.0, 2.0]]); B = np.array([[4.0, 6.0]]); C = np.array([[10.0, 20.0]])
print("euclid(A,B) =", euclidean_distances(A, B)[0,0])        # sqrt(3²+4²) = 5
print("manhat(A,B) =", manhattan_distances(A, B)[0,0])        # 3 + 4 = 7
print("cosine(A,B) =", cosine_similarity(A, B)[0,0].round(3))
print("cosine(A,C) =", cosine_similarity(A, C)[0,0].round(3), "<- same direction, 10x longer")
print("euclid(A,C) =", euclidean_distances(A, C)[0,0].round(2), "<- 'far' by distance, 'identical' by angle")
# euclid(A,B) = 5.0
# manhat(A,B) = 7.0
# cosine(A,B) = 0.992
# cosine(A,C) = 1.0 <- same direction, 10x longer
# euclid(A,C) = 20.12 <- 'far' by distance, 'identical' by angle
MeasureUse it when…Where you will meet it
Euclidean (L2)Features are on comparable scales (scale them first!) and magnitude matters.k-NN and k-means (Ch 11, 12), RBF kernels, Ridge penalty (Ch 7)
Manhattan (L1)You want robustness to one feature being far off; high-dimensional sparse data.Lasso penalty and feature selection (Ch 7), some k-NN variants

Common mistake

Computing Euclidean distances on unscaled features. If monthly_spend ranges 0–200 and support_calls ranges 0–6, the distance between two customers is almost entirely about spend; the calls column might as well not exist. Any distance-based method (k-NN, k-means, SVMs with RBF kernels, PCA) needs standardised features. Chapter 8 makes this automatic with a Pipeline.

4. Derivatives, gradients and walking downhill

Explain it like I'm 9

You are standing on a hillside in thick fog, trying to get to the bottom of the valley. You cannot see, but you can feel which way the ground slopes under your feet. So you take a small step in the steepest downhill direction, feel again, step again. That is gradient descent. The "feel of the slope" is the derivative; when the hill has many directions, the slope in every direction at once is the gradient.

Derivatives: how much does the output move when I nudge the input?

Precisely: for a function f(x) of one variable, the derivative f′(x) is the slope of the tangent line at x, defined as the limit of rise-over-run as the run shrinks:

f′(x) = limh→0 [ f(x + h) − f(x) ] / h
The math (optional)

h is a tiny nudge to the input; f(x+h) − f(x) is how much the output moved; dividing gives "output change per unit of input change". A positive derivative means the function is rising here (step left to go down); negative means falling (step right); zero means flat, which is where minima, maxima and saddle points live. You will rarely compute derivatives by hand: numpy's finite differences check them, and PyTorch's autograd (Chapter 16) computes them exactly for any function you can write in code. What you need is the meaning.

Interactive: the tangent line is the derivative
f(x) = x³/3 − x: – slope f′(x) = x² − 1: – gradient step goes: –
Slide x across the curve. The violet line is the tangent; its slope is the derivative. Where the slope is zero (x = −1 and x = +1) the curve is momentarily flat: one is a local maximum, the other a local minimum. A gradient step always moves against the slope: right when the slope is negative, left when it is positive. Notice that from the far left, walking downhill never reaches the minimum at x = +1: it falls off toward −∞. That is what "local vs global" means in the subsection on minima below.

The gradient: the slope in every direction at once

A model has many parameters, so its loss is a function of many variables: L(w1, w2, …, wd). The partial derivative ∂L/∂wi is the ordinary derivative with respect to wi while holding all the others fixed ("nudge only this one knob"). The gradient collects them into a vector:

∇L(w) = ( ∂L/∂w1, ∂L/∂w2, …, ∂L/∂wd )
The math (optional)

The gradient is a vector with one entry per parameter. Two facts make it useful. First, it points in the direction of steepest ascent: of all directions you could step, the gradient's direction increases L fastest, and its length says how steep. Second, therefore, −∇L points steepest downhill. Gradient descent is the update rule

w ← w − η · ∇L(w)

where η (eta, the learning rate) is the step size. Too small and you crawl; too large and you overshoot the valley and bounce out. Chapters 5 and 16 spend real time on choosing it.

# Gradient descent on a 2-parameter bowl, with a numerical check of the gradient
import numpy as np
def f(w):            # a bowl-shaped loss with its minimum at (2, -1)
    return (w[0] - 2)**2 + 3*(w[1] + 1)**2
def grad(w):         # the exact gradient: partial derivatives
    return np.array([2*(w[0] - 2), 6*(w[1] + 1)])
def numerical_grad(w, h=1e-5):   # sanity check: nudge each input, measure the change
    g = np.zeros_like(w)
    for i in range(len(w)):
        e = np.zeros_like(w); e[i] = h
        g[i] = (f(w + e) - f(w - e)) / (2*h)
    return g

w = np.array([-1.0, 2.0])
print("exact grad:", grad(w), " numerical:", numerical_grad(w).round(4))
lr = 0.1
for step in range(1, 26):
    w = w - lr * grad(w)             # walk downhill
    if step in (1, 5, 10, 25): print(f"step {step:2d}: w = {w.round(3)}  loss = {f(w):.4f}")
# exact grad: [-6. 18.]  numerical: [-6. 18.]
# step  1: w = [-0.4  0.2]  loss = 10.0800
# step  5: w = [ 1.017 -0.969]  loss = 0.9692
# step 10: w = [ 1.678 -1.   ]  loss = 0.1038
# step 25: w = [ 1.989 -1.   ]  loss = 0.0001

Notice that w2 converges in about five steps and w1 takes twenty-five. The bowl is three times steeper in the w2 direction (the coefficient 3), so the same learning rate is "big" for w2 and "small" for w1. This is exactly the stretched-ellipse problem in Figure 3.4, and it is the mathematical reason feature scaling speeds up training.

The chain rule: derivatives of a function of a function

Real models are compositions: the loss depends on the prediction, the prediction depends on the weights. To find how the loss changes with a weight, you multiply the derivatives along the chain:

if L = g(u) and u = h(w), then dL/dw = (dL/du) · (du/dw)
The math (optional)

A concrete two-step example. Let the prediction be u = w·x with x = 3, and the loss be the squared error L = (u − y)² with target y = 4. Then dL/du = 2(u − y) and du/dw = x = 3. At w = 1: u = 3, dL/du = 2(3 − 4) = −2, so dL/dw = (−2)(3) = −6. Meaning: increasing w a little will decrease the loss (the derivative is negative), by about 6 units per unit of w. So gradient descent increases w. Check: w = 1.1 gives u = 3.3 and L = 0.49, down from 1.0. Backpropagation (Chapter 15) is nothing but this multiplication, repeated backwards through every layer of a network. Each layer contributes one factor; the gradient for an early weight is a product of many local derivatives.

Deep dive: the chain rule end-to-end on a two-layer function 9 min
Explain it like I'm 9

A message passes through four people before it reaches you, and each person changes it a little: one doubles it, one shrinks it to a fifth, one multiplies by one and a half. If you want to know how much the first person's change affects what you hear, you multiply all the changes along the way. Backpropagation is exactly that: walk back along the chain, multiplying local "how much does this step stretch things" numbers.

Precisely. Here is the smallest thing that deserves the name "network": one input x, a first layer u = w1x followed by a sigmoid h = σ(u), a second layer z = w2h, and squared loss L = (z − y)². Two weights, two questions: ∂L/∂w2 and ∂L/∂w1. Take x = 2, y = 2, w1 = 0.5, w2 = 1.5.

The math (optional)

Forward: u = 0.5 × 2 = 1; h = σ(1) = 0.7311; z = 1.5 × 0.7311 = 1.0966; L = (1.0966 − 2)² = 0.8162.

Backward, the last weight: ∂L/∂w2 = (∂L/∂z)(∂z/∂w2) = 2(z − y) · h = (−1.8068)(0.7311) = −1.321.

Backward, the first weight: ∂L/∂w1 = (∂L/∂z)(∂z/∂h)(∂h/∂u)(∂u/∂w1) = (−1.8068)(1.5)(0.1966)(2) = −1.066. Note that the first factor, ∂L/∂z, was already computed for w2; backpropagation reuses it, which is why the cost of all the gradients is about the same as one forward pass. The sigmoid's derivative h(1 − h) is at most 0.25, so each sigmoid layer shrinks the gradient flowing through it by at least a factor of 4: a small cause of the vanishing-gradient problem, and the reason ReLU replaced sigmoid inside deep networks (Chapter 15).

# The chain rule on a two-layer function, with numbers, then checked by finite differences
import numpy as np
sigmoid = lambda u: 1 / (1 + np.exp(-u))
x, y = 2.0, 2.0                              # one input, one target
w1, w2 = 0.5, 1.5                            # two weights, one per layer

def forward(w1, w2):
    u = w1 * x                               # layer 1: linear
    h = sigmoid(u)                           # layer 1: squash
    z = w2 * h                               # layer 2: linear
    L = (z - y) ** 2                         # loss
    return u, h, z, L

u, h, z, L = forward(w1, w2)
print(f"forward:  u = {u:.4f}  h = {h:.4f}  z = {z:.4f}  L = {L:.4f}")

dL_dz = 2 * (z - y)                          # local derivative of the loss
dz_dw2, dz_dh = h, w2                        # local derivatives of layer 2
dh_du = h * (1 - h)                          # local derivative of the sigmoid
du_dw1 = x                                   # local derivative of layer 1
dL_dw2 = dL_dz * dz_dw2                      # one factor
dL_dw1 = dL_dz * dz_dh * dh_du * du_dw1      # a product of four local factors
print(f"backward: dL/dz = {dL_dz:.4f}  dh/du = {dh_du:.4f}  ->  dL/dw2 = {dL_dw2:.4f}  dL/dw1 = {dL_dw1:.4f}")

eps = 1e-6
num_w1 = (forward(w1 + eps, w2)[3] - forward(w1 - eps, w2)[3]) / (2 * eps)
num_w2 = (forward(w1, w2 + eps)[3] - forward(w1, w2 - eps)[3]) / (2 * eps)
print(f"numerical check:                                 dL/dw2 = {num_w2:.4f}  dL/dw1 = {num_w1:.4f}")
# forward:  u = 1.0000  h = 0.7311  z = 1.0966  L = 0.8162
# backward: dL/dz = -1.8068  dh/du = 0.1966  ->  dL/dw2 = -1.3209  dL/dw1 = -1.0657
# numerical check:                                 dL/dw2 = -1.3209  dL/dw1 = -1.0657

The finite-difference check is the habit to keep: perturb one weight by ±10−6, recompute the loss, and compare the slope with the chain-rule number. If they agree to four decimals, your gradient code is right; if not, the hand-derived formula is the suspect, never the numerical one. PyTorch's autograd (Chapter 16) does precisely the bookkeeping in the figure for any graph you can write in code, but it cannot tell you whether the graph you wrote is the one you meant.

Minima: local, global, and why convexity is a gift

Key idea

Training = gradient descent on a loss. Everything from linear regression to GPT is: define a loss that is small when predictions are good, compute its gradient with respect to the parameters, step against it, repeat. Convex losses (linear models) have one answer; non-convex losses (deep nets) have many, and the craft is in finding a good one.

At work

When a colleague says "the model didn't converge", translate: gradient descent did not reach a flat point. The usual causes, in order of likelihood: unscaled features (elongated contours), learning rate too high (loss bounces or explodes to nan), learning rate too low (loss creeps and the time budget runs out), or a bug in the loss. Look at the loss curve before touching anything else.

5. Logs, exponentials, sigmoid and softmax

Explain it like I'm 9

Multiplying a hundred tiny numbers together gives a number so small your calculator just says 0. Logs fix that: a log turns "multiply" into "add", and turns a number like 0.000000001 into a friendly −9. Exponentials go the other way, turning any number into a positive one. The sigmoid is a squasher that takes any number and gently folds it into the range 0 to 1, so it can be read as a probability. Softmax does the same trick for several numbers at once, making them all positive and adding up to 1.

Precisely. The natural exponential exp(z) = ez maps any real number to a positive one and turns sums into products: exp(a+b) = exp(a)·exp(b). The natural logarithm ln is its inverse: ln(exp(z)) = z, and it turns products into sums: ln(ab) = ln a + ln b. Three consequences you use constantly:

  • Likelihoods are products of many probabilities (one per example), and products of 10,000 numbers below 1 underflow to 0.0 in floating point. Their logs are sums of moderate negative numbers, which computers handle perfectly. Every "log-loss", "log-likelihood" and "cross-entropy" in this book exists for this reason.
  • Logs do not change where the maximum is. Because ln is increasing, the parameters that maximise the likelihood also maximise the log-likelihood. So we optimise the log for convenience and lose nothing.
  • Logs compress skewed scales. Income, spend, counts: a log transform turns a long right tail into something bell-shaped, which linear models like (Chapter 8).
σ(z) = 1 / (1 + e−z) softmax(z)j = ezj / ∑k ezk
The math (optional)

The sigmoid σ takes a real score z (for instance w·x) and returns a number in (0, 1). σ(0) = 0.5; large positive z gives ≈1; large negative gives ≈0. Its derivative is σ(z)(1−σ(z)), which is why it appears so cleanly in logistic regression's gradient (Chapter 6). Softmax generalises it to K classes: it exponentiates each score (making them positive) and divides by the total (making them sum to 1). The entry j is the model's probability for class j. Subtracting the maximum score before exponentiating changes nothing mathematically (the constant cancels) but prevents overflow; every serious implementation does this.

# sigmoid, softmax, and why we work with logs
import numpy as np
sigmoid = lambda z: 1 / (1 + np.exp(-z))
z = np.array([-4, -1, 0, 1, 4])
print("sigmoid:", sigmoid(z).round(3))

def softmax(z):
    z = z - z.max()                     # subtract the max first: avoids overflow, same result
    e = np.exp(z); return e / e.sum()
scores = np.array([2.0, 1.0, 0.1])
p = softmax(scores)
print("softmax:", p.round(3), " sum =", p.sum().round(6))
print("log-probabilities:", np.log(p).round(3))
print("product of 5 tiny probs:", np.prod([1e-80]*5), " sum of their logs:", np.sum(np.log([1e-80]*5)))
# sigmoid: [0.018 0.269 0.5   0.731 0.982]
# softmax: [0.659 0.242 0.099]  sum = 1.0
# log-probabilities: [-0.417 -1.417 -2.317]
# product of 5 tiny probs: 0.0  sum of their logs: -921.0340371976183

The last line is the whole argument for logs in one print statement: the product of five probabilities of 10−80 underflows to exactly 0.0, destroying all information, while the sum of their logs is a perfectly ordinary −921.

6. Probability: distributions, expectation, Bayes

Explain it like I'm 9

A random variable is a number you do not know yet: the roll of a die, tomorrow's temperature, whether this customer will cancel. A distribution is the list of all the values it could take and how likely each one is. The expectation is the average you would get if you could repeat the experiment a million times. And Bayes' theorem is the rule for updating what you believe when you get a clue.

Precisely. A random variable X is a quantity whose value is determined by chance. A discrete one (counts, categories) has a probability mass function P(X = k); a continuous one (spend, height) has a density p(x) whose integral over an interval gives a probability. Five distributions cover most of applied ML:

Expectation and variance

E[X] = ∑k k · P(X = k) Var(X) = E[(X − E[X])²] σ = √Var(X)
The math (optional)

The expectation (mean) is the probability-weighted average of the values: each possible value k times its probability, summed (an integral for continuous variables). It is the long-run average. The variance is the expected squared distance from the mean: how spread out the values are. Its square root, the standard deviation σ, is in the same units as X and is the number you actually quote. Example: a Bernoulli with p = 0.26 (our churn rate) has E[X] = 0.26 and Var(X) = 0.26 × 0.74 = 0.192, σ ≈ 0.44. Note that expectation is linear: E[aX + bY] = aE[X] + bE[Y], always; variance adds only for independent variables.

Conditional probability and independence

P(A | B) = P(A and B) / P(B) A, B independent ⇔ P(A and B) = P(A)·P(B) ⇔ P(A | B) = P(A)
The math (optional)

P(A | B) reads "the probability of A given that B happened": restrict attention to the worlds where B is true, and ask what fraction of those also have A. From the churn data: P(churn) = 0.26 but P(churn | 75+ days since login) = 0.46. Two events are independent when knowing one tells you nothing about the other: the conditional probability equals the unconditional one. Almost every ML model is a machine for estimating conditional probabilities P(label | features), and "features are informative" simply means the label is not independent of them. Naive Bayes (Chapter 11) is what you get by assuming the features are independent given the label.

Bayes' theorem: updating a belief with evidence

P(H | E) = P(E | H) · P(H) / P(E), with P(E) = P(E | H)P(H) + P(E | ¬H)P(¬H)
The math (optional)

H is a hypothesis ("this patient has the disease"), E is evidence ("the test came back positive"). P(H) is the prior: how likely H was before the evidence (the prevalence). P(E | H) is the likelihood: how likely the evidence is if H is true (the test's sensitivity). P(E) is the total probability of seeing the evidence under either hypothesis, which needs the false-positive rate 1 − specificity. P(H | E) is the posterior: the updated belief. The theorem is just the definition of conditional probability written twice and rearranged, but its consequences surprise almost everyone.

The classic worked example. A disease affects 1% of the population. A test detects it 99% of the time when present (sensitivity 0.99) and comes back negative 95% of the time when absent (specificity 0.95). Your test is positive. How likely is it that you have the disease? Most people, including most doctors in published surveys, say "about 95%". Count a population of 1,000 instead:

At work

Bayes is the reason a fraud model with "99% accuracy" can be useless. If 0.1% of transactions are fraud and your model flags 1% of legitimate transactions, then for every real fraud you catch you will flag about ten innocent customers. Before promising precision numbers, compute the base rate and run this calculation. Chapter 6 turns this into precision, recall and the precision–recall curve; the arithmetic is identical.

Deep dive: why Bayes flips intuition on rare diseases — the odds form 7 min
Explain it like I'm 9

A test is a megaphone that makes your suspicion twenty times louder. If you started with a whisper (one in a thousand), twenty times a whisper is still quiet. If you started with a normal voice (one in three), twenty times that is a shout. The megaphone is the same; what comes out depends entirely on how loud you started. Doctors who say "95%" are hearing the megaphone and forgetting the whisper.

Precisely. Rewrite Bayes' theorem in terms of odds (probability of yes divided by probability of no) and the test becomes a single multiplier that does not depend on the prevalence at all:

The math (optional)
posterior odds = prior odds × LR+, LR+ = sensitivity / (1 − specificity)

Prior odds are P(H)/P(¬H): a 1% prevalence is odds of 1 : 99. LR+, the positive likelihood ratio, is how many times more likely a positive result is in a sick person than in a healthy one; with sensitivity 0.99 and specificity 0.95 it is 0.99/0.05 = 19.8. Posterior odds are what you believe after the test; convert back with P = odds/(1 + odds). The derivation is two lines: divide Bayes' theorem for H by Bayes' theorem for ¬H, and P(E) cancels. For our example: (1/99) × 19.8 = 0.2, and 0.2/1.2 = 0.167, the same 17% as Figure 3.8. A negative test multiplies the odds by LR− = (1 − sensitivity)/specificity = 0.01/0.95 ≈ 0.0105.

# Bayes in odds form: posterior odds = prior odds × likelihood ratio. The prior does the damage.
sens, spec = 0.99, 0.95
LR_pos = sens / (1 - spec)                        # how much a positive test multiplies the odds
print(f"likelihood ratio of a positive test = {sens} / {1 - spec:.2f} = {LR_pos:.1f}")
print(" prevalence   prior odds   posterior odds   P(disease | positive)")
for prev in (0.001, 0.01, 0.05, 0.10, 0.30):
    prior_odds = prev / (1 - prev)
    post_odds = prior_odds * LR_pos
    post = post_odds / (1 + post_odds)
    print(f"   {prev:5.1%}     1 : {1 / prior_odds:6.1f}     {post_odds:8.3f}          {post:6.1%}")
# likelihood ratio of a positive test = 0.99 / 0.05 = 19.8
#  prevalence   prior odds   posterior odds   P(disease | positive)
#     0.1%     1 :  999.0        0.020            1.9%
#     1.0%     1 :   99.0        0.200           16.7%
#     5.0%     1 :   19.0        1.042           51.0%
#    10.0%     1 :    9.0        2.200           68.7%
#    30.0%     1 :    2.3        8.486           89.5%

The table is the whole intuition. The test is identical in every row (LR+ = 19.8), yet a positive result means 2% in a screening population and 90% in a symptomatic clinic. The "95%" that people guess is 1 − false positive rate: it is the answer to "how often does a healthy person test negative?", a question about the test alone, whereas "do I have it?" is a question about the test and the prior. Two rules of thumb fall out. A positive result from a test with LR+ around 20 moves you from "rare" to "possible" (1% → 17%), not to "certain"; to reach 90% from 1% you need LR+ ≈ 900, which is why confirmatory tests exist. And a second, independent positive test multiplies the odds again: 0.2 × 19.8 ≈ 4, i.e. 80%, which is the logic of "repeat the test before treating".

At work

Every classifier is a test with an LR+. Read it off the confusion matrix: recall / false-positive rate. Then ask what the prior is in the population the model will actually score, which is often far lower than in the training set (fraud is 5% in the labelled sample because investigators only labelled suspicious cases, and 0.1% in live traffic). Precision in production is the posterior in the live population, and it can be a tenth of what the validation set showed. Chapter 6 computes the same quantity as precision; this is the reasoning that lets you forecast it before deployment.

7. Maximum likelihood: where loss functions come from

Explain it like I'm 9

You find a coin and flip it 50 times: 13 heads. What is the coin's chance of heads? You could try every possible answer, 10%, 20%, 30%…, and for each ask "how likely would 13 heads out of 50 be if that were the truth?" The answer that makes what you actually saw most likely is 26%. That is maximum likelihood, and it is how models pick their parameters: choose the parameters under which the data you observed would have been most probable.

θ̂ = argmaxθ P(data | θ) = argmaxθ ∑i log P(xi | θ) = argminθ [ −∑i log P(xi | θ) ]
The math (optional)

θ (theta) stands for all the parameters of a model; P(data | θ) is the likelihood, the probability of the observed examples if θ were the truth. When examples are independent the likelihood is a product over examples, so its log is a sum of per-example log-probabilities (§5). Maximising a quantity is the same as minimising its negative, so maximum likelihood = minimising the negative log-likelihood, which is precisely a loss function summed over the training set. Two famous cases: if you assume the label is normal around a linear prediction, the negative log-likelihood is the mean squared error (Chapter 5). If you assume the label is Bernoulli with probability σ(w·x), it is the log-loss / binary cross-entropy (Chapter 6). Loss functions are not arbitrary: each one is a statement about how you believe the data was generated.

# Bayes by hand, then maximum likelihood for a coin (a grid search over p)
import numpy as np
prev, sens, spec = 0.01, 0.99, 0.95
p_pos = prev*sens + (1-prev)*(1-spec)              # P(test positive)
post  = prev*sens / p_pos                          # P(disease | positive)
print(f"P(positive) = {p_pos:.4f}   P(disease | positive) = {post:.3f}")
print("per 1000: true positives ≈", round(1000*prev*sens, 1), " false positives ≈", round(1000*(1-prev)*(1-spec), 1))

# Maximum likelihood: which p makes the observed flips most probable?
rng = np.random.default_rng(1)
flips = rng.random(50) < 0.3                       # true p = 0.3, 50 flips
heads = flips.sum()
ps = np.linspace(0.01, 0.99, 99)
loglik = heads*np.log(ps) + (50-heads)*np.log(1-ps)    # log P(data | p), up to a constant
print("heads:", heads, " MLE p̂ =", ps[np.argmax(loglik)].round(2), " (= heads/50 =", heads/50, ")")
# P(positive) = 0.0594   P(disease | positive) = 0.167
# per 1000: true positives ≈ 9.9  false positives ≈ 49.5
# heads: 13  MLE p̂ = 0.26  (= heads/50 = 0.26 )
Key idea

A loss function is a negative log-likelihood in disguise. Squared error assumes Gaussian noise; log-loss assumes Bernoulli labels; Poisson regression assumes Poisson counts. When a model's errors look nothing like its assumed distribution (heavy tails, counts with lots of zeros), the loss is the first thing to question, not the algorithm.

Deep dive: from Gaussian noise to squared error, line by line 8 min
Explain it like I'm 9

Suppose you believe every measurement is "the true value plus a wobble", and that small wobbles are common and huge wobbles are rare, in the bell-shaped way. Then the most believable line through your dots is the one that makes the wobbles it needs as small as possible, and because the bell shape punishes big wobbles by their square, "most believable" turns out to mean "smallest sum of squared leftovers". Squared error was never an arbitrary choice; it is the bell curve in disguise.

Precisely. Assume each target is the model's prediction plus Gaussian noise: yi = w·xi + εi, εi ~ N(0, σ²), independently. Then the likelihood of the data given w is the product of Gaussian densities, and its negative log is a sum of squares plus constants:

The math (optional)
p(yi | xi, w) = (1/√(2πσ²)) · exp( −(yi − w·xi)² / (2σ²) )
−log P(data | w) = ∑i (yi − w·xi)² / (2σ²) + (n/2) log(2πσ²)

Line 1 is the Gaussian density: the probability of observing yi if the truth were w·xi with noise σ. Line 2 takes the log of the product (a sum of logs, §5) and flips the sign. The second term does not contain w, and 1/(2σ²) is a positive constant, so minimising the negative log-likelihood over w is the same as minimising ∑(yi − w·xi)², which is MSE up to the factor 1/n. Every symbol matters: if the noise were Laplace (double-exponential) instead of Gaussian, the exponent would contain |y − w·x| and the MLE would minimise absolute error (MAE); if the noise variance differed per row, each square would be weighted by 1/σi² (weighted least squares).

The same move for classification. Assume yi ~ Bernoulli(pi) with pi = σ(w·xi). Then P(yi | pi) = piyi(1 − pi)1−yi, and −log P(data | w) = −∑i [ yi log pi + (1 − yi) log(1 − pi) ], which is exactly the log-loss of Chapter 6. Nothing was chosen; it was derived from "labels are coin flips whose bias depends on x".

# Maximum likelihood by grid search: the Gaussian NLL and the MSE pick the same slope; the Bernoulli NLL is log-loss
import numpy as np
from sklearn.metrics import log_loss
rng = np.random.default_rng(0)

# --- regression: y = 2x + Gaussian noise. Which slope w makes the data most likely?
x = rng.uniform(0, 5, 40); y = 2 * x + rng.normal(0, 1.0, 40)
ws = np.linspace(1.5, 2.5, 1001)
mse = np.array([np.mean((y - w * x) ** 2) for w in ws])
nll = np.array([np.sum(0.5 * np.log(2 * np.pi) + 0.5 * (y - w * x) ** 2) for w in ws])   # σ = 1
print(f"slope minimising MSE = {ws[mse.argmin()]:.3f}   slope minimising Gaussian NLL = {ws[nll.argmin()]:.3f}   "
      f"least squares: {np.sum(x * y) / np.sum(x * x):.3f}")

# --- classification: the Bernoulli negative log-likelihood IS sklearn's log_loss
p = np.array([0.9, 0.2, 0.7, 0.4]); yb = np.array([1, 0, 0, 1])
nll_bern = -np.mean(yb * np.log(p) + (1 - yb) * np.log(1 - p))
print(f"Bernoulli NLL (mean) = {nll_bern:.4f}   sklearn log_loss = {log_loss(yb, p):.4f}")
# slope minimising MSE = 2.108   slope minimising Gaussian NLL = 2.108   least squares: 2.108
# Bernoulli NLL (mean) = 0.6122   sklearn log_loss = 0.6122

The grid search makes the identity concrete: the slope that minimises MSE, the slope that minimises the Gaussian negative log-likelihood, and the least-squares formula all land on 2.108, because they are three spellings of the same objective. The Bernoulli line shows that scikit-learn's log_loss is literally the mean negative log-likelihood of the labels under the model's probabilities.

Key idea

When a stakeholder asks "why squared error?", the honest answer is "because we are assuming the errors are roughly bell-shaped and equally spread". If the residual plot (Chapter 5) says otherwise, with heavy tails or a funnel, the assumption is wrong and the loss should change with it: MAE or Huber loss for heavy tails, a log-transformed target or a Poisson/Gamma likelihood for skewed positive quantities. The loss is a modelling decision, and the likelihood is how you make it deliberately.

8. Statistics you will use every week

Describing a column: centre, spread, quantiles

The mean is the arithmetic average; it is the number that minimises squared error and it is pulled by outliers. The median is the middle value; it minimises absolute error and ignores outliers. The mode is the most frequent value; useful for categories. The standard deviation is the typical distance from the mean (§6). Quantiles cut the sorted data into fractions: the 90th percentile is the value that 90% of rows fall below. For skewed data (spend, income, latency) report the median and a couple of quantiles; the mean alone is misleading, as the spend histogram in Chapter 2 showed.

Sampling error: every number you compute is a guess

Explain it like I'm 9

If you want to know how tall kids in your school are, you measure 30 of them and average. Measure a different 30 and you get a slightly different average. Neither is wrong; they are both estimates of the true school-wide average, and the wobble between them is sampling error. Bigger samples wobble less. The bootstrap is a clever trick for measuring the wobble using only the one sample you have.

SE(mean) = s / √n 95% CI ≈ mean ± 1.96 · SE
The math (optional)

s is the sample standard deviation and n the sample size. The standard error is the standard deviation of the estimate itself: how much the mean would vary across repeated samples. It shrinks with √n, so four times the data halves the error. The central limit theorem says the sampling distribution of a mean is approximately normal whatever the data's shape, which justifies the 1.96 (the normal distribution's 97.5th percentile) in the 95% confidence interval. A 95% CI means: if you repeated the whole study many times, 95% of the intervals you built would contain the true value. It does not mean "there is a 95% probability the truth is in this interval", although in practice people read it that way and it is rarely harmful.

The bootstrap replaces the formula with computation, and works for any statistic (a median, a ratio, a model's AUC): resample your n rows with replacement, recompute the statistic, repeat a few thousand times, and read the spread of the results. The 2.5th and 97.5th percentiles of the bootstrap results give a 95% interval. This is the tool you will use to put error bars on model metrics in Chapter 13.

# Describing a skewed column, and putting an honest error bar on the mean, two ways
import numpy as np
rng = np.random.default_rng(0)
spend = rng.gamma(4, 12, 400).round(2)             # 400 customers' monthly spend (skewed)
print(f"mean {spend.mean():.2f}  median {np.median(spend):.2f}  std {spend.std(ddof=1):.2f}")
print("quantiles 10/50/90:", np.quantile(spend, [.1, .5, .9]).round(1))

# standard error of the mean: formula vs bootstrap
se_formula = spend.std(ddof=1) / np.sqrt(len(spend))
boot_means = np.array([rng.choice(spend, len(spend), replace=True).mean() for _ in range(2000)])
print(f"SE (formula) {se_formula:.2f}   SE (bootstrap) {boot_means.std():.2f}")
lo, hi = np.percentile(boot_means, [2.5, 97.5])
print(f"95% bootstrap CI for the mean: [{lo:.1f}, {hi:.1f}]")

# the same trick works for ANY statistic, e.g. the median (no formula needed)
boot_med = [np.median(rng.choice(spend, len(spend), replace=True)) for _ in range(2000)]
print("95% CI for the median:", np.percentile(boot_med, [2.5, 97.5]).round(1))
# mean 46.50  median 43.59  std 22.71
# quantiles 10/50/90: [21.1 43.6 77.4]
# SE (formula) 1.14   SE (bootstrap) 1.13
# 95% bootstrap CI for the mean: [44.3, 48.8]
# 95% CI for the median: [39.7 46.2]

p-values, in one honest paragraph

A p-value answers a narrow question: if there were truly no effect (the "null hypothesis"), how often would random sampling alone produce a result at least this extreme? A small p-value (conventionally below 0.05) says the data would be surprising under "no effect". It does not tell you the probability that the effect is real, how big the effect is, or whether it matters. With enough data, trivially small effects become "significant"; with little data, large real effects do not. In practice at work: report the effect size with a confidence interval, use the p-value as a sanity check against noise, and never run twenty tests and report the one that passed (that is the multiple-comparisons trap, and it is the leakage of statistics). For A/B tests, decide the sample size before you start and do not peek.

Common mistake

Correlation is not causation, and models do not care. Ice-cream sales correlate with drownings (both rise in summer). Customers who call support churn more; that does not mean support calls cause churn, and cancelling the support line will not reduce churn. A predictive model is allowed to use any correlate it can find, which is what makes it useful for prediction and dangerous for decisions: "if we reduce X, will Y change?" is a causal question that needs an experiment (A/B test) or causal methods (Chapter 22), not a feature importance. When a stakeholder asks "what should we change?", that is your cue to slow down.

9. A taste of information theory: entropy

Explain it like I'm 9

How surprised are you by the answer? If I tell you a fair coin came up heads, you learn a little (it could have gone either way). If I tell you a coin that is heads 99% of the time came up heads, you learn almost nothing. If it came up tails, you learn a lot. Entropy is the average surprise: how much you expect to learn from the answer before you hear it. It is measured in bits: one bit is the surprise of a fair coin flip.

H(X) = −∑k P(X = k) · log2 P(X = k) (surprise of outcome k = −log2 P(k) bits)
The math (optional)

The surprise (information) of an outcome with probability p is −log2 p bits: probability ½ → 1 bit, ¼ → 2 bits, 1 → 0 bits. Entropy is the expected surprise: each outcome's surprise weighted by its probability. It is maximal when all outcomes are equally likely (log2 K bits for K outcomes) and zero when the outcome is certain. Worked example: a node in a decision tree contains 26% churners and 74% stayers. H = −(0.26 log2 0.26 + 0.74 log2 0.74) = −(0.26 × (−1.943) + 0.74 × (−0.434)) = 0.505 + 0.321 = 0.827 bits. A pure node (100% one class) has 0 bits. Decision trees (Chapter 9) choose the split that reduces entropy the most, the information gain; cross-entropy loss (Chapters 6 and 15) is the same formula with the model's predicted probabilities inside the log.

# Entropy in bits, and the information gain of a split (the heart of decision trees)
import numpy as np
def entropy(p):
    p = np.asarray(p, dtype=float); p = p[p > 0]        # 0·log 0 is defined as 0
    return max(0.0, -(p * np.log2(p)).sum())
print("fair coin       :", entropy([.5, .5]), "bits")
print("loaded 90/10    :", entropy([.9, .1]).round(3), "bits")
print("certain         :", entropy([1.0]), "bits")
print("fair 8-sided die:", entropy([1/8]*8), "bits  (= log2 8)")

# a node in a decision tree: 26% churners
print("churn node (26/74):", entropy([.26, .74]).round(3), "bits")
# a split that separates them better lowers the average entropy -> information gain (Ch 9)
left, right = [.10, .90], [.45, .55]           # two children holding 55% and 45% of the rows
after = 0.55*entropy(left) + 0.45*entropy(right)
print("after split:", after.round(3), "bits  -> gain", (entropy([.26,.74]) - after).round(3))
# fair coin       : 1.0 bits
# loaded 90/10    : 0.469 bits
# certain         : 0.0 bits
# fair 8-sided die: 3.0 bits  (= log2 8)
# churn node (26/74): 0.827 bits
# after split: 0.705 bits  -> gain 0.122
Key idea

Three ideas in this chapter are secretly the same idea. Entropy measures the surprise in a distribution. Cross-entropy loss measures the surprise of the true labels under the model's distribution: a confident wrong prediction is very surprising and costs a lot. And maximum likelihood minimises exactly that cross-entropy. When you train a classifier, you are teaching it to be less surprised by the data.

Quiz

Check your understanding

1. X has shape (2000, 8) and W has shape (8, 16). What is the shape of X @ W, and what does it represent?

Inner dimensions (8 and 8) match and vanish; the outer ones (2000 and 16) remain. Each column of W is one weight vector, so every row gets 16 scores: exactly what a neural-network layer computes (§2).

2. At the current parameters the gradient of the loss is (−6, 18). With learning rate 0.1, what is the next update?

The gradient points uphill, so we step against it: w ← w − 0.1 × (−6, 18) = w + (0.6, −1.8). The second parameter moves more because its slope is steeper (§4).

3. Two document vectors are (1, 2, 0) and (10, 20, 0). Which statement is true?

The second vector is 10× the first: same direction, so cosine = 1, while Euclidean distance is about 20. For word counts, length reflects document size, not content, so cosine is the sensible measure (§3).

4. A fraud model has sensitivity 90% and specificity 99%. Fraud occurs in 0.5% of transactions. Roughly what fraction of flagged transactions are actually fraud?

Per 10,000 transactions: 50 frauds, 45 caught; 9,950 legitimate, 1% = 99.5 false alarms. Posterior = 45 / (45 + 99.5) ≈ 0.31. The base rate dominates (§6).

5. You measured a model's accuracy on 400 test rows as 75%. A colleague's variant scores 77% on the same rows. What is the most defensible conclusion?

SE = √(0.75 × 0.25 / 400) ≈ 0.022, so the 95% interval is about ±4.2 points; a 2-point gap is noise at this sample size. Compute a CI on the difference (paired bootstrap over the same rows) before claiming an improvement (§8).

6. A decision-tree node has 50% churners. After a candidate split, the two children (equal size) have 50% and 50% churners. What is the information gain?

Parent entropy is 1 bit; each child is also at p = 0.5, so 1 bit each; the weighted average is still 1 bit and the gain is 0. A split only gains information if it makes the children purer (§9).

A good memo contains: the three numbers with their sources (or clearly labelled estimates); the 1,000-person tree; precision as a single sentence ("of every 10 alerts, about 3 are real"); the cost of a false alarm versus a missed case in business terms; and a recommendation that moves one lever, usually raising the threshold to trade sensitivity for specificity, or applying the rule only to a higher-base-rate subgroup (which is what Bayes tells you: the prior matters as much as the test). Chapter 6 gives you the precision–recall curve to choose that threshold quantitatively.

Chapter summary

  • A vector is a row of features; the dot product w·x is both a weighted sum (a model's score) and a similarity (‖w‖‖x‖cos θ).
  • Matrix × vector scores every row at once; matrix × matrix applies k models at once (a layer). Inner dimensions must match: (n×d)(d×k) → (n×k).
  • Euclidean and Manhattan measure distance (scale features first); cosine measures direction only and suits text and embeddings.
  • The derivative is the slope; the gradient is the slope in every parameter direction and points uphill. Training = step against it: w ← w − η∇L.
  • The chain rule multiplies local derivatives along a composition; backpropagation is the chain rule applied layer by layer.
  • Convex losses have one minimum (linear models); non-convex ones (neural nets) have many, so starting point and optimiser matter.
  • Logs turn products into sums and prevent underflow; sigmoid squashes a score to (0,1); softmax turns K scores into a distribution.
  • Bernoulli, binomial, normal, uniform and Poisson cover most modelling; know their means and variances.
  • Bayes: posterior ∝ likelihood × prior. Count per 1,000 people; rare conditions make positive tests mostly false alarms.
  • Maximum likelihood = minimising negative log-likelihood; every standard loss is one. MSE assumes Gaussian noise, log-loss assumes Bernoulli labels.
  • Every statistic has sampling error: SE = s/√n, bootstrap for anything else. p-values check noise, not importance. Correlation is not causation.
  • Entropy = expected surprise in bits; information gain drives decision trees; cross-entropy loss is the same formula with model probabilities inside.
