1. The ML landscape map

Everything in this book hangs off one tree. At the root: learn a function from data. The first split is by the kind of feedback in the data (Chapter 1): labels give you supervised learning, no labels give you unsupervised learning, and rewards give you reinforcement learning. Deep learning is not a fourth family but a family of models (stacked differentiable layers) that can be used in any of the three; we draw it as its own column because its tooling, failure modes and vocabulary are different enough to deserve one. Along the bottom run the cross-cutting skills that every project needs regardless of branch.

Key idea

The map is not a ranking. Boosted trees win on most business tables (Chapter 10); deep learning wins when the input is an image, text, audio or a truly huge dataset (Chapters 17–19); unsupervised methods win when there is no label yet (Chapter 12). The columns are separated by what the data gives you, not by how sophisticated the method is.

2. The workflow at a glance & leakage checklist

Chapter 1 introduced the seven-step loop and Chapter 23 ran it end to end. Here it is compressed to the one question you must answer at each step and the tool you will reach for. If you can answer all seven questions for a project, you understand the project; if one is blank, that is where it will fail.

Common mistake — the leakage checklist (Chapters 7, 8, 13, 23)

Leakage is the single most common reason a model looks great in the notebook and useless in production. Before you trust any score, tick every box:

  • Time: every feature is computable from information available at the moment the prediction would be made. No "days until cancellation", no post-outcome fields (refund issued, ticket closed).
  • Split first: scalers, imputers, encoders, feature selectors and target encoders are fitted on the training fold only — i.e. they sit inside the Pipeline that cross-validation refits.
  • Groups: rows from the same customer / patient / device are all in the same fold (GroupKFold), so the model can't memorize an entity.
  • Time series: validation folds are strictly later than training folds (TimeSeriesSplit); no random shuffling of a time axis.
  • Duplicates: near-identical rows (re-exports, retries) are deduplicated before splitting, or they straddle the split and inflate the score.
  • Target proxies: no feature is a renamed or aggregated version of the target (e.g. "customer risk tier" set by the same fraud team whose decisions are the label).
  • Suspiciously good: an AUC above 0.95 on a hard business problem, or one feature with 80% of the importance, is a leak until proven otherwise.
  • Train/serve parity: the production feature code is the same code (ideally the same pickled pipeline) as the training feature code.

At work

Two rules cover 90% of model choice on tabular data. Rule 1: start with a regularized linear model as a baseline and a gradient-boosted tree model as the contender; if boosting beats linear by a lot, the relationship is non-linear and you keep boosting. Rule 2: if you have fewer than a thousand rows, or you must explain each prediction to a regulator, the linear model (or a shallow tree) is probably the final answer. Everything else in this table is for specific situations: kNN and SVM for small, clean, low-dimensional problems; Naive Bayes for bag-of-words text; deep nets for images, text and sequences.

Explain it like I'm 9

A smoke detector that never beeps is "99.9% accurate" because there is almost never a fire. That is why accuracy is a bad report card for rare things. Instead we ask two questions: when it beeps, was there really a fire (precision)? And when there was a fire, did it beep (recall)? The metric table is just a list of which report card to use for which kind of test.

5. Formula sheet

Every formula the book used, one line of meaning each, grouped by theme. The symbols are the book's standard ones: x is an input vector, y a true target, ŷ a prediction, w weights, n the number of examples, p a predicted probability. If a formula does not make sense in one reading, the chapter reference is where the slow explanation lives.

Regression & linear models

The math
ŷ = w0 + w1x1 + … + wdxd = wTx + b

Linear model (Ch 5). A weighted sum of the features plus an intercept; each wj is "change in ŷ per unit of xj, holding the rest fixed".

MSE = (1/n) ∑ (yi − ŷi)²    RMSE = √MSE    MAE = (1/n) ∑ |yi − ŷi|

Regression errors (Ch 5). MSE squares the misses (big ones dominate, and it is differentiable); RMSE is MSE back in the units of y; MAE is the typical absolute miss and is robust to outliers.

R² = 1 − ∑ (yi − ŷi)² / ∑ (yi − ȳ)²

Coefficient of determination (Ch 5). Fraction of the target's variance the model explains; 0 = no better than predicting the mean, 1 = perfect, negative = worse than the mean (possible on test data).

L1 (Lasso): loss + λ ∑ |wj|     L2 (Ridge): loss + λ ∑ wj²

Regularization penalties (Ch 5, 7). Both shrink weights toward zero to reduce variance; L1 drives some weights to exactly zero (feature selection), L2 shrinks all of them smoothly. In scikit-learn λ is alpha for Ridge/Lasso and 1/C for logistic regression and SVM.

Bias–variance: E[(y − ŷ)²] = Bias(ŷ)² + Var(ŷ) + σ²noise

Bias–variance decomposition (Ch 7). Expected squared error = systematic error from a too-simple model + sensitivity to which training set you happened to get + irreducible noise; more flexibility lowers bias and raises variance.

Classification & probability

The math
σ(z) = 1 / (1 + e−z),   z = wTx + b,   p = σ(z)

Sigmoid / logistic regression (Ch 6). Squashes any real number into (0, 1) so a linear score becomes a probability; z is the log-odds, so each unit of xj multiplies the odds by ewj.

Log-loss = −(1/n) ∑ [ yi log pi + (1 − yi) log(1 − pi) ]

Binary cross-entropy (Ch 6). Penalizes confident wrong probabilities without bound (p → 0 for a positive costs → ∞); minimizing it is maximum-likelihood fitting.

softmax(z)k = ezk / ∑j ezj     CE = −∑k yk log pk

Softmax and cross-entropy (Ch 6, 15). Softmax turns K scores into K probabilities that sum to 1; cross-entropy is −log of the probability given to the true class (one-hot y picks it out).

Precision = TP/(TP+FP)   Recall = TP/(TP+FN)   F1 = 2·P·R/(P+R)   Fβ = (1+β²)·P·R / (β²P + R)

Threshold metrics (Ch 6). Precision = purity of the alarms, recall = coverage of the real positives, F1 = their harmonic mean; Fβ with β = 2 weights recall more (fraud, cancer screening), β = 0.5 weights precision more.

AUC = P( score(random positive) > score(random negative) )

ROC-AUC meaning (Ch 6). The area under the ROC curve equals the probability that the model ranks a random positive above a random negative; 0.5 is coin-flipping, 1.0 is perfect ranking, and it does not depend on the threshold or on class balance.

MCC = (TP·TN − FP·FN) / √[(TP+FP)(TP+FN)(TN+FP)(TN+FN)]

Matthews correlation coefficient (Ch 6, 13). Correlation between predicted and actual labels, from −1 to +1; unlike F1 it uses all four cells, so it stays honest on imbalanced data.

P(A | B) = P(B | A) · P(A) / P(B)

Bayes' theorem (Ch 3, 11). Posterior = likelihood × prior / evidence; Naive Bayes multiplies per-feature likelihoods as if features were independent given the class.

Trees

The math
Gini(S) = 1 − ∑k pk²     H(S) = −∑k pk log2 pk

Gini impurity and entropy (Ch 9). Both measure how mixed the classes are in a node (0 = pure); Gini is the probability two random draws disagree, entropy is the bits needed to encode the class.

IG(S, split) = H(S) − ∑children c (|Sc| / |S|) · H(Sc)

Information gain (Ch 9). Impurity of the parent minus the size-weighted impurity of the children; the tree greedily picks the feature and threshold with the largest gain. For regression, impurity is the node's MSE.

Optimization

The math
w ← w − η · ∇w L(w)

Gradient descent (Ch 5, 15). Step downhill on the loss surface in the direction of steepest descent; η is the learning rate, and mini-batch/stochastic versions estimate ∇L from a batch.

v ← β v + ∇L;   w ← w − η v

Momentum (Ch 16). Keep a running average of past gradients (β ≈ 0.9) so steps accelerate along consistent directions and damp out oscillations.

m ← β1m + (1−β1)g;   v ← β2v + (1−β2)g²;   w ← w − η · m̂ / (√v̂ + ε)

Adam (Ch 16). Momentum on the gradient (m) plus a per-parameter running scale (v) so every weight gets its own effective learning rate; the hats are bias corrections for the first steps. Defaults β1 = 0.9, β2 = 0.999, η = 10⁻³ work surprisingly often.

Similarity, attention, explanation & the rest

The math
cos(a, b) = a·b / (‖a‖ ‖b‖)

Cosine similarity (Ch 12, 19). The cosine of the angle between two vectors, ignoring their length; 1 = same direction, 0 = unrelated, −1 = opposite. The standard measure for embeddings.

Attention(Q, K, V) = softmax( Q KT / √dk ) V

Scaled dot-product attention (Ch 18). Each query scores every key by dot product, the scores become weights through softmax (divided by √dk to keep them well-scaled), and the output is the weighted average of the values — a learned, content-based lookup.

φi = ∑S ⊆ F∖{i} [ |S|! (|F| − |S| − 1)! / |F|! ] · [ f(S ∪ {i}) − f(S) ]

Shapley value (Ch 20). Feature i's contribution is its average marginal effect on the prediction over every possible order in which features could be added; SHAP values sum exactly to prediction minus the average prediction.

PSI = ∑bins (pnow − pref) · ln( pnow / pref )

Population stability index (Ch 21). Drift between a reference distribution and today's, computed over bins; rule of thumb < 0.1 stable, 0.1–0.25 watch, > 0.25 investigate or retrain.

Q(s, a) ← Q(s, a) + α [ r + γ maxa' Q(s', a') − Q(s, a) ]

Q-learning update (Ch 22). Nudge the value of taking action a in state s toward the reward received plus the discounted best value of the next state; α is the learning rate, γ the discount factor.

ARIMA(p, d, q):   y't = c + ∑i=1..p φi y't−i + ∑j=1..q θj εt−j + εt,   y' = series differenced d times

ARIMA notation (Ch 14). p past values (autoregressive), d rounds of differencing to make the series stationary, q past forecast errors (moving average); seasonal SARIMA adds (P, D, Q)m at the seasonal lag m.

z = (x − μ) / σ

z-score / standardization (Ch 3, 8). Express a value as "how many standard deviations from the mean"; what StandardScaler does, and the basis of a first-pass outlier rule (|z| > 3).

The universal pattern: split → fit → predict → score

# The universal pattern: split -> fit on train -> predict on test -> score
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.dummy import DummyClassifier
from sklearn.metrics import accuracy_score, roc_auc_score

X, y = load_breast_cancer(return_X_y=True, as_frame=True)
X_tr, X_te, y_tr, y_te = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42)   # stratify keeps class ratio

baseline = DummyClassifier(strategy="most_frequent").fit(X_tr, y_tr)
model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
model.fit(X_tr, y_tr)                       # every estimator: .fit(X, y)

pred  = model.predict(X_te)                 # hard labels
proba = model.predict_proba(X_te)[:, 1]     # P(class 1); needed for AUC / thresholds
print(f"baseline acc = {accuracy_score(y_te, baseline.predict(X_te)):.3f}")
print(f"model    acc = {accuracy_score(y_te, pred):.3f}   AUC = {roc_auc_score(y_te, proba):.3f}")
print(f"score()  ->   {model.score(X_te, y_te):.3f}   (default metric: accuracy)")
print("transformers use .fit / .transform / .fit_transform; models use .fit / .predict")

The Pipeline + ColumnTransformer template

This is the block to copy into every tabular project. Numeric columns get a median imputer and a scaler, categorical columns get a most-frequent imputer and a one-hot encoder with handle_unknown="ignore", and the whole thing is cross-validated as a unit.

# Pipeline + ColumnTransformer template: the one you copy into every tabular project
import numpy as np, pandas as pd
from sklearn.compose import ColumnTransformer, make_column_selector as selector
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.model_selection import cross_val_score, StratifiedKFold

rng = np.random.default_rng(0)
n = 1200
df = pd.DataFrame({
    "age":     rng.normal(40, 12, n).round(),
    "income":  rng.lognormal(10.5, 0.5, n).round(),
    "tenure":  rng.integers(0, 120, n).astype(float),
    "plan":    rng.choice(["basic", "plus", "pro"], n, p=[.5, .3, .2]),
    "region":  rng.choice(["north", "south", "east", "west"], n),
})
df.loc[rng.random(n) < 0.08, "income"] = np.nan          # realistic missingness
df.loc[rng.random(n) < 0.03, "plan"] = np.nan
logit = -2 + 0.06*(df["age"]-40) - 0.02*df["tenure"] + (df["plan"] == "basic")*1.5
y = (rng.random(n) < 1/(1+np.exp(-logit))).astype(int)      # churn label

numeric = Pipeline([("impute", SimpleImputer(strategy="median")),
                    ("scale",  StandardScaler())])
categorical = Pipeline([("impute", SimpleImputer(strategy="most_frequent")),
                        ("onehot", OneHotEncoder(handle_unknown="ignore"))])
prep = ColumnTransformer([
    ("num", numeric,     selector(dtype_include=np.number)),
    ("cat", categorical, selector(dtype_exclude=np.number)),
])
pipe = Pipeline([("prep", prep),
                 ("model", HistGradientBoostingClassifier(max_iter=200, learning_rate=0.05,
                                                          random_state=0))])
cv = StratifiedKFold(5, shuffle=True, random_state=0)
scores = cross_val_score(pipe, df, y, cv=cv, scoring="roc_auc")   # prep refit per fold: no leakage
print(f"CV ROC-AUC = {scores.mean():.3f} ± {scores.std():.3f}")
pipe.fit(df, y)
print("feature names out:", list(pipe[:-1].get_feature_names_out())[:5], "...")
# CV ROC-AUC = 0.740 ± 0.054
# feature names out: ['num__age', 'num__income', 'num__tenure', 'cat__plan_basic', 'cat__plan_plus'] ...

PyTorch training-loop skeleton

The five lines inside the batch loop (zero the gradients, forward, loss, backward, step) are the same in every PyTorch project from this toy MLP to a vision Transformer (Chapter 16). Everything else — data loading, validation, early stopping, checkpointing — wraps around them.

# PyTorch training-loop skeleton (the same 12 lines scale from this toy to ImageNet)
import torch, torch.nn as nn
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

torch.manual_seed(0)
X, y = make_classification(n_samples=3000, n_features=20, n_informative=8, random_state=0)
Xtr, Xva, ytr, yva = train_test_split(X, y, test_size=0.2, stratify=y, random_state=0)
sc = StandardScaler().fit(Xtr)                                    # scale: fit on train only
to_t = lambda a, dt=torch.float32: torch.tensor(a, dtype=dt)
Xtr, Xva = to_t(sc.transform(Xtr)), to_t(sc.transform(Xva))
ytr, yva = to_t(ytr, torch.long), to_t(yva, torch.long)
loader = torch.utils.data.DataLoader(torch.utils.data.TensorDataset(Xtr, ytr), batch_size=64, shuffle=True)

model = nn.Sequential(nn.Linear(20, 64), nn.ReLU(), nn.Dropout(0.2),
                      nn.Linear(64, 32), nn.ReLU(), nn.Linear(32, 2))
opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-4)
loss_fn = nn.CrossEntropyLoss()                                   # takes raw logits + int labels

best, patience, bad = 0.0, 3, 0
for epoch in range(30):
    model.train()
    for xb, yb in loader:
        opt.zero_grad()                                           # 1. clear old gradients
        loss = loss_fn(model(xb), yb)                             # 2. forward + loss
        loss.backward()                                           # 3. backprop
        opt.step()                                                # 4. update weights
    model.eval()
    with torch.no_grad():                                         # 5. validate without gradients
        acc = (model(Xva).argmax(1) == yva).float().mean().item()
    if acc > best: best, bad, state = acc, 0, {k: v.clone() for k, v in model.state_dict().items()}
    else: bad += 1
    if bad >= patience: break                                     # 6. early stopping
model.load_state_dict(state)
print(f"stopped at epoch {epoch+1}, best val acc ≈ {best:.3f}")
# stopped at epoch 13, best val acc ≈ 0.942

At work

Tuning has diminishing returns. In a typical tabular project the gains stack roughly like this: a good validation scheme and leak-free features (huge), the right model family (large), early stopping and learning rate (moderate), tree structure parameters (small), everything else (noise). If a colleague spends a week on Bayesian optimization of colsample_bytree, the project is probably in trouble elsewhere. Budget: one RandomizedSearchCV with 30–60 draws, then stop.

8. The debugging flowchart

"The model performs badly" is not a diagnosis. There are four different diseases with four different treatments, and the first three questions in the flowchart separate them: is the training score bad? (underfitting — the model cannot even fit what it has seen), is the gap between training and validation big? (overfitting — it fits what it has seen and nothing else), is cross-validation great but production bad? (leakage, drift or a train/serve mismatch), and does the score jump around across seeds or folds? (instability — too little data for the variance of the model). Chapters 7, 13, 21 and 23 covered each branch in depth.

Key idea

Three numbers diagnose almost everything: training score, validation score (mean ± std across folds), and, once deployed, production score. Print all three every time. Low–low is underfitting; high–low is overfitting; high–high–low is leakage or drift; wide ± is instability. Reading the flowchart takes a minute; guessing without it takes a week.

9. Glossary

Every term the book introduced, alphabetically, at most two sentences each, with the chapter where it is explained properly. Use it to settle arguments in design reviews and to decode papers and documentation. Bold term, then definition.

A

Activation function
The non-linearity applied after each layer's weighted sum (ReLU, sigmoid, tanh, GELU); without it a deep network collapses into one linear layer. (Ch 15)
Adam
An optimizer that combines momentum with a per-parameter adaptive step size; the default choice for training neural networks. (Ch 16)
AdaBoost
An early boosting algorithm that re-weights misclassified examples so the next weak learner focuses on them; historically important, now mostly replaced by gradient boosting. (Ch 10)
Anomaly detection
Finding rows that do not look like the rest, usually without labelled examples of "anomalous"; Isolation Forest, DBSCAN noise points and autoencoder reconstruction error are the common tools. (Ch 22)
ARIMA
AutoRegressive Integrated Moving Average, a classical forecasting model written ARIMA(p, d, q): p lags of the series, d differences, q lags of past errors. (Ch 14)
Attention
A mechanism that lets each position in a sequence compute a weighted average over all other positions, with weights learned from content; the core of the Transformer. (Ch 18)
AUC (ROC-AUC)
Area under the ROC curve; the probability that a random positive is scored above a random negative. Threshold-free and class-balance-insensitive. (Ch 6)
Autoencoder
A network trained to reconstruct its input through a narrow bottleneck; the bottleneck is a learned compression, and large reconstruction error flags anomalies. (Ch 22)
Autoregressive
Predicting the next value from previous values of the same series; ARIMA's AR term and LLM next-token generation are both autoregressive. (Ch 14, 19)

B

Backpropagation
The chain rule applied layer by layer, backwards, to compute the gradient of the loss with respect to every weight in a network. (Ch 15)
Bagging
Bootstrap aggregating: train many models on bootstrap resamples of the data and average their predictions to reduce variance; the idea behind random forests. (Ch 10)
Baseline
The simplest possible predictor (mean, majority class, last value, the current business rule) that every model must beat convincingly to justify its existence. (Ch 1, 23)
Batch / mini-batch
A subset of training rows used for one gradient step; batch size trades gradient noise against memory and speed. (Ch 16)
Batch normalization
A layer that standardizes its inputs using batch statistics, stabilizing and speeding up deep-network training. (Ch 16)
Bayes' theorem
P(A|B) = P(B|A)P(A)/P(B): update a prior belief with evidence to get a posterior. (Ch 3, 11)
Bias (statistical)
Systematic error from a model that is too simple to capture the true pattern; the "underfitting" half of the bias–variance trade-off. (Ch 7)
Bias (weight)
The intercept term b in wᵀx + b, letting a linear unit shift its output; unrelated to statistical bias. (Ch 5, 15)
Bias–variance trade-off
Making a model more flexible lowers bias but raises variance; the best generalization sits at the minimum of their sum. (Ch 7)
Boosting
Building an ensemble sequentially, each new model correcting the errors of the sum so far; gradient boosting is the dominant form. (Ch 10)
Bootstrap
Resampling the training set with replacement to create many "alternative" datasets; used in bagging and to estimate confidence intervals. (Ch 7, 10)
Brier score
Mean squared error between predicted probabilities and 0/1 outcomes; a proper measure of probability quality. (Ch 13)

C

Calibration
Whether predicted probabilities match observed frequencies (of events scored 0.8, about 80% happen); checked with a calibration curve and fixed with Platt scaling or isotonic regression. (Ch 13)
Categorical feature
A column whose values are labels rather than quantities (country, plan type); needs encoding (one-hot, ordinal, target) or a model that handles it natively. (Ch 8)
Causal inference
Estimating the effect of an intervention rather than a correlation; needs experiments (A/B tests) or assumptions (confounders observed) that prediction does not. (Ch 22)
Class imbalance
When one class is far rarer than the other; makes accuracy misleading and calls for PR-AUC, class weights, resampling or threshold tuning. (Ch 13)
Classification
Supervised learning where the target is a category. (Ch 1, 6)
Clustering
Grouping rows so that members of a group are similar to each other and different from other groups, without labels. (Ch 12)
Coefficient
A learned weight in a linear model; its sign and size (after scaling) say how the feature moves the prediction. (Ch 5)
ColumnTransformer
The scikit-learn object that applies different preprocessing to different columns (scale the numbers, one-hot the categories) inside one pipeline. (Ch 8)
Concept drift
The relationship between features and target changes over time (the same inputs now mean something else), so the model must be retrained. (Ch 21)
Confusion matrix
The table of actual vs predicted classes (TP, FP, FN, TN for binary); every classification metric is a ratio of its cells. (Ch 6)
Convolution
Sliding a small learned filter across an image (or sequence) to detect a local pattern anywhere it appears; the building block of CNNs. (Ch 17)
Cosine similarity
The cosine of the angle between two vectors; the standard similarity measure for embeddings. (Ch 12, 19)
Cross-entropy
The loss for classification: −log of the probability assigned to the true class, averaged over examples. (Ch 6, 15)
Cross-validation
Splitting the data into k folds and training k times, each time holding out one fold, to estimate generalization with less variance than a single split. (Ch 7)
Curse of dimensionality
As features grow, data becomes sparse and distances become uninformative, hurting kNN, clustering and anything distance-based. (Ch 11, 12)

D

Data drift
The distribution of the inputs changes over time (new customer mix, new sensor) even if the true relationship does not; detected with PSI or similar. (Ch 21)
Data leakage
Information about the target sneaking into the features or preprocessing, inflating validation scores that then collapse in production. (Ch 7, 8)
DBSCAN
Density-based clustering that grows clusters from dense cores and labels sparse points as noise; finds arbitrary shapes without choosing k. (Ch 12)

10. Interview & self-test: 40 questions

Forty questions in three tiers. Answer each out loud before opening the model answer; if your version is shorter, more concrete and mentions a trade-off, it is probably better than ours. Interviewers are not testing whether you know the words. They are testing whether you know when the textbook answer is wrong, so every model answer below ends with the caveat a senior person would add.

Beginner (1–10)

1. What is the difference between supervised and unsupervised learning? Give one business example of each.

Supervised learning has an answer key: every training row carries the label we want to predict, and the model learns the mapping from features to label (churn prediction from past churners). Unsupervised learning has no labels; the model finds structure such as clusters, low-dimensional projections or anomalies (segmenting customers by behaviour). The practical difference is evaluation: supervised models are scored against held-out labels, unsupervised ones by whether the structure is useful and stable. Caveat: many "unsupervised" business problems are really supervised problems waiting for someone to collect labels (Chapter 1, 12).

2. Regression or classification: "predict whether a shipment will be late" vs "predict how many hours late"?

"Whether late" is a binary classification (label yes/no); "how many hours" is regression (a number). Same data, different framing, different loss and metric. Choose the framing that matches the decision: if operations will either re-route or not, classification with a tuned threshold is enough; if they need to reschedule downstream work, they need the number. Caveat: you can often get both by regressing hours and thresholding, but a direct classifier is usually better calibrated at the cut-off (Chapter 1, 6).

3. Why do we split data into training and test sets?

Because a model's error on the data it learned from tells you nothing about how it will do on new data; a sufficiently flexible model can memorize the training set. The held-out test set simulates "the future": rows the model has never seen. Training score minus test score is the overfitting gap. Caveat: a single split is a noisy estimate; use cross-validation for model selection and keep the test set for one final number (Chapter 7).

4. What is overfitting, and how would you spot it?

Overfitting is fitting the noise in the training data as if it were signal, so the model does great on training rows and poorly on new ones. You spot it as a large gap between training and validation scores, and as validation score getting worse while training score keeps improving (the learning curve bends). The fixes are more data, more regularization, a simpler model, or early stopping. Caveat: a small gap does not prove the model is good; it may be underfitting both (Chapter 7).

5. Explain the bias–variance trade-off to a non-technical manager.

Bias is being consistently wrong because your model is too simple to capture the real pattern (a straight line through a curve). Variance is being inconsistently wrong because the model chases every quirk of the particular data it saw (a wiggly curve through noise). Making a model more flexible lowers bias but raises variance, so there is a sweet spot in the middle, and we find it with validation data. Caveat: with lots of data, variance shrinks and you can afford more flexibility, which is why big data favours big models (Chapter 7).

6. Why is accuracy a bad metric for fraud detection?

Because fraud is rare: if 0.5% of transactions are fraudulent, a model that never flags anything is 99.5% accurate and completely useless. Accuracy weights the two classes by their frequency, so it is dominated by the easy majority. For rare positives you look at precision (are our alarms real?), recall (are we catching the fraud?), the precision–recall curve, and the confusion matrix at a chosen threshold. Caveat: even F1 can hide business cost; the right metric weighs FP cost (investigator time) against FN cost (loss) explicitly (Chapter 6, 13).

7. What does a decision tree do, and why is a single tree rarely the final model?

A tree repeatedly picks the feature and threshold that best separates the target (by Gini, entropy or MSE) and splits the data, until the leaves are pure or small; predictions are the leaf's majority class or mean. A single deep tree has very high variance: small changes in data give a different tree, and it memorizes noise. Ensembles of trees (random forests, gradient boosting) average out that variance and are far more accurate. Caveat: a shallow single tree is still the right final model when the rules must be readable by humans (Chapter 9, 10).

8. What is a feature, and why does feature engineering matter so much?

A feature is one input column the model sees. Models can only find patterns in the representation you give them, so turning raw columns into informative ones (ratios, time since last event, aggregations per customer, text length, encoded categories) often improves results more than any algorithm change. Good features encode domain knowledge the model would otherwise have to learn from scratch with much more data. Caveat: every engineered feature is a leakage opportunity; check it is computable at prediction time (Chapter 8).

9. Why must you scale features for kNN and logistic regression but not for random forests?

kNN uses distances and logistic regression (with regularization) penalizes weights; both change their answer if one feature is measured in cents and another in kilometres, because the large-scale feature dominates the distance or is under-penalized. Trees only ask "is x greater than t?", which is invariant to any monotone rescaling, so scaling is a no-op for forests and boosting. Caveat: scale inside a pipeline, fitted on training data only, or you leak (Chapter 8, 11).

10. What is a baseline and why build one first?

A baseline is the simplest predictor available: the mean, the majority class, the last observed value, or the rule the business uses today. It tells you how hard the problem is and what "better" means; a model that beats it by 1% may not be worth deploying, while one that beats it by 30% is clearly valuable. It also catches bugs: if a fancy model cannot beat the majority class, something is wrong with the data or the split. Caveat: the baseline must use the same validation scheme as the model, or the comparison is meaningless (Chapter 1, 23).

Intermediate (11–25)

11. What is data leakage? Give three concrete ways it happens.

Leakage is information about the target reaching the model at training time that will not be available at prediction time, producing validation scores that collapse in production. Three common routes: fitting a scaler, imputer or target encoder on the full data before splitting; including features recorded after the outcome (refund issued, account closed date); and random splits when rows share an entity or a time axis, so the model sees the "future" of the same customer. Detection: suspiciously high scores, one feature dominating importance, and a score that drops when you re-split by time. Caveat: the cleanest fix is structural (pipelines, GroupKFold, TimeSeriesSplit), not vigilance (Chapter 7, 8).

12. Why use ROC-AUC, and when would you prefer PR-AUC?

ROC-AUC summarizes ranking quality across all thresholds: the probability a random positive scores above a random negative, independent of class balance and of any cut-off, which makes it a good model-selection metric. But on heavily imbalanced data the false-positive rate stays tiny even when most alarms are wrong, so ROC-AUC can look excellent while precision is poor. PR-AUC (average precision) focuses on the positive class and reflects what the analyst reviewing alarms will experience. Caveat: neither tells you performance at the threshold you will deploy; report that too (Chapter 6, 13).

13. How do you handle class imbalance?

First, choose the right metric (PR-AUC, recall at a precision floor, cost-weighted) and do not touch accuracy. Then: use class_weight="balanced" or scale_pos_weight so the loss cares about the minority; tune the decision threshold on validation data instead of using 0.5; and only if those are insufficient try resampling (undersample the majority, or SMOTE the minority, applied inside the CV folds). Collecting more positives beats all of these. Caveat: resampling changes the calibration of probabilities, so recalibrate if you need probabilities (Chapter 13).

14. Random forest vs gradient boosting: how do they differ and when would you pick each?

A random forest trains many deep trees independently on bootstrap samples with random feature subsets and averages them; it reduces variance and is hard to overfit badly, with almost no tuning. Gradient boosting trains shallow trees sequentially, each fitting the residual errors of the ensemble so far, scaled by a learning rate; it reduces bias too and usually wins on tabular data but needs early stopping and some tuning. Pick a forest for a quick robust model or when nobody will tune it; pick boosting (LightGBM/XGBoost/CatBoost) when you want the best score and can run early stopping. Caveat: on tiny or extremely noisy data the forest often ties or wins (Chapter 10).

15. What would you tune in XGBoost, in what order?

Fix a moderate learning rate (0.05) and let early stopping on a validation set pick the number of rounds. Then tune tree structure: max_depth (3–10) and min_child_weight, which control how complex each tree's interactions can be. Then the sampling regularizers subsample and colsample_bytree (0.5–1.0), then reg_lambda/gamma. Finally lower the learning rate (0.01–0.03) and re-fit with early stopping for a last small gain. Caveat: gains after the first two steps are small; spend the time on features instead (Chapter 10, 13).

16. Explain k-fold cross-validation and when a plain k-fold is the wrong choice.

Split the data into k folds, train on k−1 and validate on the remaining one, rotate k times, and report the mean and standard deviation of the score; every row is validated exactly once and the estimate is less noisy than one split. It is wrong for time series (validation must be later than training: TimeSeriesSplit), for data with repeated entities (all of a customer's rows must share a fold: GroupKFold), and for imbalanced classification without stratification. Nested CV is needed when you tune hyperparameters and want an unbiased estimate. Caveat: k-fold with preprocessing outside the pipeline leaks in every fold (Chapter 7, 13).

17. What is regularization and how do L1 and L2 differ in effect?

Regularization adds a penalty on model complexity to the loss so the model prefers simpler solutions and generalizes better. L2 (Ridge) penalizes squared weights and shrinks all of them smoothly, which stabilizes correlated features. L1 (Lasso) penalizes absolute weights and drives some exactly to zero, performing feature selection. ElasticNet mixes both. In trees the analogues are depth limits, minimum leaf size and pruning; in nets, weight decay and dropout. Caveat: the penalty strength is scale-dependent, so standardize first (Chapter 5, 7).

18. How do you choose the number of clusters in k-means, and what does k-means assume?

Plot inertia against k and look for the elbow, compute the silhouette score for each k, and, most importantly, check whether the segments are distinct and actionable for the business. k-means assumes roughly spherical, similar-sized clusters in a scaled Euclidean space and always finds exactly k clusters even if none exist. For irregular shapes or unknown k use DBSCAN or hierarchical clustering. Caveat: with many features, reduce with PCA first or distances become meaningless (Chapter 12).

19. What is PCA doing, mathematically and intuitively?

PCA finds orthogonal directions (principal components) in feature space ordered by how much variance the data has along them; they are the eigenvectors of the covariance matrix. Projecting onto the first few keeps most of the variance in fewer dimensions, which removes redundancy among correlated features, speeds up models and enables 2-D plots. Intuitively it rotates the cloud of points to line up with its longest axes and drops the thin ones. Caveat: it is unsupervised, so a low-variance direction can still be the one that predicts the target; and it needs standardized inputs (Chapter 12).

20. How would you validate a demand-forecasting model?

With time-ordered splits: train on the past, validate on the following window, roll forward (expanding or sliding window), and report error per forecast horizon. Compare against a seasonal-naive baseline (same day last week/year) with MAE or MASE, because many forecasting models fail to beat it. Check residuals for remaining seasonality and check performance on the periods that matter (holidays, promotions). Caveat: never shuffle, never let lag features look past the cut-off, and remember that features unknown at forecast time (actual weather) must be replaced by forecasts of them (Chapter 14).

21. Explain what a Pipeline is in scikit-learn and why you insist on it.

A Pipeline chains transformers (imputer, scaler, encoder) and one final estimator into a single object with fit and predict. Calling fit learns every step's statistics from the training rows only and calling predict replays them, so preprocessing can never see validation or test data, and cross-validation and grid search refit the whole chain per fold. It also guarantees that the exact same preprocessing runs in production because the pipeline is what you persist. Caveat: pipelines make target encoding and feature selection safe only if those steps are inside them too (Chapter 8).

22. When would you use logistic regression over gradient boosting even though boosting scores higher?

When explanations are legally or operationally required per decision (credit, hiring, medical), when there are few rows so variance dominates, when the deployment target cannot run a tree library, or when the score difference is within the CV standard deviation. A logistic model with well-engineered features is also easier to monitor: coefficient drift is visible. Caveat: "explainable" is not automatic for logistic regression either; with hundreds of correlated features the coefficients stop meaning what people think (Chapter 6, 20).

23. What is the difference between a parameter and a hyperparameter, and how do you choose hyperparameters?

Parameters are learned from data during fit (coefficients, split thresholds, network weights); hyperparameters are chosen before fit and shape how learning happens (depth, learning rate, C, number of neighbours). You choose them by searching on cross-validated scores: random search with a sensible budget, then a narrow grid around the best, with early stopping for iterative models. The test set is never used for this. Caveat: if the best hyperparameters are at the edge of your search range, extend the range (Chapter 13).

24. How do you explain a black-box model's prediction to a customer or auditor?

With SHAP values: for each prediction, they attribute the difference from the average prediction to each feature, with contributions that sum exactly to the output, so "your score is high mainly because of X (+0.3) and Y (+0.2), partly offset by Z (−0.1)". Globally, mean absolute SHAP gives feature importance and dependence plots show the shape of each effect. For trees, TreeSHAP is exact and fast; for other models KernelSHAP or permutation importance work but are slower and approximate. Caveat: SHAP explains the model, not the world; a feature can be important because it proxies something else (Chapter 20).

25. What is the curse of dimensionality and which models suffer most?

As the number of features grows, the volume of the space grows exponentially, data becomes sparse, and all points become roughly equidistant, so "nearest" stops meaning "similar". Distance-based methods (kNN, k-means, RBF SVMs) and density estimators degrade first; trees and regularized linear models cope better because they select features implicitly or explicitly. Remedies: feature selection, regularization, PCA/embeddings, or more data. Caveat: text and images have millions of dimensions and still work because the data lies on a much lower-dimensional manifold, which is what deep nets exploit (Chapter 11, 12).

Advanced (26–40)

26. Explain scaled dot-product attention. Why divide by √dk, and why multiple heads?

Each token produces a query, a key and a value vector; the attention weights are softmax(QKᵀ/√dk), and the output is the weighted sum of values, so every token gathers information from the tokens it "attends to" based on content. The √dk keeps the dot products from growing with dimension, which would saturate the softmax and kill gradients. Multiple heads run this in parallel with different projections so one head can track syntax while another tracks coreference, and their outputs are concatenated. Caveat: attention is quadratic in sequence length, which is why context length is expensive and why efficient-attention variants exist (Chapter 18).

27. Why did ReLU replace sigmoid as the default activation?

Sigmoid saturates: for large |z| its derivative is near zero, so gradients vanish as they pass back through many layers and deep networks stop learning. ReLU, max(0, z), has derivative 1 for positive inputs, so gradients flow unchanged, it is trivially cheap, and it produces sparse activations. Its "dead unit" problem (always-negative inputs give zero gradient) is mild and handled by variants like Leaky ReLU or GELU. Caveat: sigmoid is still correct at the output of a binary classifier and inside gates; the replacement is for hidden layers (Chapter 15, 16).

28. Your deep network's training loss is NaN after a few steps. What do you check?

Learning rate first: too high a rate makes the loss diverge, so lower it by 10× or add warm-up. Then input scale (unstandardized features or un-normalized pixels), a log of zero in a custom loss (clip probabilities), exploding gradients (add clipping, check norms), and label errors like an index outside the number of classes. Batch normalization or a lower-variance initialization also helps. Caveat: if the loss is NaN from step one, it is almost always the data or the loss function, not the optimizer (Chapter 16).

29. RAG vs fine-tuning an LLM: how do you decide?

Retrieval-augmented generation puts relevant documents into the prompt at query time; it is the right tool when the answer depends on knowledge that changes, is private, or must be cited, and it needs no training. Fine-tuning changes the model's weights; it is the tool for changing style, format, or teaching a skill the base model lacks, and it does not reliably inject facts. The usual order is prompt engineering → RAG → fine-tuning, escalating only when the previous step's evaluation fails. Caveat: RAG quality is dominated by retrieval quality (chunking, embeddings, re-ranking), so evaluate retrieval separately from generation (Chapter 19).

30. How would you monitor a model in production, and when would you retrain?

Three layers: system health (latency, error rate, feature nulls), input drift (PSI or KS tests per feature against the training distribution, and prediction-distribution drift), and, when labels arrive, performance (the same metric as validation, sliced by segment). Alert on drift and on a metric drop beyond the CV standard deviation. Retrain on a fixed cadence tied to how fast the world changes, and additionally when drift or performance triggers fire, always re-validating against the current model before promotion. Caveat: label delay means performance monitoring lags, so drift is your early warning, not a nuisance (Chapter 21).

31. What is train/serve skew and how do you prevent it structurally?

It is any difference between how features are computed in training and in production: a different SQL query, a different default for missing values, a timezone bug, or a category renamed upstream. The structural fix is to have one implementation of the feature code used by both paths (a pickled pipeline, a shared feature library, or a feature store), to log production inputs and periodically replay them through the offline model to compare predictions, and to add schema checks at the API boundary. Caveat: even with one code path, upstream data changes will drift; that is what monitoring is for (Chapter 21).

32. Why can correlation-based models not answer "what if we change X?", and what can?

A predictive model learns P(y | x) as it occurs in the data, where x may be correlated with the outcome through confounders; changing x in the world does not change those confounders, so the model's counterfactual is wrong (customers who get discounts churn less because we give discounts to loyal customers). Causal answers need either a randomized experiment (A/B test, the gold standard), or observational methods with explicit assumptions: adjustment for measured confounders, difference-in-differences, instrumental variables, or uplift models trained on experimental data. Caveat: SHAP importance is not causal importance (Chapter 22).

33. Explain the Q-learning update and the exploration–exploitation trade-off.

Q(s, a) estimates the long-run reward of taking action a in state s; after each step the estimate is nudged toward the observed reward plus the discounted value of the best next action: Q ← Q + α[r + γ max Q(s′, ·) − Q]. Because the target uses the current estimate of the next state, it bootstraps and converges under enough exploration. Exploration (trying non-greedy actions, e.g. ε-greedy) is required or the agent never discovers better actions; exploitation is required to collect reward. Caveat: in business settings RL is usually a bandit problem with immediate reward, which is far easier and safer than full RL (Chapter 22).

34. What is calibration, why does it matter, and how do you fix it?

A model is calibrated if, among predictions of 0.7, about 70% are positive. It matters whenever the probability itself drives a decision: expected-value pricing, risk triage, or combining scores across models. Boosted trees, SVMs and neural nets are often mis-calibrated (over-confident); check with a reliability diagram and the Brier score, and fix with Platt scaling (logistic on the scores) or isotonic regression fitted on a held-out fold (CalibratedClassifierCV). Caveat: resampling for imbalance destroys calibration, so calibrate after (Chapter 13).

35. How does transfer learning work for images, and when does it fail?

A CNN pretrained on a large dataset has learned general visual features (edges, textures, parts) in its early and middle layers; you keep those, replace the final classifier, and either train only the new head or fine-tune the whole network with a small learning rate. This lets a few hundred labelled images reach accuracy that would otherwise need hundreds of thousands. It fails when the domain is far from natural images (radiology, spectrograms, satellite bands) and the low-level statistics differ, or when the pretraining data leaks your test set. Caveat: augmentation and a proper validation split matter more than the choice of backbone (Chapter 17).

36. What are embeddings, and how would you use them for a recommender?

An embedding is a learned dense vector for a discrete item such that similar items are close; it turns categorical identity into geometry. For a recommender, matrix factorization learns a user vector and an item vector whose dot product predicts the rating or interaction; nearest neighbours in item space give "similar items", and a user's vector ranks all items. Modern systems feed those embeddings, plus context, into a two-tower or boosted model. Caveat: cold-start users and items have no interactions and need content features or popularity fallbacks (Chapter 19, 22).

37. A model has AUC 0.99 on cross-validation on a hard business problem. What do you do?

Distrust it. Check for leakage first: look at feature importances for a single dominant feature, inspect when each feature is populated relative to the label, re-split by time and by entity group, and remove any feature derived after the outcome. Check for duplicates across folds and for the label being derivable from the features by a rule. If it survives all of that, confirm on a genuinely future holdout before anyone announces it. Caveat: the number that matters is production performance on labels collected after deployment (Chapter 7, 23).

38. Explain how gradient boosting relates to gradient descent.

Gradient descent updates parameters by stepping against the gradient of the loss; gradient boosting updates the function by adding a new tree fitted to the negative gradient of the loss with respect to the current predictions, scaled by a learning rate. For squared error the negative gradient is the residual, so each tree fits what is left unexplained; for log-loss it is y − p. This is why boosting handles any differentiable loss (quantile, Poisson, ranking) and why the learning rate and number of rounds trade off exactly like step size and iterations. Caveat: second-order methods (XGBoost uses Hessians) and regularization terms are what make it work well in practice (Chapter 10).

39. How do you decide whether a 0.5-point AUC improvement is real?

Compare the two models on the same folds and look at the per-fold differences, not just the means; if the improvement is smaller than the standard deviation across folds it is noise. Repeated cross-validation, a paired test over folds, or bootstrap confidence intervals on the test set give a more formal answer. Also ask whether 0.5 points changes any decision at the operating threshold: convert to precision/recall at the deployed cut-off, or to money. Caveat: many tiny "improvements" chosen by repeated peeking at validation scores are just selection bias (Chapter 13).

40. Walk me through how you would run an ML project from request to production.

Define the decision, the target, the metric, the baseline and the success threshold in one page, and confirm someone will act on the prediction. Get the data, audit the labels, explore and clean, and build a leak-free cross-validated baseline within the first days. Iterate on features and models with a fixed validation scheme, log every experiment, and stop when improvement flattens. Evaluate on a time-ordered holdout, run error analysis by segment, explain with SHAP, and review with stakeholders. Ship the persisted pipeline behind an API with schema checks, monitor drift and performance, and set a retraining plan. Caveat: the most common failure is skipping the first step (Chapter 23).

1. A colleague's churn model has ROC-AUC 0.97 on 5-fold CV. One feature, "days_since_cancellation_request", carries 85% of the importance. What is the most likely explanation?

A cancellation request happens after the customer has decided to leave; it is a post-outcome field. Suspiciously high scores plus one dominant feature is the signature of leakage (§2 checklist, Chapter 8).

2. You have 600 rows of tabular data and the regulator must be able to see how each prediction was made. Which first model does Figure 24.3 send you to?

Under 1,000 rows and full explainability both point to the linear branch: scale, regularize, read the coefficients. Boosting would be the contender if the constraint were lifted (Chapter 5, 6, 9).

3. Which metric should you report for a rare-event classifier (0.8% positives) that will send alerts to a small team of analysts?

With rare positives the precision–recall view reflects the analysts' experience (how many alerts are real, how many events are caught). Accuracy is dominated by the 99.2% negatives (Chapter 6, 13).

4. Training accuracy 0.99, cross-validated accuracy 0.71, small standard deviation across folds. Which branch of the debugging flowchart are you on, and what is a correct fix?

Train high, validation much lower, stable across folds: a classic variance problem. Constrain the model (blue arrows in Figure 24.6) or get more data (Chapter 7, 13).

5. In the scaled dot-product attention formula, what is the role of the softmax?

Attention(Q, K, V) = softmax(QKᵀ/√dk)V: the softmax makes each row of scores a probability distribution over positions, and the output is that weighted average of V (Chapter 18).

6. You tune an XGBoost model. Which knob, when increased, makes the model less prone to overfitting?

min_child_weight raises the minimum amount of data a leaf must hold, which prunes tiny noise-fitting leaves. Depth, more rounds and a larger learning rate all add flexibility (Figure 24.6, Chapter 10, 13).
