1. The ML landscape map

Everything in this book hangs off one tree. At the root: learn a function from data. The first split is by the kind of feedback in the data (Chapter 1): labels give you supervised learning, no labels give you unsupervised learning, and rewards give you reinforcement learning. Deep learning is not a fourth family but a family of models (stacked differentiable layers) that can be used in any of the three; we draw it as its own column because its tooling, failure modes and vocabulary are different enough to deserve one. Along the bottom run the cross-cutting skills that every project needs regardless of branch.

Key idea

The map is not a ranking. Boosted trees win on most business tables (Chapter 10); deep learning wins when the input is an image, text, audio or a truly huge dataset (Chapters 17–19); unsupervised methods win when there is no label yet (Chapter 12). The columns are separated by what the data gives you, not by how sophisticated the method is.

2. The workflow at a glance & leakage checklist

Chapter 1 introduced the seven-step loop and Chapter 23 ran it end to end. Here it is compressed to the one question you must answer at each step and the tool you will reach for. If you can answer all seven questions for a project, you understand the project; if one is blank, that is where it will fail.

Common mistake — the leakage checklist (Chapters 7, 8, 13, 23)

Leakage is the single most common reason a model looks great in the notebook and useless in production. Before you trust any score, tick every box:

  • Time: every feature is computable from information available at the moment the prediction would be made. No "days until cancellation", no post-outcome fields (refund issued, ticket closed).
  • Split first: scalers, imputers, encoders, feature selectors and target encoders are fitted on the training fold only — i.e. they sit inside the Pipeline that cross-validation refits.
  • Groups: rows from the same customer / patient / device are all in the same fold (GroupKFold), so the model can't memorize an entity.
  • Time series: validation folds are strictly later than training folds (TimeSeriesSplit); no random shuffling of a time axis.
  • Duplicates: near-identical rows (re-exports, retries) are deduplicated before splitting, or they straddle the split and inflate the score.
  • Target proxies: no feature is a renamed or aggregated version of the target (e.g. "customer risk tier" set by the same fraud team whose decisions are the label).
  • Suspiciously good: an AUC above 0.95 on a hard business problem, or one feature with 80% of the importance, is a leak until proven otherwise.
  • Train/serve parity: the production feature code is the same code (ideally the same pickled pipeline) as the training feature code.

At work

Two rules cover 90% of model choice on tabular data. Rule 1: start with a regularized linear model as a baseline and a gradient-boosted tree model as the contender; if boosting beats linear by a lot, the relationship is non-linear and you keep boosting. Rule 2: if you have fewer than a thousand rows, or you must explain each prediction to a regulator, the linear model (or a shallow tree) is probably the final answer. Everything else in this table is for specific situations: kNN and SVM for small, clean, low-dimensional problems; Naive Bayes for bag-of-words text; deep nets for images, text and sequences.

Explain it like I'm 9

A smoke detector that never beeps is "99.9% accurate" because there is almost never a fire. That is why accuracy is a bad report card for rare things. Instead we ask two questions: when it beeps, was there really a fire (precision)? And when there was a fire, did it beep (recall)? The metric table is just a list of which report card to use for which kind of test.

5. Formula sheet

Every formula the book used, one line of meaning each, grouped by theme. The symbols are the book's standard ones: x is an input vector, y a true target, ŷ a prediction, w weights, n the number of examples, p a predicted probability. If a formula does not make sense in one reading, the chapter reference is where the slow explanation lives.

Regression & linear models

The math
ŷ = w0 + w1x1 + … + wdxd = wTx + b

Linear model (Ch 5). A weighted sum of the features plus an intercept; each wj is "change in ŷ per unit of xj, holding the rest fixed".

MSE = (1/n) ∑ (yi − ŷi)²    RMSE = √MSE    MAE = (1/n) ∑ |yi − ŷi|

Regression errors (Ch 5). MSE squares the misses (big ones dominate, and it is differentiable); RMSE is MSE back in the units of y; MAE is the typical absolute miss and is robust to outliers.

R² = 1 − ∑ (yi − ŷi)² / ∑ (yi − ȳ)²

Coefficient of determination (Ch 5). Fraction of the target's variance the model explains; 0 = no better than predicting the mean, 1 = perfect, negative = worse than the mean (possible on test data).

L1 (Lasso): loss + λ ∑ |wj|     L2 (Ridge): loss + λ ∑ wj²

Regularization penalties (Ch 5, 7). Both shrink weights toward zero to reduce variance; L1 drives some weights to exactly zero (feature selection), L2 shrinks all of them smoothly. In scikit-learn λ is alpha for Ridge/Lasso and 1/C for logistic regression and SVM.

Bias–variance: E[(y − ŷ)²] = Bias(ŷ)² + Var(ŷ) + σ²noise

Bias–variance decomposition (Ch 7). Expected squared error = systematic error from a too-simple model + sensitivity to which training set you happened to get + irreducible noise; more flexibility lowers bias and raises variance.

Classification & probability

The math
σ(z) = 1 / (1 + e−z),   z = wTx + b,   p = σ(z)

Sigmoid / logistic regression (Ch 6). Squashes any real number into (0, 1) so a linear score becomes a probability; z is the log-odds, so each unit of xj multiplies the odds by ewj.

Log-loss = −(1/n) ∑ [ yi log pi + (1 − yi) log(1 − pi) ]

Binary cross-entropy (Ch 6). Penalizes confident wrong probabilities without bound (p → 0 for a positive costs → ∞); minimizing it is maximum-likelihood fitting.

softmax(z)k = ezk / ∑j ezj     CE = −∑k yk log pk

Softmax and cross-entropy (Ch 6, 15). Softmax turns K scores into K probabilities that sum to 1; cross-entropy is −log of the probability given to the true class (one-hot y picks it out).

Precision = TP/(TP+FP)   Recall = TP/(TP+FN)   F1 = 2·P·R/(P+R)   Fβ = (1+β²)·P·R / (β²P + R)

Threshold metrics (Ch 6). Precision = purity of the alarms, recall = coverage of the real positives, F1 = their harmonic mean; Fβ with β = 2 weights recall more (fraud, cancer screening), β = 0.5 weights precision more.

AUC = P( score(random positive) > score(random negative) )

ROC-AUC meaning (Ch 6). The area under the ROC curve equals the probability that the model ranks a random positive above a random negative; 0.5 is coin-flipping, 1.0 is perfect ranking, and it does not depend on the threshold or on class balance.

MCC = (TP·TN − FP·FN) / √[(TP+FP)(TP+FN)(TN+FP)(TN+FN)]

Matthews correlation coefficient (Ch 6, 13). Correlation between predicted and actual labels, from −1 to +1; unlike F1 it uses all four cells, so it stays honest on imbalanced data.

P(A | B) = P(B | A) · P(A) / P(B)

Bayes' theorem (Ch 3, 11). Posterior = likelihood × prior / evidence; Naive Bayes multiplies per-feature likelihoods as if features were independent given the class.

Trees

The math
Gini(S) = 1 − ∑k pk²     H(S) = −∑k pk log2 pk

Gini impurity and entropy (Ch 9). Both measure how mixed the classes are in a node (0 = pure); Gini is the probability two random draws disagree, entropy is the bits needed to encode the class.

IG(S, split) = H(S) − ∑children c (|Sc| / |S|) · H(Sc)

Information gain (Ch 9). Impurity of the parent minus the size-weighted impurity of the children; the tree greedily picks the feature and threshold with the largest gain. For regression, impurity is the node's MSE.

Optimization

The math
w ← w − η · ∇w L(w)

Gradient descent (Ch 5, 15). Step downhill on the loss surface in the direction of steepest descent; η is the learning rate, and mini-batch/stochastic versions estimate ∇L from a batch.

v ← β v + ∇L;   w ← w − η v

Momentum (Ch 16). Keep a running average of past gradients (β ≈ 0.9) so steps accelerate along consistent directions and damp out oscillations.

m ← β1m + (1−β1)g;   v ← β2v + (1−β2)g²;   w ← w − η · m̂ / (√v̂ + ε)

Adam (Ch 16). Momentum on the gradient (m) plus a per-parameter running scale (v) so every weight gets its own effective learning rate; the hats are bias corrections for the first steps. Defaults β1 = 0.9, β2 = 0.999, η = 10⁻³ work surprisingly often.

Similarity, attention, explanation & the rest

The math
cos(a, b) = a·b / (‖a‖ ‖b‖)

Cosine similarity (Ch 12, 19). The cosine of the angle between two vectors, ignoring their length; 1 = same direction, 0 = unrelated, −1 = opposite. The standard measure for embeddings.

Attention(Q, K, V) = softmax( Q KT / √dk ) V

Scaled dot-product attention (Ch 18). Each query scores every key by dot product, the scores become weights through softmax (divided by √dk to keep them well-scaled), and the output is the weighted average of the values — a learned, content-based lookup.

φi = ∑S ⊆ F∖{i} [ |S|! (|F| − |S| − 1)! / |F|! ] · [ f(S ∪ {i}) − f(S) ]

Shapley value (Ch 20). Feature i's contribution is its average marginal effect on the prediction over every possible order in which features could be added; SHAP values sum exactly to prediction minus the average prediction.

PSI = ∑bins (pnow − pref) · ln( pnow / pref )

Population stability index (Ch 21). Drift between a reference distribution and today's, computed over bins; rule of thumb < 0.1 stable, 0.1–0.25 watch, > 0.25 investigate or retrain.

Q(s, a) ← Q(s, a) + α [ r + γ maxa' Q(s', a') − Q(s, a) ]

Q-learning update (Ch 22). Nudge the value of taking action a in state s toward the reward received plus the discounted best value of the next state; α is the learning rate, γ the discount factor.

ARIMA(p, d, q):   y't = c + ∑i=1..p φi y't−i + ∑j=1..q θj εt−j + εt,   y' = series differenced d times

ARIMA notation (Ch 14). p past values (autoregressive), d rounds of differencing to make the series stationary, q past forecast errors (moving average); seasonal SARIMA adds (P, D, Q)m at the seasonal lag m.

z = (x − μ) / σ

z-score / standardization (Ch 3, 8). Express a value as "how many standard deviations from the mean"; what StandardScaler does, and the basis of a first-pass outlier rule (|z| > 3).
