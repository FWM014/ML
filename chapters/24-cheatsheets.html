1. The ML landscape map

Everything in this book hangs off one tree. At the root: learn a function from data. The first split is by the kind of feedback in the data (Chapter 1): labels give you supervised learning, no labels give you unsupervised learning, and rewards give you reinforcement learning. Deep learning is not a fourth family but a family of models (stacked differentiable layers) that can be used in any of the three; we draw it as its own column because its tooling, failure modes and vocabulary are different enough to deserve one. Along the bottom run the cross-cutting skills that every project needs regardless of branch.

Key idea

The map is not a ranking. Boosted trees win on most business tables (Chapter 10); deep learning wins when the input is an image, text, audio or a truly huge dataset (Chapters 17–19); unsupervised methods win when there is no label yet (Chapter 12). The columns are separated by what the data gives you, not by how sophisticated the method is.

Common mistake — the leakage checklist (Chapters 7, 8, 13, 23)

Leakage is the single most common reason a model looks great in the notebook and useless in production. Before you trust any score, tick every box:

  • Time: every feature is computable from information available at the moment the prediction would be made. No "days until cancellation", no post-outcome fields (refund issued, ticket closed).
  • Split first: scalers, imputers, encoders, feature selectors and target encoders are fitted on the training fold only — i.e. they sit inside the Pipeline that cross-validation refits.
  • Groups: rows from the same customer / patient / device are all in the same fold (GroupKFold), so the model can't memorize an entity.
  • Time series: validation folds are strictly later than training folds (TimeSeriesSplit); no random shuffling of a time axis.
  • Duplicates: near-identical rows (re-exports, retries) are deduplicated before splitting, or they straddle the split and inflate the score.
  • Target proxies: no feature is a renamed or aggregated version of the target (e.g. "customer risk tier" set by the same fraud team whose decisions are the label).
  • Suspiciously good: an AUC above 0.95 on a hard business problem, or one feature with 80% of the importance, is a leak until proven otherwise.
  • Train/serve parity: the production feature code is the same code (ideally the same pickled pipeline) as the training feature code.
