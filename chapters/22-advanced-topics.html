1. Recommender systems: the user × item matrix

Every recommender starts from the same object: a matrix with one row per user, one column per item, and a cell that says how the user felt about the item. Sometimes the cell is a star rating (explicit feedback); far more often it is a click, a purchase, a watch-time, a skip (implicit feedback). The defining feature of this matrix is that it is almost entirely empty. A streaming service with 10 million users and 20,000 titles has 2 × 1011 cells; a typical user has touched a few hundred. Sparsity above 99% is normal.

Explain it like I'm 9

You have not read the new comic. Your friend Eli has, and Eli likes almost all the same comics you like. So you ask Eli. That's collaborative filtering: "people like me liked this." The other way is to look at the comic itself: it's a space adventure with robots, and you like space adventures with robots. That's content-based: "things like what I liked." The best systems do both.

Content-based vs collaborative vs hybrid

Content-based filtering describes items by their attributes (genre, price, text embedding, ingredients) and recommends items whose attributes match what the user liked before. It needs no other users, works from day one for a new item, and explains itself ("because you watched…"). Its weakness is that it can only recommend more of the same. Collaborative filtering (CF) ignores item attributes entirely and uses only the pattern of who-liked-what. It discovers surprising connections (people who buy camping gear also buy this specific book) but needs interaction history, so it is helpless for a brand-new user or item. Hybrid systems, which is nearly every production system, use content features to bootstrap and CF to refine.

Neighbourhood collaborative filtering

The simplest CF looks for neighbours. User-based: find the k users whose rating vectors are most similar to mine and average their ratings of the target item. Item-based: find the k items most similar to the target item (similar meaning "rated similarly by the same people") and average my ratings of those. Item-based won in practice (Amazon popularized it in the early 2000s) because item-item similarities are stable and can be precomputed offline: a product's neighbours change slowly, while a user's taste vector changes with every click.

The math (optional)

Cosine similarity between two rating vectors a and b over the cells both have filled:

sim(a, b) = (a · b) / (‖a‖ · ‖b‖) = ∑u au bu / ( √∑u au2 · √∑u bu2 )

au and bu are the ratings user u gave to items a and b; the sums run only over users who rated both. The prediction for user u on item i is a similarity-weighted average of u's ratings on the k nearest items:

r̂ui = r̄u + ∑j∈Nk(i) sim(i, j) · (ruj − r̄u) / ∑j∈Nk(i) sim(i, j)

r̄u is the user's average rating (subtracting it is the "adjusted cosine" trick: a 4 from a harsh grader is praise), and Nk(i) is the set of the k most similar items the user has rated.

Here is the whole thing on the six-user matrix from Figure 22.1. Notice the two engineering details that separate a toy from something usable: similarity is computed only on co-rated cells, and ratings are centred per user before comparing.

# A tiny explicit-ratings matrix (0 = not rated) and an item-item recommender
import numpy as np
users = ["Ana", "Ben", "Cy", "Dee", "Eli", "Fay"]
items = ["Dune", "Heat", "Up", "Alien", "Coco"]
R = np.array([[5, 4, 0, 5, 1],
              [4, 0, 1, 4, 0],
              [1, 1, 5, 0, 4],
              [0, 1, 4, 1, 5],
              [5, 5, 0, 4, 0],
              [0, 2, 5, 1, 0]], dtype=float)
mask = R > 0
print("sparsity:", f"{(~mask).mean():.0%} of cells are empty")

# adjusted cosine: subtract each user's mean first, so a "4 from a tough grader" counts as praise
user_mean = np.nanmean(np.where(mask, R, np.nan), axis=1, keepdims=True)
C = np.where(mask, R - user_mean, 0.0)              # centered ratings, holes → 0

def sim(i, j):
    co = mask[:, i] & mask[:, j]                     # users who rated BOTH items
    if co.sum() < 2:
        return 0.0
    a, b = C[co, i], C[co, j]
    return float(a @ b / (np.linalg.norm(a) * np.linalg.norm(b) + 1e-9))

S = np.array([[sim(i, j) for j in range(5)] for i in range(5)])
np.set_printoptions(precision=2, suppress=True)
print("item-item similarity (adjusted cosine):\n", S)

def predict(u, i, k=2):
    """user mean + weighted average of the user's deviations on the k most similar items she rated."""
    rated = np.where(mask[u])[0]
    nbrs = rated[S[i, rated] > 0]                    # only positively similar neighbours
    nbrs = nbrs[np.argsort(-S[i, nbrs])[:k]]
    if len(nbrs) == 0:
        return float(user_mean[u, 0])                # nothing to go on → fall back to her average
    w = S[i, nbrs]
    return float(user_mean[u, 0] + (w @ C[u, nbrs]) / w.sum())

for u, i in [(0, 2), (1, 1), (4, 2), (5, 4)]:
    print(f"{users[u]} → {items[i]:<6} predicted {predict(u, i):.2f}")
# sparsity: 30% of cells are empty
# item-item similarity (adjusted cosine):
#  [[ 1.    0.89 -0.98  0.83 -0.87]
#  [ 0.89  1.   -0.86  0.79 -0.73]
#  [-0.98 -0.86  1.   -0.93  0.85]
#  [ 0.83  0.79 -0.93  1.   -0.97]
#  [-0.87 -0.73  0.85 -0.97  1.  ]]
# Ana → Up     predicted 1.00
# Ben → Heat   predicted 4.00
# Eli → Up     predicted 4.67
# Fay → Coco   predicted 5.00

The similarity matrix has the structure you would draw by hand: Dune, Heat and Alien form one block, Up and Coco another, and the blocks are strongly anti-correlated. Ana, who loved the first block, gets a predicted 1.0 for Up. Eli's case shows a real limitation: Eli rated only block-one films, none of which is positively similar to Up, so the model has nothing to go on and falls back to his mean. Raw cosine on positive ratings would have hidden this (every similarity comes out near 0.9 when all ratings are between 1 and 5), which is why centring matters.

Common mistake

Treating an empty cell as a zero rating. In explicit-feedback data a blank means "unknown", and filling it with 0 makes the model believe every user hates 99% of the catalogue. In implicit-feedback data a blank is weak evidence of disinterest (they could have clicked and did not), and the standard fix is to weight known positives by a confidence that grows with interaction count rather than to treat blanks as hard negatives. Know which regime you are in before writing a single line.

2. Matrix factorization, cold start and evaluation

Neighbourhood methods do not scale gracefully (an item-item matrix for a million items has 1012 entries) and they cannot generalize beyond direct co-ratings. Matrix factorization (MF) fixes both by assuming the rating matrix has low rank: every user is a short vector of tastes, every item is a short vector of traits, and a rating is just their dot product.

The math (optional)

Learn user vectors uu ∈ ℝk and item vectors vi ∈ ℝk by minimizing the squared error on the observed cells Ω, with a penalty that keeps the vectors small:

minU,V ∑(u,i)∈Ω ( rui − μ − bu − bi − uu·vi )2 + λ ( ‖uu‖2 + ‖vi‖2 + bu2 + bi2 )

μ is the global mean rating, bu and bi are user and item biases (some people rate high, some films are universally loved), λ is the regularization strength that stops the factors from memorizing the sparse training cells. The sum runs only over observed cells, which is what makes this different from a plain SVD. Two ways to solve it: stochastic gradient descent one cell at a time (the "Funk SVD" of Netflix-Prize fame), or ALS (alternating least squares): fix V and solve for U (an ordinary least-squares problem per user), then fix U and solve for V, repeat. ALS parallelizes beautifully and is the standard for implicit feedback (Spark's ALS, the implicit library).

With a tiny matrix we can cheat and use a plain truncated SVD after filling the holes with the global mean; it shows the rank idea perfectly and is what the widget below animates.

# Matrix factorization with truncated SVD: R ≈ U · V^T with k latent factors
import numpy as np
R = np.array([[5,4,0,5,1],[4,0,1,4,0],[1,1,5,0,4],[0,1,4,1,5],[5,5,0,4,0],[0,2,5,1,0]], float)
mask = R > 0
mu = R[mask].mean()                       # global mean fills the holes to start
R_filled = np.where(mask, R, mu)

def factorize(M, k):
    U, s, Vt = np.linalg.svd(M, full_matrices=False)
    return (U[:, :k] * s[:k]) @ Vt[:k, :]       # rank-k reconstruction

np.set_printoptions(precision=2, suppress=True)
for k in [1, 2, 3, 5]:
    R_hat = factorize(R_filled, k)
    rmse = np.sqrt(((R_hat - R)[mask] ** 2).mean())   # error on the KNOWN cells
    print(f"rank {k}: RMSE on known ratings = {rmse:.2f}")

R_hat = factorize(R_filled, 2)
print("rank-2 predictions for the empty cells (row=user, col=item):")
print(np.where(mask, np.nan, R_hat.clip(1, 5)))
# rank 1: RMSE on known ratings = 1.54
# rank 2: RMSE on known ratings = 0.65
# rank 3: RMSE on known ratings = 0.51
# rank 5: RMSE on known ratings = 0.00
# rank-2 predictions for the empty cells (row=user, col=item):
# [[ nan  nan 2.3   nan  nan]
#  [ nan 3.52  nan  nan 1.96]
#  [ nan  nan  nan 1.62  nan]
#  [2.38  nan  nan  nan  nan]
#  [ nan  nan 3.36  nan 3.03]
#  [2.67  nan  nan  nan 3.99]]

Rank 5 reproduces the known cells exactly, which is the recommender version of overfitting: a rank equal to the number of items just memorizes the table, and its predictions for empty cells are noise. Rank 2 already captures the two-taste structure (RMSE 0.65) and its predictions are sensible: Ana is predicted 2.3 for Up, Eli 3.4 for Up (he is a generous rater) and Fay 4.0 for Coco. In real systems the rank and λ are chosen by validation on held-out ratings, exactly like any hyperparameter (Chapter 13).

Implicit feedback and the confidence trick

Ratings are rare; clicks, plays and purchases are abundant. Implicit data has no negatives: an unplayed song might be disliked or simply undiscovered. The standard approach (Hu, Koren & Volinsky, 2008) treats every cell as a binary preference pui ∈ {0, 1} and attaches a confidence cui = 1 + α·(number of interactions): unknown cells count a little, a song played 40 times counts a lot. ALS then minimizes ∑ cui(pui − uu·vi)2 over all cells. Modern systems replace the dot product with two neural "towers" (a user tower and an item tower producing embeddings whose dot product is the score, trained with sampled negatives), but the picture is identical to Figure 22.2: two vectors, one dot product.

Cold start, popularity bias and diversity

CF cannot say anything about a user with no history or an item nobody has touched: this is the cold-start problem. The fixes are unglamorous and effective: (1) fall back to popularity or to content-based similarity until enough interactions exist; (2) ask new users two or three onboarding questions; (3) build hybrid models whose item vector is partly computed from item attributes (so a new film with "sci-fi, 2026, director X" lands near its siblings on day one); (4) for new items, run a small exploration budget that shows them to a few users deliberately (the bandit idea from Section 7).

A subtler failure is popularity bias. Popular items have the most interactions, get the best-estimated vectors, are recommended more, and collect even more interactions: a feedback loop that shrinks the catalogue in effect to a few hundred blockbusters. Offline metrics reward this because the held-out clicks were themselves generated by yesterday's popularity-biased system. Production teams counter it with diversity re-ranking (penalize showing ten items from the same category), popularity-debiasing weights during training, and explicit exploration.

Evaluation: offline ranking metrics vs online reality

A recommender produces a ranked list, so classification accuracy is the wrong yardstick. The offline metrics all take a ranked list and a set of held-out "relevant" items (things the user actually consumed later) and ask how well the list put the relevant items at the top.

The math (optional)
precision@k = |top-k ∩ relevant| / k recall@k = |top-k ∩ relevant| / |relevant|
DCG@k = ∑p=1..k relp / log2(p + 1) NDCG@k = DCG@k / IDCG@k

relp is 1 if the item at position p is relevant (or its graded relevance), and the log2(p + 1) discount says a hit at position 1 is worth 1, at position 2 worth 0.63, at position 10 worth 0.29. IDCG is the DCG of the best possible ordering, so NDCG lies in [0, 1] and is comparable across users with different numbers of relevant items. MAP (mean average precision) averages precision@p over the positions p where a hit occurs, then averages across users. Hit rate@k is the fraction of users with at least one hit in their top k, the simplest of all and often the one a product manager understands best.

# Ranking metrics: precision@k, recall@k, NDCG@k for one user
import numpy as np

def precision_at_k(ranked, relevant, k):
    return len(set(ranked[:k]) & relevant) / k

def recall_at_k(ranked, relevant, k):
    return len(set(ranked[:k]) & relevant) / len(relevant)

def ndcg_at_k(ranked, relevant, k):
    gains = [1.0 if it in relevant else 0.0 for it in ranked[:k]]
    dcg = sum(g / np.log2(i + 2) for i, g in enumerate(gains))     # position 1 → log2(2)
    ideal = sum(1.0 / np.log2(i + 2) for i in range(min(len(relevant), k)))
    return dcg / ideal

ranked   = ["Coco", "Alien", "Heat", "Up", "Dune"]   # what the model shows, best first
relevant = {"Alien", "Dune"}                          # what the user actually liked (held out)
for k in (1, 3, 5):
    print(f"k={k}: P@k={precision_at_k(ranked, relevant, k):.2f} "
          f"R@k={recall_at_k(ranked, relevant, k):.2f} "
          f"NDCG@k={ndcg_at_k(ranked, relevant, k):.2f}")
# k=1: P@k=0.00 R@k=0.00 NDCG@k=0.00
# k=3: P@k=0.33 R@k=0.50 NDCG@k=0.39
# k=5: P@k=0.40 R@k=1.00 NDCG@k=0.62

Offline metrics are computed on clicks the old system caused, on items the old system chose to show. They are a filter for obviously bad models, not a measurement of value. The only measurement that counts is online: an A/B test (Section 5) of the new ranker against the old one on click-through rate, conversion, watch time, or, if you are careful, long-term retention. Expect offline gains to shrink by half or vanish online, and expect a model with a worse NDCG to sometimes win because it is more diverse.

At work

Most companies do not need Figure 22.3. If you have under a million users and a catalogue of thousands, start with item-item CF on implicit data (a few hundred lines, precomputed nightly), add a popularity fallback for cold users, and A/B test it against "most popular this week". That baseline is embarrassingly hard to beat and takes a week. Reach for two-tower models when the catalogue is large enough that item-item similarity does not fit in memory, or when you have rich content features (text, images) that a neural tower can exploit. Whatever you build, log impressions (what was shown), not only clicks; without impressions you cannot compute CTR, cannot de-bias, and cannot train the next model properly.

Key idea

Recommendation is matrix completion plus ranking. Every method, from neighbours to two-tower networks, estimates a score for a (user, item) pair from patterns of co-occurrence; the differences are in scalability, cold-start behaviour and what extra features they can absorb. Offline ranking metrics are a filter; the online A/B test is the measurement.

3. Anomaly detection: what "weird" means

An anomaly (outlier, novelty) is an observation that does not fit the pattern of the rest. That definition hides the entire difficulty: "the pattern" must be learned from data that is mostly normal but is not labeled, and "does not fit" must be turned into a number. Anomaly detection is the unsupervised cousin of classification, used whenever the rare class is too rare, too varied, or too new to have enough labels: fraud, machine failure, network intrusion, data-quality bugs, sensor faults, insider trading.

Explain it like I'm 9

Imagine a class photo. A point anomaly is the kid wearing a giant dinosaur costume: weird anywhere. A contextual anomaly is a kid in a swimsuit: fine at the pool, weird in the school photo. A collective anomaly is thirty kids all standing perfectly still with the same blank stare: each kid is normal, but all of them together is creepy. A detector has to know which kind of weird it is looking for.

The no-labels reality

Almost always you start with a pile of unlabeled data that is "mostly normal", a vague sense of what a problem looks like, and a human (fraud analyst, engineer, nurse) who will review whatever you flag. That shapes the whole design: the output is a ranked list for review, not a yes/no; the budget is how many alerts a human can check per day; and the metric is precision of the top-k at that budget, plus whatever recall you can estimate. Frame it that way in the first meeting and half of the arguments about thresholds disappear.

Statistical baselines: z-score, IQR, Mahalanobis

For a single numeric variable the classic tools are the z-score (how many standard deviations from the mean; flag |z| > 3) and the IQR rule (flag anything below Q1 − 1.5·IQR or above Q3 + 1.5·IQR). Both need a robust version in practice, because the anomalies you are hunting inflate the mean and standard deviation that define "normal": use the median and the MAD (median absolute deviation, scaled by 1.4826 to match σ for Gaussian data) instead. For several variables, distance from the centre must account for correlation: a customer spending $500 is normal, a customer with 2 logins is normal, but $500 with 2 logins may be very odd. The Mahalanobis distance does exactly this.

The math (optional)
z = (x − μ) / σ robust z = (x − median) / (1.4826 · MAD)
DM(x) = √( (x − μ)ᵀ Σ−1 (x − μ) )

μ is the mean vector, Σ the covariance matrix of the normal data, and Σ−1 rescales each direction by its spread and rotates away correlation, so DM is the z-score generalized to an ellipse. For Gaussian data with d variables, DM2 follows a χ2 distribution with d degrees of freedom, which gives a principled threshold (e.g. the 99th percentile). scikit-learn's EllipticEnvelope fits μ and Σ robustly (Minimum Covariance Determinant) so that the anomalies do not distort the ellipse they are measured against.

4. Anomaly detectors, thresholds and evaluation

Isolation Forest

Isolation Forest (Liu, Ting & Zhou, 2008) is the default choice for tabular anomaly detection and the one you should try first. It builds many random trees: pick a random feature, pick a random split value between that feature's min and max, recurse. Anomalies, being few and different, get separated into their own leaf after a handful of splits; normal points, sitting in dense regions, need many. The anomaly score is a function of the average path length across trees. It is fast (linear time), handles hundreds of features, needs no distance metric or scaling, and has one hyperparameter that matters: contamination, the expected fraction of anomalies, which only sets the threshold and does not change the ranking.

Local Outlier Factor and One-Class SVM

Local Outlier Factor (LOF) compares the density around a point to the density around its neighbours. A point in a sparse region that borders a dense cluster gets a high LOF; a point in a uniformly sparse region does not, because its neighbours are equally sparse. This "local" view catches anomalies that global methods miss when the data has clusters of very different density (Figure 22.6, left). It is a k-NN method, so it needs scaled features and does not scale to millions of rows without approximate neighbours. One-Class SVM learns a boundary that encloses most of the training data in a kernel feature space; it is elegant but sensitive to its ν and γ parameters and rarely beats Isolation Forest on real tabular data. Know it exists; reach for it only when the data is small and smooth.

Autoencoders: reconstruction error

For high-dimensional, structured inputs (images of products on a conveyor, spectrograms of a motor, sequences of API calls) the modern detector is an autoencoder (Chapter 15): a network trained to compress its input to a small bottleneck and reconstruct it. Trained on normal data only, it learns to reconstruct normal things well. A defective part, a failing bearing, an unusual request pattern reconstructs badly, and the reconstruction error is the anomaly score (Figure 22.6, right). The same idea powers time-series anomaly detection with LSTM or transformer autoencoders, and forecasting-based detection: predict the next value, flag large residuals.

Choosing the threshold (contamination)

Every detector outputs a score; the threshold is a business decision, not a statistical one. Three ways to set it: (1) budget: flag the top k per day, where k is what the reviewers can handle; (2) expected rate: if you believe ~1% of transactions are fraudulent, set contamination=0.01; (3) the score distribution: look at the histogram of scores on normal data and cut at the 99.5th percentile or at an obvious gap. Never trust the library default (contamination="auto") for anything that pages a human at night.

Evaluating without labels, and with a few

With no labels, two honest options remain. First, precision of the top-k reviewed by humans: take the 50 highest-scored items, have an expert label them, and report "31 of 50 were real problems". That is a real number a business can act on. Second, injected anomalies: synthesize plausible anomalies (a transaction with a foreign IP and a 10× amount; a sensor value stuck at a constant), mix them in, and measure how many you recover. Injected anomalies test only the failure modes you imagined, but they catch broken pipelines and give you a regression test.

With a few labels, which you will accumulate as reviewers work through the queue, evaluate as a ranking problem: PR-AUC (average precision) and precision@k, never ROC-AUC alone (Chapter 6: with 0.5% positives a ROC-AUC of 0.95 can coexist with a useless alert queue). Those labels are also the seed of a supervised model: once you have a few hundred confirmed anomalies, a gradient-boosted classifier using the unsupervised scores as features usually beats every unsupervised method.

# Three unsupervised detectors on synthetic data with injected outliers, scored with labels we normally wouldn't have
import numpy as np
from sklearn.datasets import make_blobs
from sklearn.ensemble import IsolationForest
from sklearn.neighbors import LocalOutlierFactor
from sklearn.covariance import EllipticEnvelope
from sklearn.metrics import average_precision_score

rng = np.random.default_rng(0)
X_norm, _ = make_blobs(n_samples=1000, centers=[[0, 0], [6, 5]], cluster_std=1.0, random_state=0)
X_out = rng.uniform(-6, 12, size=(30, 2))               # 3% injected anomalies, spread anywhere
X = np.vstack([X_norm, X_out])
y = np.r_[np.zeros(1000), np.ones(30)]                    # 1 = anomaly (only used for scoring)

detectors = {
    "IsolationForest": IsolationForest(contamination=0.03, random_state=0),
    "LOF":             LocalOutlierFactor(n_neighbors=20, contamination=0.03),
    "EllipticEnvelope": EllipticEnvelope(contamination=0.03, random_state=0),
}
k = 30
print(f"{'detector':<18}{'PR-AUC':>8}{'P@30':>8}")
for name, det in detectors.items():
    if name == "LOF":
        det.fit(X); score = -det.negative_outlier_factor_      # higher = more anomalous
    else:
        det.fit(X); score = -det.score_samples(X)
    top_k = np.argsort(-score)[:k]
    print(f"{name:<18}{average_precision_score(y, score):>8.2f}{y[top_k].mean():>8.2f}")
# detector            PR-AUC    P@30
# IsolationForest       0.75    0.63
# LOF                   0.86    0.83
# EllipticEnvelope      0.79    0.73

On this data LOF wins because the injected anomalies are spread uniformly and some land close to the two clusters, where only local density catches them. Change the shape of the anomalies and the ranking of methods changes, which is the honest lesson: there is no universally best detector, so keep an evaluation harness (labels, injections, top-k review) and let it choose.

Time series, fraud and feedback loops

For time series (Chapter 14) the recipe is: remove what you can explain (trend, seasonality, known events) with a forecast model, then run a detector on the residuals, with windowed features (rolling mean, rolling std, lag differences) so that collective anomalies become point anomalies in feature space. For fraud, remember that fraudsters adapt: the moment you block a pattern, they change it, so the distribution shifts by design; retrain often, keep an unsupervised detector running alongside the supervised one to catch new patterns, and treat the labels with suspicion, because you only ever label what you investigated, and you only investigate what the previous model flagged. This feedback loop quietly teaches the next model to look where the last one looked.

Common mistake: alert fatigue

A detector that fires 400 alerts a day with 3% precision will be muted within a month, and then it catches nothing. Fewer, better alerts always beat more alerts. Set the threshold from the reviewers' capacity, group related alerts into one incident, show the reviewer why the item scored high (the features driving the score; SHAP works on Isolation Forest too, Chapter 20), and measure precision weekly. An alerting system's real metric is the fraction of alerts that get acted on.

At work

Start with robust z-scores on the two or three metrics the domain expert already watches; you will be surprised how often that is enough, and it builds trust. Then Isolation Forest on a wider feature table with a contamination set from the review budget. Ship the ranked list into the reviewers' existing tool, log every decision they make, and in three months you will own a labeled dataset that turns the problem into ordinary supervised learning. The unsupervised model was never the destination; it was the label-collection machine.

Key idea

Anomaly detection is ranking by strangeness under a review budget. The score comes from a model of normal (a distribution, a tree ensemble's path length, a local density, a reconstruction); the threshold comes from the business; the evaluation comes from humans reviewing the top of the list. Labels, once they exist, beat every unsupervised method.

5. Causal inference: correlation is not a lever

Every model in this book so far answers "what will happen?" Business, however, keeps asking "what will happen if we do X?" Those are different questions, and confusing them is the most expensive mistake in applied ML. Ice-cream sales and drowning deaths rise together every summer; a predictive model would happily use ice-cream sales to forecast drownings, and it would be right. Banning ice cream would save nobody, because the common cause is hot weather. Hot weather is a confounder: a variable that affects both the "treatment" (ice cream) and the outcome (drowning), creating a correlation with no causal arrow between them.

Explain it like I'm 9

Kids who own more books get better grades. Does mailing every kid a box of books raise grades? Probably not much: the families who buy lots of books are also the families who read aloud, help with homework, and can afford tutors. The books are a sign of those things, not the cause of the grades. To find out what books alone do, you would have to hand out books by coin flip and watch. That coin flip is the whole secret of causal inference.

Randomized experiments: the gold standard

If you assign the treatment by coin flip, nothing else can be correlated with it, so no back door exists and the difference in outcomes is the causal effect. That is why an A/B test is the most powerful tool in this chapter and the one you should fight for. Its discipline is simple but violated constantly:

  1. Randomize the unit that matters. If users talk to each other (marketplaces, social features), randomize by region or time, not by user, or the control group is contaminated.
  2. Decide the sample size before you start. To detect a 1-point lift on a 20% conversion rate at 80% power you need roughly 30,000 users per arm; a power calculation takes one minute and prevents a month of wishful thinking.
  3. Do not peek. Checking the p-value daily and stopping when it dips below 0.05 inflates the false-positive rate several-fold. Fix the duration, or use a sequential testing method built for peeking.
  4. Pre-register the metric. One primary metric, decided in advance; everything else is exploratory. Twenty metrics at α = 0.05 give you a "significant" win by chance most of the time.
  5. Watch guardrails. A ranker that lifts clicks by 5% and complaints by 40% is not a win.

Observational causal methods, honestly

Sometimes you cannot randomize: the treatment already happened, it is unethical to withhold, or the business refuses. Then you estimate the effect from observational data by adjusting for confounders, and you must say out loud that the result is only as good as the assumption that you measured all of them. The main tools:

The math (optional)

Regression adjustment: fit Y = β0 + τ·T + βᵀx and read τ as the effect, valid if x contains every confounder and the linear form is right. Propensity score e(x) = P(T = 1 | x), estimated with any classifier. Matching pairs each treated unit with an untreated unit of similar e(x) and compares outcomes within pairs. Inverse probability weighting (IPW) estimates the average treatment effect as

τ̂IPW = (1/n) ∑i [ Ti Yi / e(xi) − (1 − Ti) Yi / (1 − e(xi)) ]

Each treated unit is up-weighted by how unlikely it was to be treated, so the reweighted treated group looks like the whole population; likewise for controls. It requires overlap: every x must have a real chance of both treatment and control (e(x) not near 0 or 1), otherwise the weights explode. Difference-in-differences compares the change in outcome for the treated group to the change for an untreated group over the same period, cancelling any fixed difference between them (assumes parallel trends). Instrumental variables use a variable that shifts treatment but affects the outcome only through treatment (a random nudge, a policy cutoff) to recover the effect even with unmeasured confounding; they are powerful and fragile, and belong in an economist's hands.

# Confounding: a "retention offer" that is sent mostly to engaged customers
import numpy as np
from sklearn.linear_model import LogisticRegression, LinearRegression

rng = np.random.default_rng(42)
n = 50_000
engagement = rng.normal(0, 1, n)                     # confounder: affects BOTH treatment and outcome
p_treat = 1 / (1 + np.exp(-1.5 * engagement))       # engaged customers get the offer more often
T = rng.random(n) < p_treat                          # treatment: got the offer
TRUE_EFFECT = 0.05                                   # offer raises retention by 5 points, for everyone
p_stay = np.clip(0.5 + 0.15 * engagement + TRUE_EFFECT * T, 0, 1)
Y = rng.random(n) < p_stay                           # outcome: stayed

naive = Y[T].mean() - Y[~T].mean()
print(f"naive difference in retention (treated - untreated): {naive:+.3f}")

# 1) regression adjustment: control for the confounder
X = np.c_[T, engagement]
adj = LinearRegression().fit(X, Y).coef_[0]
print(f"regression-adjusted effect:                         {adj:+.3f}")

# 2) inverse probability weighting: re-weight so treated/untreated look alike
ps = LogisticRegression().fit(engagement[:, None], T).predict_proba(engagement[:, None])[:, 1]
w = np.where(T, 1 / ps, 1 / (1 - ps))
ipw = np.average(Y[T], weights=w[T]) - np.average(Y[~T], weights=w[~T])
print(f"IPW effect:                                         {ipw:+.3f}")

# 3) the gold standard: randomize
T_rct = rng.random(n) < 0.5
Y_rct = rng.random(n) < np.clip(0.5 + 0.15 * engagement + TRUE_EFFECT * T_rct, 0, 1)
print(f"randomized experiment:                              {Y_rct[T_rct].mean() - Y_rct[~T_rct].mean():+.3f}")
print(f"true effect:                                        {TRUE_EFFECT:+.3f}")
# naive difference in retention (treated - untreated): +0.210
# regression-adjusted effect:                         +0.049
# IPW effect:                                         +0.052
# randomized experiment:                              +0.057
# true effect:                                        +0.050

The naive comparison overstates the effect four-fold: the offer looks like it lifts retention by 21 points when the true effect is 5, because engaged customers, who were going to stay anyway, received it more often. Both adjustments recover the truth because we simulated the confounder and measured it. In real data you never know whether you measured them all; the randomized arm is the only line with no asterisk.

Common mistake

Reading a feature importance or a SHAP value as a causal effect. "Customers who received the discount churn less, so discounts reduce churn" is exactly the ice-cream fallacy when discounts were targeted at loyal customers. A predictive model is trained to exploit confounding, not to remove it; that is what makes it a good predictor and a terrible policy guide. The words to use with stakeholders are "associated with", until an experiment lets you say "causes".

6. Uplift modeling: whom to treat

Here is the sharpest version of the prediction-versus-intervention gap. A churn model tells you who will leave. The retention team wants to know whom a phone call will keep. Those are different people. Some customers will leave whatever you do; some will stay whatever you do; some will be persuaded by the call; and some, annoyingly, will be reminded by the call that they meant to cancel. Only the third group is worth the call. Uplift modeling (also: heterogeneous treatment effect estimation) predicts, per customer, the difference the treatment makes.

Meta-learners: S, T and X

Uplift needs experimental (or well-adjusted observational) data with a treatment column. Given that, the simplest estimators reuse ordinary supervised models:

  • S-learner ("single"): fit one model f(x, T) with the treatment as a feature; uplift τ̂(x) = f(x, 1) − f(x, 0). Simple, but a regularized model may ignore T when its effect is small relative to the other features, shrinking all uplifts toward zero.
  • T-learner ("two"): fit f1 on treated rows and f0 on control rows; τ̂(x) = f1(x) − f0(x). Easy, robust, the default. Its weakness is that the two models' errors do not cancel, so the difference is noisy when one arm is small.
  • X-learner: a T-learner followed by a second stage that imputes each unit's individual effect (Y − f0(x) for treated, f1(x) − Y for controls), models those, and blends with propensity weights. Better when the arms are unbalanced. Beyond that: uplift trees that split directly on the difference in outcome rates, causal forests, and double machine learning; the causalml and econml libraries implement them all.
# Uplift modeling: predict WHO the offer will change, not who will stay
import numpy as np
from sklearn.ensemble import GradientBoostingClassifier

rng = np.random.default_rng(7)
n = 20_000
X = rng.normal(size=(n, 4))                 # x0 = price sensitivity, x1 = loyalty, x2, x3 = noise
T = rng.random(n) < 0.5                     # a real randomized campaign: coin-flip treatment
base = 1 / (1 + np.exp(-0.8 * X[:, 1]))     # loyal customers stay anyway (sure things)
tau = 0.25 * (X[:, 0] > 0.5) - 0.10 * (X[:, 1] > 1.0)   # persuadables +25 pts, sleeping dogs -10 pts
Y = rng.random(n) < np.clip(base + tau * T, 0, 1)

tr = np.arange(n) < 12_000                  # first 12k train, rest test
te = ~tr
gbm = lambda: GradientBoostingClassifier(n_estimators=100, max_depth=3, random_state=0)
m1 = gbm().fit(X[tr & T], Y[tr & T])        # T-learner: one model per arm
m0 = gbm().fit(X[tr & ~T], Y[tr & ~T])
tau_hat = m1.predict_proba(X[te])[:, 1] - m0.predict_proba(X[te])[:, 1]

# Qini-style check: sort test customers by predicted uplift, then measure the OBSERVED
# treated-minus-control retention gap inside each decile
order = np.argsort(-tau_hat)
Yo, To, tau_o = Y[te][order], T[te][order], tau_hat[order]
gap = lambda sl: Yo[sl][To[sl]].mean() - Yo[sl][~To[sl]].mean()
d = len(order) // 10
print(f"{'decile':<8}{'observed uplift':>16}{'mean predicted':>16}")
for i in range(10):
    sl = slice(i * d, (i + 1) * d)
    print(f"{i + 1:<8}{gap(sl):>+16.3f}{tau_o[sl].mean():>+16.3f}")
print(f"average uplift if we treat everyone: {gap(slice(None)):+.3f}")
# decile   observed uplift  mean predicted
# 1                 +0.235          +0.346
# 2                 +0.261          +0.260
# 3                 +0.148          +0.181
# 4                 +0.024          +0.104
# 5                 +0.022          +0.059
# 6                 -0.046          +0.028
# 7                 -0.001          +0.002
# 8                 -0.037          -0.021
# 9                 +0.019          -0.053
# 10                -0.052          -0.121
# average uplift if we treat everyone: +0.057

The T-learner puts the persuadables (high price sensitivity) in the top deciles, where the observed treated-minus-control gap is 24–26 points against a population average of 6, and it correctly predicts negative uplift for the bottom decile, which holds the sleeping dogs (the very loyal, who react badly to being nudged). Contact the top three deciles and you capture most of the gain at 30% of the cost; contact everyone and you actively lose the last decile. That table, translated into money (Chapter 23), is the business case.

At work

Uplift is the right frame whenever a costly, optional action is applied to a subset of people: retention offers, marketing emails, discount coupons, sales-rep calls, dunning strategies, medical outreach. Two conditions must hold before you build one: you need a treatment log with a randomized (or at least not fully targeted) control group, and the treatment effect must plausibly vary across people, otherwise a single average effect and a cost threshold is all you need. If the team has never run an experiment, your first deliverable is not a model; it is a 10% random holdout on the next campaign. That holdout is the training set for everything that follows.

Key idea

Prediction tells you what will happen; causal inference tells you what you can change. Randomization removes confounding by construction; adjustment (regression, propensity scores, IPW, diff-in-diff) removes it only for confounders you measured. Uplift modeling turns a causal question into a ranking: sort people by the effect the treatment has on them, and act on the top.

7. Reinforcement learning primer & bandits

Reinforcement learning (RL) is the third family from Chapter 1: an agent observes a state, takes an action, receives a reward and a new state, and learns a policy (state → action) that maximizes the total reward over time. There is no answer key. The feedback is delayed and partial: you learn that a chess move was bad forty moves later, and you only ever learn about the moves you tried.

Explain it like I'm 9

Training a puppy. You do not explain "sit"; the puppy tries things, and when it happens to sit it gets a treat. The puppy's whole job is to figure out which of its actions, in which situations, leads to treats, even when the treat comes a bit later. The tricky part: if the puppy only ever repeats the first thing that earned a treat, it never discovers that "roll over" earns two. It has to keep trying new things sometimes. That is exploration versus exploitation, and it is the central tension of this whole section.

The math (optional)

An MDP is (S, A, P, R, γ): states, actions, transition probabilities P(s′ | s, a), reward function R(s, a) and discount γ ∈ [0, 1). The return from time t is

Gt = rt+1 + γ rt+2 + γ2 rt+3 + … = ∑k≥0 γk rt+k+1

The state value Vπ(s) = E[Gt | st = s] under policy π, and the action value Qπ(s, a) is the same with the first action fixed. The optimal values satisfy the Bellman equation:

Q*(s, a) = E[ r + γ · maxa′ Q*(s′, a′) | s, a ]

which says: the value of taking a in s equals the immediate reward plus the discounted value of the best action in the next state. Every RL algorithm is some way of solving this equation from samples.

Multi-armed bandits: the RL you will actually use

Strip the MDP down to a single state (no state transitions, every round is independent) and you have a multi-armed bandit: k slot machines with unknown payout rates, one pull per round, maximize total payout. It is the mathematical form of "which headline / banner / price / recommendation should we show?" and it is the version of RL that runs in real products, because it needs no simulator and its failure modes are mild. The bandit's only problem is the exploration–exploitation trade-off, and three classic strategies solve it:

# Multi-armed bandits: epsilon-greedy vs UCB vs Thompson sampling, judged by cumulative regret
import numpy as np
rng = np.random.default_rng(0)
p_true = np.array([0.05, 0.08, 0.12, 0.10])   # click rates of 4 banner variants (unknown to the agent)
best = p_true.max()
T = 5000

def run(policy):
    n = np.zeros(4); s = np.zeros(4); regret = 0.0
    for t in range(1, T + 1):
        if policy == "eps-greedy":                 # explore 10% of the time, otherwise pick the best-so-far
            a = rng.integers(4) if rng.random() < 0.1 else int(np.argmax(s / np.maximum(n, 1)))
        elif policy == "ucb":                      # optimism: mean + exploration bonus that shrinks with pulls
            a = t - 1 if t <= 4 else int(np.argmax(s / n + np.sqrt(2 * np.log(t) / n)))
        else:                                      # thompson: sample a plausible rate per arm from its Beta posterior
            a = int(np.argmax(rng.beta(1 + s, 1 + n - s)))
        r = rng.random() < p_true[a]
        n[a] += 1; s[a] += r
        regret += best - p_true[a]                 # expected clicks lost by not pulling the best arm
    return regret, n

for pol in ["eps-greedy", "ucb", "thompson"]:
    reg, n = run(pol)
    print(f"{pol:<11} regret = {reg:6.1f}   pulls per arm = {n.astype(int)}")
print(f"show-each-variant-equally regret = {T * (best - p_true.mean()):.1f}")
# eps-greedy  regret =   25.5   pulls per arm = [ 226  170 4458  146]
# ucb         regret =  115.6   pulls per arm = [ 651 1041 1889 1419]
# thompson    regret =   17.0   pulls per arm = [  88  165 4535  212]
# show-each-variant-equally regret = 162.5

Read the pull counts: ε-greedy and Thompson both concentrated on arm C (the 12% arm), while UCB, whose exploration bonus assumes rewards can vary across the full [0, 1] range, kept testing the other arms far longer than these tiny click rates warranted; its regret is still under the "show every variant equally" baseline, which is what a classic A/B test costs. That is the bandit's selling point in one line: a fixed-split A/B test pays the full price of exploration for the whole test, a bandit pays it only while the answer is uncertain. The cost is statistical: a bandit's final estimates of the losing arms are noisy (it stopped pulling them), and adaptive allocation complicates the p-value. Use bandits when the goal is to earn during the test (headlines, offers, ad creatives); use fixed A/B tests when the goal is to learn precisely (pricing decisions you will defend to the board).

Contextual bandits

Add features (the user, the time, the device) and let the reward model depend on them, and you have a contextual bandit: each round, predict the reward of every arm given the context, pick with Thompson sampling or UCB over the model's uncertainty, observe, update. This is the workhorse of personalized news, ad and recommendation exploration at scale, and it is the honest answer to the cold-start and popularity-bias problems of Section 2: the exploration slot in Figure 22.3 is a contextual bandit.

8. Q-learning on a gridworld

Full RL brings back states and transitions. The cleanest algorithm to hold in your head is tabular Q-learning: keep a table Q[s, a] of estimated action values, act mostly greedily on it, and after every step nudge the entry you just used toward the reward you saw plus the discounted best value of where you landed. That nudge is the Bellman equation applied to one sample.

The math (optional)
Q(s, a) ← Q(s, a) + α [ r + γ · maxa′ Q(s′, a′) − Q(s, a) ]

α is the learning rate (how far to move toward the new estimate), r the reward just received, γ the discount, s′ the next state, and the bracket is the temporal-difference error: the gap between what we predicted and what one step of experience suggests. Q-learning is off-policy: it learns the value of the greedy policy even while the agent explores with ε-greedy, because the target uses maxa′ rather than the action actually taken next. Given enough exploration and a decaying α it converges to Q*. Deep Q-networks (DQN) replace the table with a neural network Q(s, a; θ) and the same update becomes a regression loss on the TD error.

# Tabular Q-learning on a 4x4 gridworld: start top-left, goal bottom-right (+1), pit at row 1 col 2 (-1)
import numpy as np
rng = np.random.default_rng(1)
N = 4; GOAL = (3, 3); PIT = (1, 2)
moves = {0: (-1, 0), 1: (0, 1), 2: (1, 0), 3: (0, -1)}   # up, right, down, left
arrows = "↑→↓←"
Q = np.zeros((N, N, 4))                                   # Q[row, col, action]
alpha, gamma, eps = 0.2, 0.9, 0.2                         # learning rate, discount, exploration

def step(s, a):
    r, c = s; dr, dc = moves[a]
    s2 = (min(max(r + dr, 0), N - 1), min(max(c + dc, 0), N - 1))   # walls: bump and stay
    if s2 == GOAL: return s2, 1.0, True
    if s2 == PIT:  return s2, -1.0, True
    return s2, -0.04, False                               # small step cost: prefer short paths

for episode in range(500):
    s = (0, 0)
    for _ in range(50):
        a = int(rng.integers(4)) if rng.random() < eps else int(np.argmax(Q[s]))
        s2, r, done = step(s, a)
        target = r if done else r + gamma * Q[s2].max()
        Q[s][a] += alpha * (target - Q[s][a])             # THE Q-learning update
        s = s2
        if done: break

print("learned policy (G = goal, X = pit):")
for r in range(N):
    print(" ".join("G" if (r, c) == GOAL else "X" if (r, c) == PIT else arrows[int(np.argmax(Q[r, c]))] for c in range(N)))
print("state values V(s) = max_a Q(s,a):")
print(np.round(Q.max(axis=2), 2))
# learned policy (G = goal, X = pit):
# → ↓ → ↓
# → ↓ X ↓
# → ↓ → ↓
# → → → G
# state values V(s) = max_a Q(s,a):
# [[0.43 0.52 0.52 0.71]
#  [0.52 0.62 0.   0.85]
#  [0.62 0.73 0.86 1.  ]
#  [0.73 0.86 1.   0.  ]]

The learned policy is a set of arrows: every state points along a shortest path to the goal that avoids the pit (compare the column-2 states, which route around the X). The value grid shows the discounting at work: 1.0 next to the goal, 0.86 one step further, 0.73 after that; each step back costs a factor of γ = 0.9 plus the −0.04 step penalty. Deep RL and RLHF, in one paragraph

When states are images or continuous vectors, the Q-table becomes a neural network (DQN, 2015, Atari), or the network outputs the policy directly and is trained to increase the probability of actions that led to above-average return (policy gradient; PPO is the standard modern variant). The same machinery, with the "environment" being a reward model trained on human preference comparisons, is RLHF, the step that turns a raw language model into an assistant (Chapter 19). The reward model is itself a supervised model of "which of these two answers did the human prefer"; PPO then nudges the language model's policy toward answers that score well while a penalty keeps it close to the original model, the RL equivalent of regularization.

Why RL is hard in production

Three reasons full RL stays rare outside games, robotics labs and a few large tech companies. Sample efficiency and simulators: Q-learning needed hundreds of episodes for 25 states; real problems need millions of interactions, which means a faithful simulator, and building one is usually harder than the original problem. Safety: exploration means deliberately trying actions you suspect are bad; in a game that is free, in a pricing system or a power grid it is not. Reward hacking: the agent optimizes the reward you wrote, not the goal you meant, with a creativity that is genuinely unsettling: a boat-racing agent that loops forever collecting bonus points instead of finishing, a recommender that maximizes clicks by recommending outrage. If your reward is a proxy (and it always is), the agent will find the gap between the proxy and the intent. Bandits avoid all three problems by having no state, small exploration cost, and an immediate reward. That is why they are the practical RL.

Common mistake

Reaching for RL because the problem involves "decisions over time". Most sequential business decisions are better served by a forecast plus an optimizer (predict demand, then solve a scheduling problem), or by a contextual bandit if feedback is immediate. Full RL earns its complexity only when actions change future states in ways you cannot model by hand and you have a simulator or a very cheap, safe way to explore.

Key idea

RL learns a policy from rewards by solving the Bellman equation from experience. The exploration–exploitation trade-off is the core difficulty; bandits are its simplest, most useful form. Tabular Q-learning is the mechanism; deep RL swaps the table for a network; RLHF is deep RL with a learned reward. In production, use bandits freely, full RL rarely, and watch the reward for hacks.

Honorable mentions

Survival analysis. When the question is "how long until…" (churn, failure, repayment) and many records are still alive at the end of your data (censored), a regression on "days until event" silently drops or distorts them. Survival models (Kaplan–Meier curves, Cox proportional hazards, gradient-boosted survival trees in scikit-survival) use the censored rows correctly and output a full time-to-event curve rather than a point. Reach for them whenever the label is a duration and some durations are unfinished.

Graph ML. When the rows are connected (customers who transact with each other, molecules, road networks, citation graphs), the neighbourhood is a feature. Start with hand-made graph features (degree, PageRank, how many fraudulent neighbours), which capture most of the value inside a GBM; graduate to graph neural networks (message passing, where each node's embedding aggregates its neighbours') when the structure is rich and the labels are plentiful. Fraud rings and recommendation are the classic wins.

AutoML. Tools like AutoGluon, FLAML and H2O search over models, preprocessing and hyperparameters automatically, and on clean tabular data they produce a strong ensemble in an hour. They are excellent for a baseline and a sanity check ("is my hand-built model in the right ballpark?") and poor at the parts that actually decide a project: target definition, leakage, and business translation. Use them as a fast second opinion, not as the workflow.

TabPFN. A transformer pre-trained on millions of synthetic tabular datasets that performs classification on a new small table (up to a few thousand rows) with no training, by in-context learning. On small, clean, numeric datasets it is often the best model available at zero tuning cost. Try it when n < 10,000 and you need an answer today; verify it with the same cross-validation you would use for anything else.

Semi-supervised and active learning. Labels are the expensive part of most projects. Semi-supervised methods use the unlabeled majority (pseudo-labeling confident predictions, consistency regularization) to improve a model trained on a small labeled set. Active learning chooses which unlabeled rows to send to the human labeler, typically the ones the model is least certain about or the ones most representative of a cluster, so that every label buys the maximum improvement. If you are about to pay people to label 50,000 examples, an active-learning loop usually gets the same model from 10,000.

At work

The pattern across every topic in this chapter: the "advanced" method is rarely the first deliverable. The first deliverable is the infrastructure that makes the method possible: impression logs for a recommender, a review queue that captures labels for anomaly detection, a random holdout for causal and uplift work, a reward log for bandits. Build that in week one, and the sophisticated model becomes a two-week project instead of an impossible one.

Quiz

Check your understanding

1. In an explicit-ratings matrix, a blank cell means the user…

Blank = unknown. Treating it as 0 teaches the model that everyone hates almost everything. In implicit data blanks are weak negatives, handled with confidence weights, not hard zeros.

2. Your new recommender has a better NDCG@10 offline but loses the A/B test on conversions. The most likely explanation is…

Held-out clicks are biased by past exposure and popularity. Offline metrics are a filter; online lift is the measurement, and a less "accurate" but more diverse ranker can win.

3. A fraud analyst can review 40 alerts per day. What is the right way to set the anomaly detector's threshold?

The threshold is a budget decision. Ranking under the review capacity keeps precision high, avoids alert fatigue, and produces labels that will later train a supervised model.

4. Customers who received a loyalty discount churned 20 points less than those who did not. Discounts were given by account managers to their "best" customers. The 20-point gap is…

Selection into treatment by a variable (manager's judgment of loyalty) that also drives the outcome is confounding. Only randomization, or adjustment for the confounder, can recover the real effect.

5. In uplift terms, which group should a retention campaign avoid contacting because contact makes them more likely to leave?

Sleeping dogs stay if left alone and leave if contacted (negative uplift). Sure things and lost causes are merely wasted money; persuadables are the target.

6. In the Q-learning update Q(s,a) ← Q(s,a) + α[r + γ maxa′Q(s′,a′) − Q(s,a)], the term in brackets is…

It is the gap between what the table predicted and what one step of experience suggests (reward plus discounted best next value). α controls how far the estimate moves toward it.

Exercises

Exercise 22.1 — Break the recommender

Using the code in Section 1, add a seventh user "Gus" who has rated only Coco (5). What does the item-item model predict for Gus on Dune, and why is that prediction weak? Then add an eighth user with no ratings at all. What can the model say? Propose two concrete fallbacks.

Show answer

Gus's only rated item, Coco, has negative adjusted-cosine similarity with Dune, so there are no positive neighbours and the model returns Gus's mean (5.0), which is meaningless with one rating; with more neighbours it would predict "low" because Coco-lovers dislike Dune in this data. The eighth user has no row at all: pure cold start, and CF returns nothing. Fallbacks: (1) recommend the most popular items (Up and Dune have the most high ratings), (2) content-based: ask one onboarding question ("animation or sci-fi?") and map it onto the two latent factors from Section 2; (3) an exploration slot: show a random item and learn from the response (a bandit).

Exercise 22.2 — Adjust for a confounder, then break the adjustment

In the causal simulation of Section 5, add a second confounder tenure that raises both the treatment probability and retention, but leave it out of the regression adjustment and the propensity model. Re-run. How far off are the "adjusted" estimates now, and what does that tell you about observational causal claims at work?

Show answer

Both adjusted estimates become biased upward again (typically landing between the naive and the true value), because a back door through tenure remains open. The randomized arm stays correct. Lesson: adjustment methods fix only the confounders you measured and included; the honest sentence in a report is "assuming no unmeasured confounding", and the honest recommendation is to run the experiment.

Exercise 22.3 — Do it at work: find your bandit

List every place in your company where a choice among a few options is made repeatedly with fast feedback (email subject lines, push notification timing, which promotion to show, which support macro to suggest, which supplier to route to). Pick one. Write down: the arms, the reward (measurable within hours), the context features if any, and the guardrail metric. Estimate the cost of a fixed A/B test (traffic × duration × share sent to the losing arms) versus a Thompson-sampling bandit. Present the comparison to the owner of that decision.

Show answer

A good answer names an immediate, automatically logged reward (open rate within 4 hours, not "customer satisfaction"), keeps the arm count small (3–8), and identifies a guardrail (unsubscribes, complaints). The cost comparison typically shows the bandit saving 50–80% of the exploration loss for the same decision quality; the caveat to state is that the bandit's estimates for the losing arms will be imprecise, which matters if someone later asks "by how much did the loser lose?"

Chapter summary

  • Recommendation = matrix completion + ranking. Item-item CF on implicit data is the workhorse baseline; matrix factorization and two-tower embeddings scale it; hybrids fix cold start.
  • Blank ≠ dislike. Popularity bias is a feedback loop; evaluate with precision@k / NDCG offline, but decide by online A/B lift.
  • Anomaly detection ranks by strangeness under a review budget: robust z-scores, Mahalanobis, Isolation Forest (default), LOF (local density), autoencoders (structured data).
  • Set thresholds from reviewer capacity, evaluate with top-k human review or injected anomalies, and let collected labels turn the problem supervised.
  • Correlation is not a lever. Confounders open back doors; randomization closes them by construction; regression, propensity/IPW and diff-in-diff close only the ones you measured.
  • Run A/B tests properly: right unit, pre-computed sample size, no peeking, one primary metric, guardrails.
  • Uplift models rank people by the effect of treatment on them (T-learner: two models, subtract). Validate with a Qini/decile table on a randomized holdout, in money.
  • RL = policy learning from rewards via the Bellman equation. Bandits (Thompson sampling) are the production RL; Q-learning is the mechanism; full RL needs a simulator, safety, and a reward that cannot be hacked.
  • Survival analysis for durations with censoring, graph features for connected data, AutoML/TabPFN as fast second opinions, active learning to spend the labeling budget wisely.
