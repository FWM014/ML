Neural Networks From Scratch

Every deep-learning system, from image classifiers to language models, is built from one idea repeated: a weighted sum, a bend, and a rule for nudging the weights. This chapter builds that idea up from a single neuron to a working network in sixty lines of numpy, derives backpropagation without hand-waving, and tells you honestly when a network is the right tool at work.

Two datasets run through the chapter. The first is the four-point XOR problem, small enough to compute by hand and the classic proof that networks need hidden layers. The second is scikit-learn's two moons, two interleaving crescents that no straight line separates, on which we train a network from scratch. Neither is a "real" dataset; that is the point. By the end you will have seen every number that flows through a network and every number that flows back.

1. The neuron: a weighted sum with a bend

An artificial neuron does three things to its inputs. It multiplies each input by a weight and adds them up. It adds a bias. It passes the result through a fixed nonlinear function, the activation. That's all. The biological name is marketing; mathematically it is a linear model with a bend at the end.

The math: one neuron
z = w1x1 + w2x2 + … + wdxd + b = w·x + b      a = σ(z)

x is the input vector (d features). w holds the d weights: how much each feature pushes the output up or down. b is the bias, the output when all inputs are zero. z is the pre-activation, a plain linear score. σ is the activation function, here the sigmoid σ(z) = 1/(1 + e−z), which squashes any real number into (0, 1). a is the neuron's output, its "activation". A neuron has d + 1 parameters.

Explain it like I'm 9

A neuron is a judge with a scorecard. Each input is a piece of evidence; each weight says how much that evidence counts (positive for "yes", negative for "no"). The judge adds it all up, adds their personal leaning (the bias), and then squashes the total into a verdict between 0 ("definitely no") and 1 ("definitely yes"). Training a neuron is just adjusting how much each piece of evidence counts.

Here is the punchline made concrete: take the logistic regression sklearn fits on the breast-cancer data, copy its coefficients into a hand-written neuron, and the outputs match to machine precision.

# One sigmoid neuron with sklearn's logistic-regression weights == sklearn's predictions
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
X, y = load_breast_cancer(return_X_y=True)
X = StandardScaler().fit_transform(X)                 # 569 rows × 30 features
lr = LogisticRegression(max_iter=1000).fit(X, y)
w, b = lr.coef_[0], lr.intercept_[0]                  # 30 weights + 1 bias
def sigmoid(z): return 1 / (1 + np.exp(-z))
neuron = sigmoid(X @ w + b)                           # weighted sum + bias → activation
rows = [13, 81, 86]
print("one neuron  :", neuron[rows].round(3))
print("sklearn     :", lr.predict_proba(X)[rows, 1].round(3))
print("max |diff|  :", float(np.abs(neuron - lr.predict_proba(X)[:, 1]).max()))
# one neuron  : [0.329 0.659 0.202]
# sklearn     : [0.329 0.659 0.202]
# max |diff|  : 1.1102230246251565e-16
Key idea

A neural network is logistic regression, stacked. If you understood Chapters 5 and 6 (a linear score, a squashing function, a loss, gradient descent), you already understand every ingredient. What the network adds is composition: the outputs of one layer of neurons become the inputs of the next, and that composition is what lets it draw curved boundaries.

The weights rotate the line and set how sharp the transition is (bigger |w| = steeper); the bias slides it. Notice what you cannot do with any setting: bend the line. One neuron carves the plane into two half-planes, full stop.

2. Why one neuron isn't enough: XOR

The widget's limitation is fatal for a lot of problems, and the smallest one that exposes it is XOR ("exclusive or"): the output is 1 when exactly one of two binary inputs is 1. Four points, two classes, and the two classes sit at opposite corners of a square. No single straight line puts (0,1) and (1,0) on one side and (0,0) and (1,1) on the other. Since a neuron is a straight line, a single neuron cannot learn XOR, ever. This observation (Minsky and Papert, 1969) stalled neural-network research for over a decade.

# XOR: one neuron fails, a 2-2-1 network succeeds. Look at what the hidden layer computes.
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.neural_network import MLPClassifier
X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]]); y = np.array([0, 1, 1, 0])   # XOR
line = LogisticRegression().fit(X, y)
print("one neuron (logistic regression) accuracy:", line.score(X, y))
mlp = MLPClassifier(hidden_layer_sizes=(2,), activation="tanh", solver="lbfgs",
                    max_iter=2000, random_state=1).fit(X, y)                  # 2-2-1 network
print("2-2-1 network accuracy:", mlp.score(X, y))
H = np.tanh(X @ mlp.coefs_[0] + mlp.intercepts_[0])   # what the hidden layer sees
print("hidden-layer coordinates of the 4 points:\n", H.round(2))
# one neuron (logistic regression) accuracy: 0.5
# 2-2-1 network accuracy: 1.0
# hidden-layer coordinates of the 4 points:
#  [[ 0.93  1.  ]
#  [-0.96  0.98]
#  [-0.95  0.97]
#  [-1.   -0.92]]

Read the hidden coordinates: (0,1) and (1,0), the two "1" cases, both land near (−0.95, 0.98). The network has invented a feature, "exactly one input is on", that no human specified. Rows 1 and 4, the "0" cases, land far away in different corners. In this new space a straight line finishes the job. That is the entire deep-learning story in miniature: each layer re-describes the data so that the next layer's job is easier. Note also that the fit depends on the random seed: with random_state=0 this tiny network gets stuck at 75%. Small networks have bad local minima; wider ones, as we'll see, rarely do.

Explain it like I'm 9

Imagine four coins on a table, two heads at opposite corners, two tails at the other corners. You're told to separate heads from tails with one straight ruler. Impossible. Now you're allowed to fold the table first. Fold it along the diagonal so the two tails land on top of each other, and suddenly one ruler does it. The hidden layer is the fold.

3. Activation functions and why ReLU won

The "bend" is not optional. Stack ten layers of neurons without activations and the whole thing collapses into one linear map (a matrix times a matrix is a matrix). The activation is what makes depth mean anything. Several bends are in common use.

ActivationFormulaRangeUse it forTrouble
Sigmoid1/(1+e−z)(0, 1)Output layer of a binary classifier (it's a probability).Saturates; derivative ≤ 0.25; not zero-centred. Avoid in hidden layers.
tanh(ez−e−z)/(ez+e−z)(−1, 1)Small networks, recurrent cells (Chapter 18).Still saturates, derivative ≤ 1.
ReLUmax(0, z)[0, ∞)Default for hidden layers. Cheap, no saturation for z > 0."Dead" neurons: if z < 0 for every input, gradient is 0 forever.
Leaky ReLUz if z > 0 else 0.01z(−∞, ∞)When dead ReLUs are a problem.One more hyperparameter (the slope).
GELU / SiLU (Swish)z·Φ(z) / z·σ(z)≈(−0.17, ∞)Transformers and modern vision models (Chapters 17–19). Smooth ReLU.Slightly more compute; benefit is small outside large models.
Softmaxezi / ∑j ezjprobabilities summing to 1Output layer of a multi-class classifier.Output only; never in hidden layers.
None (linear)z(−∞, ∞)Output layer of a regressor.Useless in hidden layers: the network collapses to a linear model.

Why ReLU won. Through the 1990s and 2000s, hidden layers used sigmoid or tanh, and networks deeper than three or four layers simply would not train. Section 8 shows why: the derivative of a sigmoid is at most 0.25, and backpropagation multiplies one such derivative per layer, so the learning signal reaching early layers shrank geometrically (the vanishing gradient). ReLU (Nair and Hinton, 2010; Glorot et al., 2011) has derivative exactly 1 for any positive input, so gradients pass through intact. It is also nearly free to compute (a comparison, no exponentials), and it produces sparse activations (many exact zeros) that help optimisation. The 2012 AlexNet result that started the deep-learning era used ReLU. The modern variants, GELU and SiLU, are smooth versions of the same shape and matter mostly at transformer scale; at work, on a tabular MLP, ReLU is the right default.

Common mistake

Putting a sigmoid or softmax on a hidden layer "because the values should be probabilities", or forgetting the activation on the output layer of a classifier. Hidden layers want ReLU-family activations; the output layer's activation is dictated by the task: sigmoid for binary, softmax for multi-class, nothing for regression. And in PyTorch (Chapter 16) the loss function usually applies the output activation for you (BCEWithLogitsLoss, CrossEntropyLoss), so you feed it raw logits: applying sigmoid twice is a silent, common bug.

4. The multi-layer perceptron in matrix form

A multi-layer perceptron (MLP) is neurons arranged in layers, every neuron in one layer connected to every neuron in the next ("fully connected" or "dense"). The input layer is just the features. Each hidden layer is a set of neurons whose outputs feed the next layer. The output layer produces the prediction. The number of layers with weights is the depth; the number of neurons in a layer is its width.

Writing it neuron by neuron is hopeless; the whole point of the matrix form is that one layer is one matrix multiplication. Stack the n examples as rows of X (n × d). Put the weights of all h neurons in the first layer side by side as the columns of W(1) (d × h). Then X W(1) computes every neuron's weighted sum for every example at once.

The math: the forward pass of a 2-layer MLP
Z(1) = X W(1) + b(1)    (n×d)(d×h) → (n×h)
A(1) = ReLU(Z(1))    (n×h), applied element-wise
Z(2) = A(1) W(2) + b(2)    (n×h)(h×k) → (n×k)   "logits"
Ŷ = softmax(Z(2)) row-wise    (n×k), each row sums to 1

X: n examples × d features. W(1): one column per hidden neuron, so d × h; b(1): h biases, added to every row (numpy broadcasting). Z are pre-activations, A are activations. W(2): h × k for k output classes. Z(2) are the logits, raw scores before the final squash. The shape rule to memorise: the inner dimensions must match, and the output of every layer has one row per example. Parameter count: d·h + h + h·k + k.

# Forward pass of a 4 → 3 → 2 MLP in five lines, with every shape printed
import numpy as np
rng = np.random.default_rng(0)
n, d, h, k = 5, 4, 3, 2                      # 5 examples, 4 features, 3 hidden units, 2 classes
X  = rng.normal(size=(n, d))
W1 = rng.normal(size=(d, h)) * np.sqrt(2 / d); b1 = np.zeros(h)
W2 = rng.normal(size=(h, k)) * np.sqrt(1 / h); b2 = np.zeros(k)
Z1 = X @ W1 + b1                             # (n×d)(d×h) + (h,)  → (n×h)
A1 = np.maximum(0, Z1)                       # ReLU, same shape
Z2 = A1 @ W2 + b2                            # (n×h)(h×k) + (k,)  → (n×k)   "logits"
P  = np.exp(Z2 - Z2.max(axis=1, keepdims=True)); P /= P.sum(axis=1, keepdims=True)   # softmax
print("X", X.shape, "→ Z1", Z1.shape, "→ Z2", Z2.shape, "→ P", P.shape)
print("each row of P sums to 1:", P.sum(axis=1).round(6))
print("parameters:", W1.size + b1.size + W2.size + b2.size)
print("MNIST-style 784→128→10 would have", 784*128 + 128 + 128*10 + 10, "parameters")
# X (5, 4) → Z1 (5, 3) → Z2 (5, 2) → P (5, 2)
# each row of P sums to 1: [1. 1. 1. 1. 1.]
# parameters: 23
# MNIST-style 784→128→10 would have 101770 parameters

Counting parameters: a worked example

Interviewers love this and it builds intuition for model size. A layer from width in to width out has in × out weights plus out biases. For a 784 → 128 → 10 network (a flattened 28×28 image, one hidden layer, ten digit classes): first layer 784 × 128 + 128 = 100,480; second layer 128 × 10 + 10 = 1,290; total 101,770. Note where the parameters live: 99% of them are in the first layer, because the input is wide. Add a second hidden layer of 128 and you add only 128 × 128 + 128 = 16,512. Depth is cheap; width at the input is expensive. (Two sanity checks for later chapters: the (x - max) inside softmax is not a trick, it is numerical hygiene, preventing exp from overflowing; and the √(2/d) scale on the weights is He initialisation, explained in Section 8.)

5. Loss functions

A network's output is compared to the truth by a loss function, and training is nothing but making that number small. The two you'll use cover almost everything.

The math: MSE and cross-entropy
Regression: LMSE = (1/n) ∑i (ŷi − yi)2
Binary classification: LBCE = −(1/n) ∑i [ yi log ŷi + (1 − yi) log(1 − ŷi) ]
Multi-class: LCE = −(1/n) ∑i log ŷi,ci    where ŷ = softmax(z) and ci is the true class

MSE (mean squared error): the average squared miss; big misses hurt quadratically. Use with a linear output. Binary cross-entropy: ŷi is the sigmoid output, the predicted probability of class 1. When y = 1 only the first term survives and the loss is −log ŷ: tiny if ŷ ≈ 1, enormous if ŷ ≈ 0. It punishes confident wrong answers brutally, which is what you want. Multi-class cross-entropy: only the probability the network assigned to the true class matters; −log of it. Both cross-entropies are the negative log-likelihood from Chapter 6, and both have a beautiful property: paired with their matching output activation, the gradient of the loss with respect to the logits is simply ŷ − y, the prediction minus the truth. That is the first equation of backpropagation, and it is why sigmoid+BCE and softmax+CE are always used together.

Explain it like I'm 9

MSE is like a teacher who takes off points equal to (how far off you were)². Cross-entropy is a teacher who asks "how sure were you?" If you said "I'm 99% sure it's a cat" and it was a dog, you lose a huge number of points. If you said "60% cat", you lose a few. It rewards honesty about uncertainty, which is exactly what we want from a probability.

At work

Match the loss to the output and the metric to the business, and don't confuse the two. You train with cross-entropy (smooth, differentiable) and you report accuracy, F1, or AUC (Chapter 6). For regression, MSE is the default but it chases outliers; if your target has heavy tails (revenue, durations), train with Huber loss or MAE, or predict log(y). And for imbalanced classes, weight the loss terms (pos_weight in PyTorch) before you reach for anything fancier.
