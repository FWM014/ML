Classification & Its Metrics

Most business ML is a yes/no question: fraud or not, churn or not, sick or not. This chapter teaches the model that answers it (logistic regression) and, far more importantly, how to tell whether any classifier is good — which is where most real projects go wrong.

1. Why a line can't say yes or no

Chapter 5 gave you linear regression: a weighted sum of features that predicts a number. Your first instinct for a yes/no question might be "just predict 1 for yes and 0 for no with the same machinery." Let's see why that fails, because the failure explains everything that follows.

Take our running example for this chapter: a payments company sees 1,000 card transactions in an hour, of which 50 are fraudulent. Plot the transaction amount on the x-axis and the label (1 = fraud, 0 = legit) on the y-axis and fit a straight line. Three things go wrong at once.

  1. The output is unbounded. A line happily predicts 1.2 or −0.1. Those numbers are not labels and not probabilities; nobody can act on "−10% fraud".
  2. Outliers swing the line. One $10,000 fraud at the far right drags the line up, shifting where it crosses 0.5 and mislabeling ordinary transactions. Squared error punishes the line for being "too right" about an obvious case.
  3. The wrong loss. Squared error is far too gentle on confident mistakes: its penalty is capped at 1, so a model that says "0.999 fraud" about a legitimate purchase pays barely more than one that says 0.8. Worse, squared error wrapped around an S-curve is no longer a single bowl, so gradient descent can get stuck. Probabilities need a loss built for probabilities.
Explain it like I'm 9

Imagine a dimmer switch for a light. A straight line is a slider with no ends — you can keep pushing it past "fully on" into nonsense. The sigmoid is a dimmer with hard stops: you can push as hard as you like but it only ever goes from "completely off" (0) to "completely on" (1), and most of the interesting action happens in the middle.

2. Logistic regression: score → probability

The fix is beautifully small. Keep the linear machinery from Chapter 5 — a weighted sum of features — but instead of using it as the answer, treat it as a score, then squash the score through an S-shaped function into (0, 1). The score is often called the logit; the squashing function is the sigmoid (also called the logistic function, which is where the model's slightly misleading name comes from — logistic regression is a classifier).

The math (optional)
z = w0 + w1x1 + … + wnxn = w·x + b
p = σ(z) = 1 / (1 + e−z)

z is the linear score (the logit): the same weighted sum as in Chapter 5. σ (sigma) is the sigmoid, which maps any real number into (0, 1). e−z is the exponential; when z is large and positive it vanishes and p → 1; when z is large and negative it explodes and p → 0. The inverse relationship is the log-odds: log(p / (1 − p)) = z. So logistic regression is a linear model for the log-odds, which is why each weight wj has a clean interpretation: increasing feature j by one unit multiplies the odds of "yes" by ewj.

Play with the two knobs. The weight w controls steepness (how quickly the model flips from "no" to "yes" as x grows — the sign flips the direction), and the bias b slides the whole curve left or right, moving the point where p = 0.5.

Larger |w| → a sharper, more confident switch; w near 0 → the model shrugs (p ≈ 0.5 everywhere). Negative w flips the direction. The bias moves the boundary to x = −b/w without changing its steepness.

The decision boundary is a straight line in feature space

With one feature the boundary is a point (where z = 0). With two features it is a line; with n features, a flat (n−1)-dimensional plane. Whatever the dimension, logistic regression divides the world with one straight cut. Points far from the cut get confident probabilities; points near it get probabilities near 0.5. That is the model's honesty: it is unsure exactly where you would be unsure.

The loss: punish confident wrong answers

How do we fit the weights? Squared error was the wrong loss for probabilities, so we use log-loss (also called cross-entropy or negative log-likelihood). For a single example it is simple: if the truth is 1, the loss is −log(p); if the truth is 0, the loss is −log(1 − p). Look at what this does (Figure 6.4): a confident, correct prediction costs almost nothing; a confident, wrong prediction costs a fortune — the curve goes to infinity as p approaches the wrong end.

The math (optional)
L = −(1/N) ∑i [ yi log pi + (1 − yi) log(1 − pi) ]

N is the number of training examples. yi ∈ {0, 1} is the true label of example i and pi = σ(w·xi + b) the predicted probability. Exactly one of the two terms inside the bracket is active for each example (the other is multiplied by zero), which is how one formula covers both curves in Figure 6.4. Minimizing L is the same as maximizing the likelihood of the observed labels, which is why statisticians call the fitted weights the maximum-likelihood estimate.

Fitting is gradient descent exactly as in Chapter 5, with one lucky detail: the gradient of log-loss with respect to the weights is ∑i (pi − yi) xi — "prediction minus truth, times the input" — the same form as for linear regression. There is no closed-form solution, but log-loss is convex (one bowl, one minimum), so gradient descent and the smarter optimizers scikit-learn uses by default (lbfgs) always find the best weights. In practice you never write this loop; you call fit.

Deep dive: the gradient of log-loss, line by line 6 min
Explain it like I'm 9

To teach the model, you need to know which way to nudge each weight. For a linear model the recipe was "how wrong was I, times what I was looking at". Logistic regression adds a squash on top, and you might expect the squash to make the recipe messier. It does not: the messy parts cancel out exactly, and the recipe is still "how wrong, times what I was looking at". That cancellation is the reason the sigmoid and the log-loss are a matched pair.

Precisely. For one example with features x, label y ∈ {0, 1}, score z = w·x + b and probability p = σ(z), the loss is ℓ = −[y log p + (1 − y) log(1 − p)]. Apply the chain rule (Chapter 3) through the three links ℓ → p → z → w:

The math (optional)

Step 1, loss with respect to p: ∂ℓ/∂p = −y/p + (1 − y)/(1 − p) = (p − y) / [p(1 − p)].

Step 2, sigmoid with respect to its input: ∂p/∂z = σ(z)(1 − σ(z)) = p(1 − p).

Step 3, multiply: ∂ℓ/∂z = (p − y) / [p(1 − p)] · p(1 − p) = p − y. The denominator of step 1 is exactly the derivative in step 2, so they cancel and the "error signal" at the score is simply prediction minus truth.

Step 4, score with respect to the weights: ∂z/∂w = x and ∂z/∂b = 1, so ∂ℓ/∂w = (p − y) x and ∂ℓ/∂b = p − y. Averaging over N examples:

∂L/∂w = (1/N) ∑i (pi − yi) xi ∂L/∂b = (1/N) ∑i (pi − yi)

Compare Chapter 5: ∂L/∂w = (2/N) ∑ (ŷi − yi) xi. Same shape, different prediction, and a factor of 2 that the learning rate absorbs.

# The gradient of log-loss for logistic regression is (p - y) x: check the derivation numerically
import numpy as np
sigmoid = lambda z: 1 / (1 + np.exp(-z))

X = np.array([[1.0, 2.0], [0.5, -1.0], [2.0, 0.5]]); y = np.array([1, 0, 1])   # 3 rows, 2 features
w, b = np.array([0.3, -0.2]), 0.1

def loss(w, b):
    p = sigmoid(X @ w + b)
    return -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))

p = sigmoid(X @ w + b)
grad_w = X.T @ (p - y) / len(y)                    # (1/N) Σ (p_i − y_i) x_i
grad_b = np.mean(p - y)
print("p =", p.round(4), " p - y =", (p - y).round(4))
print("analytic  dL/dw =", grad_w.round(6), " dL/db =", round(grad_b, 6))

h = 1e-6                                           # central finite differences
num_w = np.array([(loss(w + h * e, b) - loss(w - h * e, b)) / (2 * h) for e in np.eye(2)])
num_b = (loss(w, b + h) - loss(w, b - h)) / (2 * h)
print("numerical dL/dw =", num_w.round(6), " dL/db =", round(num_b, 6))
# p = [0.5    0.6106 0.6457]  p - y = [-0.5     0.6106 -0.3543]
# analytic  dL/dw = [-0.301123 -0.595937]  dL/db = -0.081235
# numerical dL/dw = [-0.301123 -0.595937]  dL/db = -0.081235

Why this matters beyond elegance. First, it is why log-loss is convex for a linear score: the error signal p − y is monotone in z, so the loss has a single bowl and lbfgs always finds its bottom. Second, it is why you must not pair a sigmoid with squared error: ∂/∂z of (p − y)² is 2(p − y)·p(1 − p), and the factor p(1 − p) goes to zero exactly when the model is confidently wrong (p near 0 or 1), so learning stalls where it is needed most. Third, the same cancellation happens for softmax with the multiclass log-loss (Section 9), where the error signal at the scores is the probability vector minus the one-hot label; every neural-network classifier (Chapter 15) ends with this pair for exactly this reason.

Common mistake

Feeding unscaled features to logistic regression. The default solver converges slowly (you will see ConvergenceWarning) and the built-in regularization (Chapter 7) penalizes big-unit features unfairly. Always wrap it in a Pipeline with StandardScaler, as below. Also note the default C=1.0 is a regularization strength — logistic regression in sklearn is never "plain".

# Block 1: logistic regression on breast cancer, probabilities, confusion matrix, report
import numpy as np

3. Probabilities, labels and the threshold

A classifier really produces two things, and confusing them is the root of most metric arguments at work:

A score (probability)

"This transaction is 0.83 likely to be fraud." Continuous, rankable, carries uncertainty. This is what the model actually learned.

A hard label

"Block it." Produced by comparing the score with a threshold t: label = 1 if p ≥ t. The threshold is a business decision, not a model property.

The default threshold of 0.5 is only sensible when a false alarm costs the same as a miss. For fraud (a miss costs $200, a review costs $5) it is absurd, and we will replace it with a number derived from those costs in Section 8. For now, hold onto the picture: the model gives you a dial; the threshold is where you set it, and every metric in the next sections depends on both.

Key idea

Separate the two questions. How well does the model rank cases? (a property of the scores — measured by AUC, average precision, log-loss). How good are the decisions at the threshold we chose? (a property of the labels — measured by precision, recall, F1, cost). Train and compare models on the first; tune the threshold and report to stakeholders on the second.

Explain it like I'm 9

A smoke detector measures smoke as a number all the time. The alarm only goes off when the number crosses a line someone set. Set the line low and it screams every time you make toast (false alarms); set it high and it sleeps through a real fire (misses). The detector didn't change — only the line did.

4. The confusion matrix, built carefully

Everything in classification evaluation starts with four counts. Take our 1,000 transactions (50 fraud, 950 legit), run the model with threshold 0.5, and sort every transaction into one of four buckets by what it really was and what we said.

Common mistake

scikit-learn's confusion_matrix(y_true, y_pred) puts true negatives in the top-left: the layout is [[TN, FP], [FN, TP]], rows = truth, columns = prediction, classes sorted ascending. Textbooks and other libraries often draw TP top-left. Before you read any confusion matrix, find out which class is "positive" and which axis is the truth. Unpack safely with tn, fp, fn, tp = confusion_matrix(y, pred).ravel().

Explain it like I'm 9

A guard dog at a gate. True positive: it barked at a burglar. False negative: a burglar walked past and it stayed asleep. False positive: it barked at the mail carrier. True negative: it let your grandmother in quietly. A good dog does lots of the first and last and little of the middle two — but "how much barking is too much" depends on whether you have more burglars or more mail carriers.

5. Accuracy, precision, recall and friends

Accuracy and the accuracy paradox

Accuracy is the fraction of all calls that were right: (TP + TN) / N = (35 + 930) / 1000 = 96.5%. Sounds excellent. Now consider a "model" that never flags anything: it gets all 950 legit transactions right and all 50 frauds wrong, for an accuracy of 95.0%. Our carefully trained model beats a rock by 1.5 points, and a slightly worse model would lose to it. This is the accuracy paradox: on imbalanced data, accuracy mostly measures the imbalance, not the model.

Key idea

Before you quote any accuracy, quote the majority-class baseline (the base rate of the bigger class). 95% accuracy on a 95/5 problem is zero skill. 80% accuracy on a 50/50 problem is real skill. Accuracy is only meaningful relative to that baseline, and on imbalanced problems you should usually not lead with it at all.

Precision and recall: two questions, two denominators

The two metrics that survive imbalance both look only at the positive class, but from different directions:

Precision — "when we flag, are we right?"

TP / (TP + FP) = 35 / 55 = 63.6%. Denominator: everything we flagged. Low precision means lots of false alarms: angry customers, wasted analyst hours. The operations team cares about this.

Recall — "of the real ones, how many did we catch?"

TP / (TP + FN) = 35 / 50 = 70%. Denominator: everything that was truly positive. Low recall means misses: fraud losses, undiagnosed patients. The risk team cares about this. Also called sensitivity or true positive rate (TPR).

Specificity is recall for the negative class: TN / (TN + FP) = 930 / 950 = 97.9%, "of the legit ones, how many did we leave alone?" Its complement, the false positive rate FPR = FP / (FP + TN) = 2.1%, is the x-axis of the ROC curve in Section 7. Doctors talk in sensitivity/specificity; engineers talk in precision/recall; they are looking at the same 2×2 grid.

The math (optional)
Precision = TP / (TP + FP) Recall = TP / (TP + FN) Specificity = TN / (TN + FP)
F1 = 2 · Precision · Recall / (Precision + Recall) = 2TP / (2TP + FP + FN)
Fβ = (1 + β²) · Precision · Recall / (β² · Precision + Recall)

F1 is the harmonic mean of precision and recall. The harmonic mean is dragged toward the smaller of the two, so a model cannot buy a high F1 by maxing one and ignoring the other: precision 1.0 with recall 0.1 gives F1 = 0.18, not 0.55. β says how many times more you care about recall than precision. β = 2 (F2) weights recall heavily — right for fraud and disease screening. β = 0.5 weights precision — right when each flag triggers an expensive human action. For our example: F1 = 70 / 105 = 0.667, F2 = 0.686, F0.5 = 0.648.

Explain it like I'm 9

You're fishing for salmon in a lake that also has trout. Precision: of the fish in your bucket, what fraction are salmon? Recall: of all the salmon in the lake, what fraction ended up in your bucket? A tiny net gives you a pure bucket (high precision) but leaves most salmon behind (low recall). Dragging the whole lake catches every salmon (recall 100%) but the bucket is mostly trout (low precision). F1 is the score you get only if both are decent.

At work

Never report precision or recall alone; report the pair, at a stated threshold, with the counts behind them ("at threshold 0.5 we catch 35 of 50 frauds and raise 20 false alarms per 1,000 transactions"). Counts per thousand are what a business owner can turn into dollars and headcount. A bare "recall = 0.70" invites the question "is that good?" and you will not have an answer.

6. The precision–recall tradeoff

Precision and recall pull in opposite directions, and the threshold is the rope. Lower the threshold and you flag more transactions: recall rises (you catch more fraud) but precision falls (more of your flags are wrong). Raise it and the reverse happens. 7. ROC, AUC and the PR curve

Figure 6.6 needs a whole plot per model. To compare models independent of any threshold, we summarize the entire sweep in one curve and one number. There are two standard curves; you need both and you need to know when each lies.

ROC, built step by step

The receiver operating characteristic (a name inherited from radar operators in the 1940s) plots recall (TPR) against the false positive rate (FPR) as the threshold sweeps from 1 down to 0. The cleanest way to understand it is to build one by hand from ten examples:

  1. Sort every example by its score, highest first. Forget the numbers; only the order matters from here on.
  2. Start at (0, 0) — threshold above everything, nothing flagged: no true positives, no false positives.
  3. Walk down the list, lowering the threshold one example at a time. Each time you pass a positive, TPR rises by 1/(number of positives): step up. Each time you pass a negative, FPR rises by 1/(number of negatives): step right.
  4. You end at (1, 1) with everything flagged. The path you drew is the ROC curve; the area under it is the AUC.
Key idea: what AUC means

AUC is the probability that a randomly chosen positive gets a higher score than a randomly chosen negative. Check it on Figure 6.7: there are 4 × 6 = 24 (fraud, legit) pairs; the fraud outranks the legit in 20 of them; 20/24 = 0.83 = the shaded area. That is why AUC is a pure ranking metric: it ignores the threshold, ignores calibration, and is unchanged if you squash or stretch all scores monotonically.

Rules of thumb: AUC 0.5 is a coin flip, 0.7 is "some signal", 0.8 is a good business model, 0.9+ is excellent (or leaking — see Chapter 7), and AUC below 0.5 means your labels are flipped. AUC is insensitive to class imbalance, which is both its strength (comparable across datasets) and its weakness, as the next figure shows.

The precision–recall curve, and when it beats ROC

The PR curve plots precision against recall over the same sweep. Its summary number is average precision (AP), the area under it (computed as a weighted mean of precisions at each recall step; scikit-learn's average_precision_score). The crucial difference: FPR's denominator is the negatives, of which we have 950; precision's denominator is the flags. With heavy imbalance, a few hundred false positives barely move FPR (300/950 = 0.32 looks tolerable on an ROC) but crush precision (49/349 = 14%). The ROC curve can look superb while the model is useless in practice.

Common mistake

Reporting AUC = 0.95 on a 1-in-1,000 problem and calling the model "production ready". At that imbalance, an AUC of 0.95 can coexist with a precision of 2% at any useful recall. Always look at the PR curve (or simply precision at the recall you need) before promising anything. Conversely, do not compare AP across datasets with different base rates: AP's floor is the base rate, so 0.30 may be excellent on a 1% problem and terrible on a 30% one.

import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

The threshold-tuning loop above is the single most valuable ten lines in this chapter. Tune the threshold on a validation set, never on the test set (Chapter 7 explains why), and store the chosen threshold next to the model as part of the artifact. Line up every fraud next to every legit transaction, one pair at a time, and ask: did the model give the fraud the higher score? Count the yeses, divide by the number of pairs. That fraction is the AUC. No threshold, no "how many did we flag", just "does the model put the bad ones above the good ones?"

Precisely. The area under the ROC staircase equals the fraction of (positive, negative) pairs in which the positive is ranked above the negative, ties counting one half. That is the Mann–Whitney U statistic divided by the number of pairs, and it can be computed from ranks alone:

The math (optional)
AUC = [ R+ − n+(n+ + 1)/2 ] / (n+ · n−)

n+ and n− are the numbers of positives and negatives; R+ is the sum of the ranks of the positives when all scores are ranked from 1 (lowest) to n (highest), ties receiving their average rank. Why it works: a positive with rank r has r − 1 examples below it, of which some are positives. Summing r − 1 over the positives counts every (positive, anything-below) pair; the positives below other positives are counted exactly n+(n+ − 1)/2 times in total, and subtracting those (the n+(n++1)/2 term absorbs the −1s as well) leaves only the (positive above negative) pairs. Dividing by n+n− turns the count into a probability. Why the staircase has the same area: each up-step (a positive) at height k/n− of the way across contributes a horizontal strip whose width is the number of negatives still to the right, which is exactly the number of negatives that positive outranks.

# AUC from ranks: the Mann-Whitney formula gives exactly the area under the ROC staircase of Figure 6.7
import numpy as np
from scipy.stats import rankdata
from sklearn.metrics import roc_auc_score

scores = np.array([0.95, 0.91, 0.80, 0.72, 0.60, 0.55, 0.41, 0.30, 0.18, 0.07])
y      = np.array([1,    1,    0,    1,    0,    0,    1,    0,    0,    0])
n_pos, n_neg = y.sum(), (1 - y).sum()

# 1) brute force: count (positive, negative) pairs in which the positive scores higher (a tie counts 1/2)
pairs = sum(1.0 if sp > sn else 0.5 if sp == sn else 0.0 for sp in scores[y == 1] for sn in scores[y == 0])
print(f"correctly ordered pairs = {pairs:.0f} of {n_pos * n_neg}  ->  AUC = {pairs / (n_pos * n_neg):.4f}")

# 2) the rank formula: same number without the double loop (rank 1 = lowest score)
ranks = rankdata(scores)
R = ranks[y == 1].sum()
auc_rank = (R - n_pos * (n_pos + 1) / 2) / (n_pos * n_neg)
print(f"ranks of the positives: {ranks[y == 1].astype(int).tolist()}, sum R = {R:.0f}")
print(f"AUC = (R - n+(n+ + 1)/2) / (n+ n-) = ({R:.0f} - {n_pos * (n_pos + 1) / 2:.0f}) / {n_pos * n_neg} = {auc_rank:.4f}")
print("sklearn roc_auc_score:", round(roc_auc_score(y, scores), 4))

# 3) any monotone re-scaling of the scores leaves the ranks, and therefore the AUC, unchanged
print("AUC after squashing every score toward 0.5:", round(roc_auc_score(y, 0.5 + 0.1 * (scores - 0.5)), 4))
# correctly ordered pairs = 20 of 24  ->  AUC = 0.8333
# ranks of the positives: [10, 9, 7, 4], sum R = 30
# AUC = (R - n+(n+ + 1)/2) / (n+ n-) = (30 - 10) / 24 = 0.8333
# sklearn roc_auc_score: 0.8333
# AUC after squashing every score toward 0.5: 0.8333

Three consequences that matter at work. (1) Ties and monotone transforms. Any strictly increasing transformation of the scores leaves the ranks unchanged, so AUC cannot see calibration (the last line above), and a model whose probabilities are all squashed into [0.45, 0.55] can still have AUC 0.99. Use log-loss or Brier (Section 10) when the numbers themselves matter. (2) An interpretable unit. "AUC 0.83" means "pick a random fraud and a random legit transaction; the model orders them correctly 83% of the time", which a stakeholder can picture, unlike "area under a curve". (3) Cheap confidence intervals. Because AUC is a mean over pairs, it has a standard error you can estimate by bootstrapping the test rows (Chapter 3); with few positives that interval is wide, and with 24 pairs, as here, it is enormous. Report it.

8. Choosing the metric and the threshold

There is no universally right metric. The right one is determined by (a) how imbalanced the classes are, (b) which error is more expensive, and (c) whether there is a fixed budget of actions. Here is the decision table I would put on the wall:

Cost-sensitive thresholding: a worked example

The most defensible way to set a threshold is to write down what each cell of the confusion matrix costs and pick the threshold that minimizes the total. For our payments company, a manual review of a flagged transaction costs $5 of analyst time (the cost of a false positive; we also pay it for true positives, but that is the same at any threshold that catches them, so it does not change the decision), and a fraud that slips through costs on average $200 (the false negative). Correct calls cost nothing. Now reuse the table from Section 6:

The math (optional)
Expected cost(t) = CFP · FP(t) + CFN · FN(t)
If probabilities are calibrated, flag when p ≥ t* = CFP / (CFP + CFN)

CFP and CFN are the costs of one false alarm and one miss; FP(t) and FN(t) are the counts at threshold t, read from the validation set. The second line is the Bayes decision rule: flag whenever the expected cost of not flagging, p · CFN, exceeds the expected cost of flagging, (1 − p) · CFP. With $5 and $200 that gives t* = 5/205 ≈ 0.024. In practice the empirical sweep (first line) usually lands somewhat higher, as our example does, because real models are not perfectly calibrated at the low end (Section 10 and Chapter 13). Trust the sweep on held-out data; use the formula as a sanity check.

# Cost-sensitive threshold: choose the cutoff that minimizes expected business cost
import numpy as np
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix

X, y = make_classification(n_samples=20000, n_features=12, n_informative=4, n_redundant=2,
                           weights=[0.95, 0.05], class_sep=1.5, flip_y=0.005, random_state=7)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.5, stratify=y, random_state=7)
proba = LogisticRegression(max_iter=1000).fit(X_tr, y_tr).predict_proba(X_te)[:, 1]
print("test size:", len(y_te), "| fraud cases:", y_te.sum())

COST_FP = 5      # $ to manually review a legitimate transaction we flagged
COST_FN = 200    # $ lost when a fraud slips through
def cost_at(t):
    tn, fp, fn, tp = confusion_matrix(y_te, (proba >= t).astype(int)).ravel()
    return COST_FP * fp + COST_FN * fn, fp, fn

print("  thr    cost    FP   FN")
for t in [0.9, 0.5, 0.3, 0.1, 0.05, 0.02]:
    c, fp, fn = cost_at(t)
    print(f"{t:5.2f}  {c:6d}  {fp:4d}  {fn:3d}")

grid = np.arange(0.01, 1.0, 0.01)
costs = [cost_at(t)[0] for t in grid]
print(f"\nbest threshold = {grid[int(np.argmin(costs))]:.2f}  → cost ${min(costs):,}")
print(f"vs default 0.50 → cost ${cost_at(0.5)[0]:,}")
print(f"Bayes rule for a calibrated model: t* = C_FP/(C_FP+C_FN) = {COST_FP/(COST_FP+COST_FN):.3f}")

At work

You will not know CFN exactly. Ask the business for a range ("a missed fraud costs us between $100 and $400") and check whether the chosen threshold moves much across that range. Usually the cost curve is flat near its minimum and the decision is robust. If it is not, you have discovered that the cost estimate, not the model, is the thing to improve — a far cheaper fix.

Deep dive: choosing a threshold from a cost matrix, derived 8 min
Explain it like I'm 9

You are deciding whether to take an umbrella. Carrying it for nothing costs a little annoyance; getting soaked costs a lot. So you take the umbrella even when the chance of rain is small, as long as chance-of-rain × soaking-cost is bigger than chance-of-dry × annoyance. The "chance" at which those two are equal is your threshold, and it depends only on the two costs.

Precisely. For one transaction the model says "fraud with probability p". Flagging it costs CFP if it is legit (probability 1 − p); passing it costs CFN if it is fraud (probability p). Flag when the expected cost of flagging is lower:

The math (optional)
(1 − p) · CFP < p · CFN ⇔ p > CFP / (CFP + CFN) = t*
general 2×2 costs: t* = (CFP − CTN) / [ (CFP − CTN) + (CFN − CTP) ]

CFP, CFN, CTP, CTN are the costs of the four cells (a correct decision can also cost something: a true positive still needs the $5 review). Rearranging the first inequality gives the first line; doing the same with all four costs gives the second, which reduces to the first when correct decisions are free. With $5 and $200: t* = 5/205 ≈ 0.024. The rule minimizes expected cost per transaction, so it also minimizes the total, and it holds for every transaction regardless of how many there are. Note what is not in the formula: the base rate. It has already been absorbed into p, provided p is a genuine probability.

That proviso is the whole story. The derivation treats p as the true probability of fraud for this row. If the model's probabilities are miscalibrated, t* is the optimum for the world the model believes in, not the real one, and the empirical sweep of Section 8 will disagree with it. The disagreement is not a flaw in either method; it is a measurement of the miscalibration:

# Bayes threshold vs empirical sweep: the gap between them measures how miscalibrated the probabilities are
import numpy as np
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix

X, y = make_classification(n_samples=20000, n_features=12, n_informative=4, n_redundant=2,
                           weights=[0.95, 0.05], class_sep=1.5, flip_y=0.005, random_state=7)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.5, stratify=y, random_state=7)
p = LogisticRegression(max_iter=1000).fit(X_tr, y_tr).predict_proba(X_te)[:, 1]
C_FP, C_FN = 5, 200
t_star = C_FP / (C_FP + C_FN)

grid = np.arange(0.01, 0.60, 0.01)
def actual_cost(t):                                    # what the confusion matrix really costs
    tn, fp, fn, tp = confusion_matrix(y_te, (p >= t).astype(int)).ravel()
    return C_FP * fp + C_FN * fn
def believed_cost(t):                                  # what the model's OWN probabilities say it costs
    flagged = p >= t
    return C_FP * (1 - p[flagged]).sum() + C_FN * p[~flagged].sum()
actual = np.array([actual_cost(t) for t in grid]); believed = np.array([believed_cost(t) for t in grid])
print(f"Bayes rule t* = {t_star:.3f}")
print(f"believed cost is minimal at t = {grid[believed.argmin()]:.2f}  (always ≈ t*: that is the derivation)")
print(f"actual   cost is minimal at t = {grid[actual.argmin()]:.2f}  (${actual.min():,.0f}; at t* it is ${actual_cost(t_star):,.0f})")

# the reason: in the low-probability range the model is over-confident about fraud
lo, hi = 0.02, 0.08
band = (p >= lo) & (p < hi)
print(f"rows with p in [{lo}, {hi}): model says {p[band].mean():.3f} on average, actual fraud rate {y_te[band].mean():.3f}")
# Bayes rule t* = 0.024
# believed cost is minimal at t = 0.03  (always ≈ t*: that is the derivation)
# actual   cost is minimal at t = 0.08  ($7,260; at t* it is $9,290)
# rows with p in [0.02, 0.08): model says 0.039 on average, actual fraud rate 0.009

The model's own probabilities are minimized almost exactly at t* (0.03 on a 0.01 grid), as the algebra says they must be. The real costs bottom out at 0.08, and the last line shows why: among rows the model scores at 2–8% fraud, the real fraud rate is under 1%. The model is over-confident in that range, so it flags too many legit rows at t*, and the truth wants a higher cut. Two fixes, in order of preference: calibrate the probabilities (Platt scaling or isotonic regression via CalibratedClassifierCV, Chapter 13) and then apply t* directly, which also makes the threshold portable to new cost estimates without re-sweeping; or keep the empirical sweep on a validation set and accept that the threshold is tied to this model's quirks and must be re-tuned after every retraining.

At work

Write the cost matrix down with the stakeholder before looking at any model output, including the costs of correct decisions (a true positive that triggers a manual review is not free). Then compute t* and the empirical optimum. If they agree, your probabilities are trustworthy enough to be used as numbers elsewhere (pricing, prioritization). If they disagree by more than a little, the calibration plot is your next slide, not the ROC curve.

9. Multiclass: softmax and averaging

Many problems have more than two answers: which of 5 support teams gets the ticket, which of 3 grape varieties made this wine, which of 10 digits is in this image. Two ideas extend everything above.

Softmax: a sigmoid for K classes

Logistic regression computes one score z. For K classes, compute K scores (one linear model per class) and turn them into K probabilities that sum to 1 with the softmax: exponentiate each score and divide by the total. The class with the largest probability is the prediction. When K = 2, softmax collapses exactly to the sigmoid. Log-loss generalizes too: the loss for an example is −log of the probability assigned to the true class.

The math (optional)
pk = ezk / ∑j=1..K ezj Loss = −log ptrue class

zk = wk·x + bk is the linear score for class k, with its own weight vector. ezk makes every score positive and amplifies differences (a score 3 higher becomes a probability e³ ≈ 20 times higher). Dividing by the sum forces the probabilities to add to 1. Adding the same constant to every score changes nothing, which is why only score differences matter. This same softmax is the last layer of nearly every neural-network classifier in Part III.

The alternative, one-vs-rest (OvR), trains K separate binary classifiers ("class 1 vs everything else", …) and picks the most confident. It works with any binary algorithm (Chapter 11's SVM, for instance) and parallelizes trivially, but its probabilities do not naturally sum to 1. scikit-learn's LogisticRegression uses true softmax (multinomial) by default; OneVsRestClassifier wraps anything else.

The multiclass confusion matrix

With K classes the matrix is K×K: rows are the truth, columns are the prediction, the diagonal is the correct calls. Everything off the diagonal is a specific kind of mistake, and which cells are populated is usually the most useful diagnostic in the whole evaluation. Macro, micro and weighted averages — a worked example

With K classes you get K precisions, K recalls and K F1 scores. To report one number you must average them, and the three ways to do so answer different questions. Using the per-class F1 values from Figure 6.10 (class 0: 0.864, class 1: 0.889, class 2: 0.973; supports 24, 29, 19):

MacroPlain mean of the per-class scores(0.864 + 0.889 + 0.973) / 3 = 0.909 (0.908 from the unrounded per-class values, as the code prints)Every class counts equally, however rare. Use when the small classes matter (rare defect types, minority segments).

If the classes are imbalanced, macro and micro/weighted can disagree wildly: a model that nails the 90% class and ignores a 2% class has a great micro score and a terrible macro score. Decide which you care about before you see the numbers, and say which you used every time you report one. When in doubt, report macro-F1 plus the full per-class table.

10. How good are the probabilities?

Every metric so far either used hard labels (precision, recall, F1) or only the ranking of scores (AUC, AP). None of them checks whether "p = 0.8" actually means 80%. That matters whenever the probability itself feeds a decision: expected-cost thresholding (Section 8), pricing, prioritization by risk, or any "expected value" calculation. Two metrics score the probabilities directly.

Log-loss (cross-entropy)

The training loss of Section 2, now used as a metric: the mean of −log ptrue class. Unbounded: a single p = 0.001 on a true positive contributes 6.9, about a hundred confident correct answers' worth. Lower is better; the no-skill baseline (always predict the base rate) is a useful yardstick.

Brier score

The mean squared error between the predicted probability and the 0/1 outcome: mean of (p − y)². Bounded in [0, 1], gentler on single disasters, easy to explain ("average squared miss"). Lower is better; the base-rate baseline is π(1 − π) for base rate π, so 0.0475 on our 5% fraud problem.

The math (optional)
Log-loss = −(1/N) ∑i log pi(yi) Brier = (1/N) ∑i (pi − yi)²

pi(yi) is the probability the model gave to the class that actually happened for example i; for a binary problem that is pi when yi = 1 and 1 − pi when yi = 0. Both are proper scoring rules: the only way to minimize them in expectation is to report your true belief, so a model cannot game them by hedging or by bluffing. That is the property that makes them the right metrics for probability quality, and the reason log-loss is used as the training objective in the first place.

What these catch that AUC cannot: two models with identical rankings (identical AUC) can have very different log-loss, because one is calibrated (when it says 0.8, it is right about 80% of the time) and the other is over- or under-confident. Figure 6.4's message applies to evaluation too: confidence is only rewarded when it is earned. The code below shows it — squashing every probability toward 0.5 leaves AUC untouched and wrecks log-loss.

# Probability-quality metrics: log-loss and Brier score punish confident wrong answers
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import log_loss, brier_score_loss, roc_auc_score

X, y = load_breast_cancer(return_X_y=True); y = 1 - y
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, stratify=y, random_state=42)
p = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)).fit(X_tr, y_tr).predict_proba(X_te)[:, 1]

print("model    log-loss:", round(log_loss(y_te, p), 4), " Brier:", round(brier_score_loss(y_te, p), 4))

# Same ranking, but squash every probability toward 0.5: AUC unchanged, log-loss/Brier worse
p_timid = 0.5 + 0.2 * (p - 0.5)
print("timid    log-loss:", round(log_loss(y_te, p_timid), 4), " Brier:", round(brier_score_loss(y_te, p_timid), 4),
      " AUC:", round(roc_auc_score(y_te, p_timid), 4), "(same as before)")

# The no-skill baseline: always predict the base rate
base = np.full_like(p, y_tr.mean())
print("baseline log-loss:", round(log_loss(y_te, base), 4), " Brier:", round(brier_score_loss(y_te, base), 4))

# One confident mistake costs a lot: log-loss of a single example predicted 0.999 when truth is 0

My standard evaluation block for any binary classifier, in this order: (1) base rate and majority baseline; (2) ROC-AUC and average precision on the validation set; (3) the PR curve, eyeballed; (4) precision, recall and counts at the chosen threshold, plus expected cost if costs are known; (5) log-loss or Brier vs the base-rate baseline, plus a reliability diagram if the probabilities will be used as numbers. Quiz

Check your understanding

1. A model achieves 99.2% accuracy detecting a defect that occurs in 0.8% of parts. What have you learned about the model?

This is the accuracy paradox. The majority baseline is 99.2%, so the model has shown zero skill beyond it. Look at recall, precision and the PR curve.

2. Out of 200 patients, 40 have the disease. The screening model flags 60 patients, 36 of whom are truly ill. What are precision and recall?

TP = 36, FP = 60 − 36 = 24, FN = 40 − 36 = 4. Precision = 36/60 = 60%; recall = 36/40 = 90%. Good for screening: few misses, at the price of 24 unnecessary follow-ups.

3. You lower the decision threshold from 0.5 to 0.2. Which statement is guaranteed?

Lowering the threshold can only add flags, so true positives can only increase or stay: recall is monotone non-decreasing. Precision usually falls, accuracy can go either way, and AUC does not depend on the threshold at all.

4. What does an ROC-AUC of 0.85 mean?

AUC is a ranking metric: the probability that a randomly chosen positive outranks a randomly chosen negative. It says nothing about the threshold, accuracy, or calibration.

5. A retention team can call 300 customers per month, no more. Which metric should drive the churn model?

The budget fixes k = 300 actions. Only the quality of the top-300 ranking matters, so precision@k (or lift at the top 300) is the right lead metric; there is no threshold to tune.

6. Two models have the same ROC-AUC on a validation set, but model A has log-loss 0.20 and model B has 0.45. What is the most likely explanation?

AUC only sees the ranking; log-loss also sees the probability values. Equal AUC with different log-loss means the ordering is the same but B's probabilities are worse as probabilities — typically overconfident wrong answers. Calibrate B (Chapter 13) before using its probabilities as numbers.

Exercise 6.1 — Read the matrix

A spam filter processed 10,000 emails, of which 2,000 were spam. It sent 1,900 emails to the spam folder, and 1,750 of those really were spam. Compute TP, FP, FN, TN, accuracy, precision, recall, specificity and F1. Then: which of the two errors would users complain about most, and which direction should the threshold move?

Show answer

TP = 1,750; FP = 1,900 − 1,750 = 150; FN = 2,000 − 1,750 = 250; TN = 8,000 − 150 = 7,850. Accuracy = (1,750 + 7,850)/10,000 = 96.0%. Precision = 1,750/1,900 = 92.1%. Recall = 1,750/2,000 = 87.5%. Specificity = 7,850/8,000 = 98.1%. F1 = 2·1,750/(2·1,750 + 150 + 250) = 3,500/3,900 = 0.897. Users hate real mail disappearing into the spam folder (the 150 false positives) far more than seeing a little spam. Raise the threshold: precision goes up toward 99%, recall drops, and that is the right trade for email. Lead with precision (or F0.5), not F1.

Exercise 6.2 — Draw the ROC by hand

Eight loan applicants, sorted by the model's default score from highest to lowest, with D = defaulted and R = repaid: D, D, R, D, R, R, R, R. Draw the ROC staircase (3 defaulters → up-steps of 1/3, 5 repayers → right-steps of 1/5) and compute the AUC by counting correctly ranked (D, R) pairs. Then compute average precision from the same list.

Show answer

Pairs: there are 3 × 5 = 15 (D, R) pairs. Defaulter 1 outranks all 5 repayers, defaulter 2 outranks 5, defaulter 3 outranks 4 (one repayer, at rank 3, is above it). Correct pairs = 14, so AUC = 14/15 ≈ 0.933. The staircase: up, up, right, up, right, right, right, right. For AP, at each defaulter the precision is: rank 1 → 1/1 = 1.0, rank 2 → 2/2 = 1.0, rank 4 → 3/4 = 0.75. AP = mean of these = (1 + 1 + 0.75)/3 ≈ 0.917 (scikit-learn's step-wise formula gives the same value here because each recall step is 1/3).

Exercise 6.3 — Set a threshold at work

Take a binary classification problem from your job (or the breast-cancer dataset if you have none) and do three things. (a) Write down the cost of a false positive and a false negative, even if you have to guess a range. (b) Fit a logistic regression on a training split, sweep the threshold from 0.01 to 0.99 on a validation split, and plot total cost against threshold. (c) Report the chosen threshold, the confusion matrix at that threshold, and how much the threshold moves if you double CFN. Keep the plot: it is the most persuasive slide you will bring to the meeting that decides whether the model ships.

Show answer

Use the code from Section 8 as a template, replacing make_classification with your data. The expected result is a U-shaped cost curve whose minimum is well away from 0.5 whenever the two costs differ substantially. When you double CFN the optimum moves toward a lower threshold (flag more). If it barely moves, your decision is robust to the cost estimate; if it moves a lot, spend effort on pinning down the cost, not on the model. Always sweep on validation data and confirm on the test set exactly once.

Chapter summary

  • A straight line cannot predict yes/no; logistic regression keeps the linear score and squashes it through the sigmoid into a probability. Its boundary is a straight cut in feature space.
  • Log-loss trains it and punishes confident wrong answers. Always scale features; sklearn's C is a regularization strength.
  • A classifier outputs probabilities; the threshold that turns them into labels is a business decision, not a model property.
  • Confusion matrix: rows = truth, columns = prediction. Precision reads down the flagged column (TP/(TP+FP)); recall reads along the positive row (TP/(TP+FN)); specificity is recall of the negatives.
  • Accuracy is meaningless without the majority baseline; on imbalanced data it mostly measures the imbalance.
  • Lowering the threshold raises recall and lowers precision. F1 balances them; Fβ tilts toward the error you fear more.
  • ROC-AUC = probability a random positive outranks a random negative; threshold-free, imbalance-blind. Use PR curves and average precision when positives are rare.
  • Choose the threshold by minimizing expected cost from a cost matrix on validation data; 0.5 is almost never it. Fixed budgets call for precision@k.
  • Multiclass: softmax probabilities, K×K confusion matrix, and say whether you averaged macro (classes equal) or micro/weighted (examples equal).
  • Log-loss and Brier score judge the probabilities themselves; equal AUC does not mean equal calibration (Chapter 13).
